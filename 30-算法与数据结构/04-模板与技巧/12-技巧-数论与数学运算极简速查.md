## 一、 快速幂（Binary Exponentiation）：极简迭代与防坑

### 1. 为什么比递归更简洁高效？
之前在分治思想中，常用递归式 $x^n = (x^{n/2})^2$ 实现快速幂，虽然直观，但有 $O(\log n)$ 的递归调用栈开销。

**更简洁的非递归写法是“二进制拆分迭代法”**：
- 任何正整数 $n$ 都可以表示为若干个二进制位的和：
  $$13 = (1101)_2 = 2^3 + 2^2 + 2^0 = 8 + 4 + 1$$
  $$x^{13} = x^8 \cdot x^4 \cdot x^1$$
- 循环推进过程中：
  1. 检查当前末位二进制是否为 1（`(exp & 1) == 1`）：若为 1 则将当前底数累乘入答案；
  2. 底数自乘倍增（`x *= x`）：依次生成 $x^1, x^2, x^4, x^8, \dots$；
  3. 指数无脑右移（`exp >>= 1`）；
- **时间复杂度 $O(\log n)$，空间复杂度绝对 $O(1)$，核心仅 4 行循环！**

### 2. LeetCode 50: Pow(x, n) 极简通用模板（含溢出避坑）
> [!caution] 面试必考避坑点：`Integer.MIN_VALUE` 溢出
> 当 $n = -2147483648$ 时，在 32 位有符号整型中执行 `-n` 会越界溢出，仍然为负数！必须在取反前将指数转为 `long`。

```java
class Solution {
    public double myPow(double x, int n) {
        long exp = n; // 关键：转为 long 防止 Integer.MIN_VALUE 取反溢出
        if (exp < 0) {
            x = 1.0 / x;
            exp = -exp;
        }

        double ans = 1.0;
        // 核心仅 4 行二进制拆分循环
        while (exp > 0) {
            if ((exp & 1) == 1) ans *= x;
            x *= x;
            exp >>= 1;
        }
        return ans;
    }
}
```

> [!tip]- 展开查看深度解析：“二进制找零钱”心智模型与单步推演表
> 很多同学第一次看迭代快速幂时，常困惑**“为什么是 `x *= x`？这样 `x` 不就越来越大暴增了吗？”**
> 
> **答案是：我们要的正是这个暴增！因为我们在按二进制面额印钞。**
> 
> 假设要计算 $x^{13}$：
> - 老实连乘需要乘 13 次（$O(n)$）；
> - 若把指数 $13$ 转成二进制：$13 = (1101)_2 = 8 + 4 + 0 + 1$；
> - 根据指数幂公式：$x^{13} = x^8 \times x^4 \times x^1$。
> 
> **三行代码各司其职：**
> - `if ((exp & 1) == 1) ans *= x;`：检查当前位是否为 1，若是则收下当前面额；
> - `x *= x;`：印钞机自乘翻倍，为更高位准备好基础面额（$x^1 \to x^2 \to x^4 \to x^8 \dots$）；
> - `exp >>= 1;`：指数无脑右移，去检查下一位。
> 
> **$x^{13}$ 完整单步推演表：**
> 
> | 轮次 | 剩余指数 `exp` (二进制) | 末位是 1 吗？(`exp & 1`) | 对 `ans` 的操作 | 底数 `x` 的变化（`x *= x` 翻倍） |
> | :---: | :---: | :---: | :---: | :---: |
> | **第 1 轮** | $13$ (`1101`) | **是 (1)** | 收下当前面额：`ans = ans * x^1` | $x$ 翻倍变成 **$x^2$** |
> | **第 2 轮** | $6$ (`110`) | **否 (0)** | 不需要面额 $x^2$，`ans` 保持原值 | 但 $x$ 继续翻倍变成 **$x^4$** |
> | **第 3 轮** | $3$ (`11`) | **是 (1)** | 收下当前面额：`ans = ans * x^4` | $x$ 翻倍变成 **$x^8$** |
> | **第 4 轮** | $1$ (`1`) | **是 (1)** | 收下当前面额：`ans = ans * x^8` | $x$ 翻倍变成 **$x^{16}$** |
> | **退出** | $0$ (`0`) | 循环结束 | **最终答案：$ans = x^1 \times x^4 \times x^8 = x^{13}$** | 循环退出 |

### 3. 大数取模快速幂（`qpow`，笔试与组合数学必备）
在动态规划、组合数计算中，计算 $(a^b) \pmod m$ 是家常便饭：

```java
public long qpow(long a, long b, long mod) {
    long ans = 1;
    a %= mod;
    while (b > 0) {
        if ((b & 1) == 1) ans = (ans * a) % mod;
        a = (a * a) % mod; // 防止乘法溢出
        b >>= 1;
    }
    return ans;
}
```

## 二、 最大公约数（GCD）与最小公倍数（LCM）

### 1. 欧几里得辗转相除法：单行递归与极简迭代
定理：两个整数的最大公约数等于其中较小的数和两数相除余数的最大公约数，即 $\gcd(a, b) = \gcd(b, a \pmod b)$。当 $b = 0$ 时，$\gcd(a, 0) = a$。

#### ① 单行三元递归（极简美学）
```java
public static int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}
```

#### ② 迭代版本（$O(1)$ 栈空间）
```java
public static int gcd(int a, int b) {
    while (b != 0) {
        int temp = a % b;
        a = b;
        b = temp;
    }
    return a;
}
```

> [!tip] 辗转相除法的“自动调序”神技
> 如果初始传入时 $a < b$（例如 `gcd(3, 10)`），第一轮 `3 % 10 = 3`，下一轮自然变成 `gcd(10, 3)`！
> **代码完全不需要先做大小比较或 `swap(a, b)`，它会在第一次运算后自动调换顺序**。

> [!example]- 展开查看深度解析：为什么 GCD 自动调序且无需比较大小？
> 很多人写 GCD 会忍不住加上 `if (a < b) { int t = a; a = b; b = t; }`。
> 实际上**完全不需要**！
> 
> **单步推演示例（以 `gcd(3, 10)` 为例）：**
> - **输入**：$a = 3, b = 10$（小的在前，大的在后）；
> - **第 1 次递归/循环**：计算余数 $3 \pmod{10} = 3$；
> - **下一次入参**：调用 `gcd(b, a % b)`，即传入的是 `gcd(10, 3)`！
> 
> 仅仅经过第 1 轮计算，两个参数就**自动完成了互换**！从第 2 轮开始就是标准的大数除以小数。
> 这种数学上的自愈性让代码可以精简到单行三元表达式 `return b == 0 ? a : gcd(b, a % b);`。

### 2. 最小公倍数 LCM（防溢出黄金法则）
数学定义：$a \times b = \gcd(a, b) \times \text{lcm}(a, b) \implies \text{lcm}(a, b) = \frac{a \times b}{\gcd(a, b)}$。

> [!danger] 致命陷阱：千万不要写 `(a * b) / gcd(a, b)`
> 如果 $a$ 与 $b$ 较大（如 $10^5$），先乘法 $a \times b = 10^{10}$ 直接超过 32 位整型上限 $2 \times 10^9$，瞬间暴负数！
> **必须“先除后乘”**：
> ```java
> public static long lcm(long a, long b) {
>     return (a / gcd((int) a, (int) b)) * b; // a 一定能被 gcd 整除，先除保平安！
> }
> ```

> [!danger]- 展开查看深度解析：为什么必须“先除后乘”？（反例警示）
> 很多人习惯按公式直接写 `(a * b) / gcd(a, b)`，这在算法题中是**超级隐形炸弹**。
> 
> **反例对比：**
> - 设 $a = 100000, b = 100000$（都在 Java 32 位 `int` 的范围 $2 \times 10^9$ 内，看起来很安全）；
> - $\gcd(a, b) = 100000$；
> - **错误写法**：`a * b` 算得 $10^{10}$，而 32 位 signed int 最大值是 $2.14 \times 10^9$。
>   在计算除法前，`a * b` 就已经发生了整型溢出，截断变成了 `-727379968`，除以 GCD 后输出 `-7273`，直接爆负数判错！
> - **正确姿势**：`(a / gcd(a, b)) * b`。
>   因为 $a$ 一定是 $\gcd(a, b)$ 的倍数，所以 `a / gcd(a, b)` 整除结果为 1，再乘 $b$ 结果为 $100000$，全流程安全无溢出！

### 3. GCD 在力扣高频题中的四大降维场景

#### 场景 1：裴蜀定理（Bézout's identity）与水壶问题（LC 365）
> **题目**：有两个容量分别为 $x, y$ 的水壶，问能否通过灌满、倒空和相互倒水，恰好量出 $z$ 升水？
> **数学第一性原理**：任何倒水操作本质上都是在求解二元一次不定方程 $ax + by = z$。
> 裴蜀定理断言：$ax + by = z$ 有整数解当且仅当 $z$ 是 $\gcd(x, y)$ 的倍数，且 $z \le x + y$。

```java
class Solution365 {
    public boolean canMeasureWater(int x, int y, int target) {
        if (target > x + y) return false;
        if (target == 0) return true;
        return target % gcd(x, y) == 0; // 一行秒杀
    }

    private int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);
    }
}
```

#### 场景 2：多数连续归约 GCD（LC 914. 卡牌分组）
> **技巧**：利用 $\gcd(0, x) = x$ 的特性，求数组中所有元素的公约数时，初始累加器设为 `0` 即可：
```java
int g = 0;
for (int count : freqMap.values()) {
    g = gcd(g, count);
}
return g >= 2;
```

#### 场景 3：几何共线点斜率化简，规避浮点精度（LC 149. 直线上最多的点数）
> **痛点**：两点 $(x_1, y_1)$ 与 $(x_2, y_2)$ 的斜率 $k = \frac{\Delta y}{\Delta x}$。如果用 `double` 存入 HashMap，浮点数误差会导致精度错乱；如果直接算除法还会遭遇除以 0。
> **解法**：求出 $g = \gcd(\Delta x, \Delta y)$，将分子分母同除以 $g$ 得到不可约分数对，以字符串 `"dx/dy"` 或 `long` 状态压缩作为哈希 Key！

```java
int dx = x2 - x1;
int dy = y2 - y1;
int g = gcd(dx, dy);
String slopeKey = (dx / g) + "_" + (dy / g); // 精确无误差的斜率 Key！
```

#### 场景 4：容斥原理与二分答案（LC 878. 第 N 个神奇数字）
> **题目**：找出能被 $a$ 或 $b$ 整除的第 $n$ 个正整数。
> **解法**：在二分查找的 `check(mid)` 中，$\le mid$ 的神奇数字个数由容斥原理给出：
> $$\text{count} = \lfloor \frac{mid}{a} \rfloor + \lfloor \frac{mid}{b} \rfloor - \lfloor \frac{mid}{\text{lcm}(a, b)} \rfloor$$

## 三、 质数筛选（Sieve of Eratosthenes 埃氏筛）

### 1. 埃氏筛极简模板（LC 204. 计数质数）
找出小于 $n$ 的所有质数个数，直接暴力判断每个数是 $O(n \sqrt{n})$。埃氏筛原理：质数的倍数一定不是质数，从 $2$ 开始将每个质数的倍数标记为合数。
- **时间复杂度**：$O(n \log \log n) \approx O(n)$，空间复杂度 $O(n)$。

```java
class Solution204 {
    public int countPrimes(int n) {
        boolean[] isPrime = new boolean[n];
        // 初始假定 >= 2 的数都是质数
        Arrays.fill(isPrime, true);

        int count = 0;
        for (int i = 2; i < n; i++) {
            if (isPrime[i]) {
                count++;
                // 优化：从 i * i 开始标记合数，防止重复标记且防止 i*i 溢出
                if ((long) i * i < n) {
                    for (int j = i * i; j < n; j += i) {
                        isPrime[j] = false;
                    }
                }
            }
        }
        return count;
    }
}
```

## 四、 刷题常用数学与整数速写小技巧

| 技巧名称 | 传统写法（易错/繁琐） | 极简高效一行流 | 核心原理与解决痛点 |
| :--- | :--- | :--- | :--- |
| **整数向上取整** | `(int) Math.ceil((double) a / b)` | **`(a + b - 1) / b`** | 规避浮点数转换精度丢失与性能开销 |
| **负数取模防负** | `int r = a % mod; if (r < 0) r += mod;` | **`(a % mod + mod) % mod`** | Java 中 `(-3) % 7 = -3`，一行流拉回正数区间 |
| **两数异号判断** | `(a > 0 && b < 0) \|\| (a < 0 && b > 0)` | **`(a ^ b) < 0`** | 符号位异或：最高符号位不同结果即为负数 |
| **无溢出中点计算** | `(left + right) / 2`（会溢出） | **`left + (right - left) / 2`** 或 **`(left + right) >>> 1`** | 无符号右移 `>>>` 彻底免除正数溢出风险 |
| **两数交换免临时变量** | `int t = a; a = b; b = t;` | **`a ^= b; b ^= a; a ^= b;`** | 位运算异或律（注意：两变量下标相同时不可用） |
