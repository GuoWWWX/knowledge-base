# LC0128-最长连续序列

> 链接：[LeetCode 128. 最长连续序列](https://leetcode.cn/problems/longest-consecutive-sequence/)  
> **大厂考情**：大厂高频面试 No.1 梯队题，哈希表 $O(N)$ 降维经典代表作。

## 🧾 题目理解

给定一个未排序的整数数组 `nums` ，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

**请你设计并实现时间复杂度为 $O(n)$ 的算法解决此问题。**

- **示例 1**：
  - 输入：`nums = [100,4,200,1,3,2]`
  - 输出：`4`
  - 解释：最长数字连续序列是 `[1, 2, 3, 4]`。它的长度为 4。
- **示例 2**：
  - 输入：`nums = [0,3,7,2,5,8,4,6,0,1]`
  - 输出：`9`

---

## 💡 思路分析

### ❌ 排序法（不符合题意，$O(N \log N)$）
若直接使用 `Arrays.sort(nums)`，时间复杂度为 $O(N \log N)$，违背了题目“必须在 $O(N)$ 内完成”的核心约束。

### ✅ 哈希集合去重 + 智能起点剪枝（严格 $O(N)$）

1. **哈希去重**：将所有数字存入 `HashSet<Integer>` 中，去重并支持 $O(1)$ 查找；
2. **核心剪枝（神仙技巧）**：
   - 遍历集合中的每一个数字 `num`；
   - **判断 `set.contains(num - 1)` 是否为真**：
     - 若为真，说明 `num` 绝对不是连续序列的“起点”（因为它前面的数 `num - 1` 肯定能构成更长的序列），**直接跳过！绝不从它开始向后扫描**；
     - 若为假，说明 `num` 就是某一段连续序列的“排头兵”！此时才开启 `while (set.contains(curNum + 1))` 不断向后查找递增元素，计算该段序列长度并更新全局最大值。
3. **为什么总时间是 $O(N)$？**
   - 虽然代码里有 `while` 嵌套循环，但因为只有“序列起点”才会触发向后扫描，整个数组中的每个数字**最多只会被向后寻找 1 次**！因此所有数字的访问次数总和不超过 $2N$，时间复杂度严格为 $O(N)$。

---

## ⏱️ 复杂度

- **时间复杂度**：$O(N)$。构建哈希表 $O(N)$，扫描各连续段总次数为 $O(N)$。
- **空间复杂度**：$O(N)$。哈希集合存储去重元素。

---

## 💻 Java 标准可运行代码

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int longestConsecutive(int[] nums) {
        if (nums == null || nums.length == 0) return 0;

        // 1. 全部存入 HashSet 去重并加速检索
        Set<Integer> numSet = new HashSet<>();
        for (int x : nums) {
            numSet.add(x);
        }

        int maxLen = 0;

        // 2. 遍历集合
        for (int num : numSet) {
            // 核心剪枝：只有当 num - 1 不存在时，当前 num 才是这一段连续序列的起点！
            if (!numSet.contains(num - 1)) {
                int curNum = num;
                int curStreak = 1;

                // 向后寻找连续数字
                while (numSet.contains(curNum + 1)) {
                    curNum++;
                    curStreak++;
                }

                // 更新全局最大长度
                maxLen = Math.max(maxLen, curStreak);
            }
        }

        return maxLen;
    }
}
```

---

## ⚠️ 易错点

- **遍历对象选错**：严禁在 `for (int num : nums)` 原数组上循环，若原数组包含大量重复值，重复检查会引起不必要开销；必须直接在去重后的 `numSet` 上遍历。
- 如果不写 `if (!numSet.contains(num - 1))`，每次遇到中间数都往后扫一遍，算法会退化到 $O(N^2)$ 直接超时。
