# LC1188-手撕阻塞队列 (Bounded Blocking Queue)

> 链接：[LeetCode 1188. 设计有限阻塞队列](https://leetcode.cn/problems/design-bounded-blocking-queue/)  
> **大厂考情**：美团、阿里、字节跳动后端面试手撕并发编程 No.1 题（生产者-消费者模型实战）。

## 🧾 题目理解

实现一个拥有如下方法的线程安全有限阻塞队列 `BoundedBlockingQueue`：
- `BoundedBlockingQueue(int capacity)` 初始化队列，其容量为 `capacity`。
- `void enqueue(int element)` 在队尾增加一个 `element`。如果队列满，调用线程应被**阻塞**直到队列非满。
- `int dequeue()` 返回并删除队首元素。如果队列空，调用线程应被**阻塞**直到队列非空。
- `int size()` 返回当前队列中的元素数量。

**多线程并发约束**：允许多个生产者和多个消费者线程同时调用入队与出队方法，必须保证线程安全与不发生死锁。

---

## 💡 思路分析：显式锁 ReentrantLock + 双条件变量 Condition

### 1. 为什么不用单条件变量？
- 若只用一个 `Condition`（或传统的单个 `wait/notifyAll`），每次有新元素入队唤醒时，会同时唤醒其他生产者和消费者，造成大量的**惊群效应（Thundering Herd）**和无效竞争；
- **标准设计**：使用两个独立的条件变量：
  - `notFull`：队列未满条件（生产者在此等待，由消费者出队后精准唤醒）；
  - `notEmpty`：队列非空条件（消费者在此等待，由生产者入队后精准唤醒）。

### 2. 致命细节：为什么判断等待必须用 `while` 而不是 `if`？
```java
// 错误示范！
if (count == capacity) {
    notFull.await();
}

// 必须使用 while 循环！
while (count == capacity) {
    notFull.await();
}
```
- **原因 1（虚假唤醒 Spurious Wakeup）**：操作系统底层或 JVM 允许线程在没有任何信号的情况下被意外唤醒；
- **原因 2（竞争破坏条件）**：当线程从 `await()` 被唤醒并重新拿到锁时，队列可能已经被其他并发跑得更快的线程填满/清空了。若用 `if` 会直接向下执行导致越界崩溃，**必须用 `while` 重新检验条件**！

## 💻 Java 标准白板手撕源码

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

class BoundedBlockingQueue {

    private final int[] queue;
    private final int capacity;
    private int head;  // 队首指针
    private int tail;  // 队尾指针
    private int count; // 当前元素数量

    // 独占可重入互斥锁
    private final ReentrantLock lock = new ReentrantLock();
    // 条件变量 1：队列未满（供生产者等待）
    private final Condition notFull = lock.newCondition();
    // 条件变量 2：队列非空（供消费者等待）
    private final Condition notEmpty = lock.newCondition();

    public BoundedBlockingQueue(int capacity) {
        this.capacity = capacity;
        this.queue = new int[capacity];
        this.head = 0;
        this.tail = 0;
        this.count = 0;
    }

    /**
     * 生产者入队
     */
    public void enqueue(int element) throws InterruptedException {
        lock.lock();
        try {
            // 必须使用 while 防止虚假唤醒
            while (count == capacity) {
                notFull.await(); // 队列已满，生产者阻塞挂起
            }

            // 循环队列入队
            queue[tail] = element;
            tail = (tail + 1) % capacity;
            count++;

            // 精准唤醒等待的消费者线程
            notEmpty.signal();
        } finally {
            lock.unlock();
        }
    }

    /**
     * 消费者出队
     */
    public int dequeue() throws InterruptedException {
        lock.lock();
        try {
            while (count == 0) {
                notEmpty.await(); // 队列已空，消费者阻塞挂起
            }

            // 循环队列出队
            int element = queue[head];
            head = (head + 1) % capacity;
            count--;

            // 精准唤醒等待的生产者线程
            notFull.signal();
            return element;
        } finally {
            lock.unlock();
        }
    }

    /**
     * 查询当前队列大小
     */
    public int size() {
        lock.lock();
        try {
            return count;
        } finally {
            lock.unlock();
        }
    }
}
```

## ⏱️ 复杂度分析

- **时间复杂度**：`enqueue`、`dequeue`、`size` 均为严格的 **$O(1)$**；
- **空间复杂度**：$O(\text{capacity})$，固定循环数组存储。
