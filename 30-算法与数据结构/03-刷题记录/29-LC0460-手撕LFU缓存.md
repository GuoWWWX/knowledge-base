# LC0460-手撕 LFU 缓存 (双哈希表 + 双向链表桶)

> 链接：[LeetCode 460. LFU 缓存](https://leetcode.cn/problems/lfu-cache/)  
> **大厂考情**：微软、字节跳动、Shopee 高阶架构与手撕考核标杆（“代码量最长、逻辑最绕的缓存设计神题”）。

## 🧾 题目理解

请你为 **最不经常使用（LFU）** 缓存算法设计并实现数据结构。

实现 `LFUCache` 类：
- `LFUCache(int capacity)` - 用数据结构的容量 `capacity` 初始化对象。
- `int get(int key)` - 如果键 `key` 存在于缓存中，则获取键的值，并将其**访问频次加 1**，返回其值；否则返回 `-1`。
- `void put(int key, int value)` - 如果键 `key` 已存在，则变更其值，并将其**访问频次加 1**；如果键不存在，请插入键值对。当缓存达到容量上限时，应在插入新项之前，**逐出最不经常使用的项（频次最小）**。在此问题中，当存在平局（即两个或更多个键具有相同使用频次）时，应该逐出**最久未使用的项（即同频次下遵循 LRU 淘汰）**。

函数 `get` 和 `put` 必须以 **$O(1)$** 的平均时间复杂度运行。

---

## 💡 思路分析：双哈希表 + 频次双向链表

### 1. 为什么比 LRU 复杂得多？
- **LRU** 只有一条时间维度链表，淘汰尾部即可；
- **LFU** 有两个淘汰维度：**先比“频次（Frequency）”**，频次最少的先死；**再比“时间”**，同频次下最久未用的先死。

### 2. 核心架构设计
必须维护两张哈希表与一个全局变量：
1. **`keyTable`**：`Map<Integer, Node>`，根据 `key` 在 $O(1)$ 时间内秒查节点；
2. **`freqTable`**：`Map<Integer, DoublyLinkedList>`，将**相同访问频次**的所有节点挂在同一个双向链表上；
3. **`minFreq`**：整型变量，实时记录**当前整个缓存中最小的访问频次**。
   - 当缓存满时，我们直接定位到 `freqTable.get(minFreq)`，将其末尾节点删除淘汰！
   - 什么时候 `minFreq` 会增加？当最小频次链表里的节点被访问晋升，且该链表变为空时，`minFreq++`。
   - 什么时候 `minFreq` 会重置为 1？每当插入一个全新的未见过的 Key 时，它的初始频次为 1，`minFreq` 必定重置为 1。

## 💻 Java 标准白板手撕源码

```java
import java.util.HashMap;
import java.util.Map;

class LFUCache {

    // 1. 双向链表节点
    static class Node {
        int key;
        int value;
        int freq; // 访问频次
        Node prev;
        Node next;

        Node(int key, int value) {
            this.key = key;
            this.value = value;
            this.freq = 1; // 新节点初始频次为 1
        }
    }

    // 2. 自定义双向链表（带首尾虚拟哨兵）
    static class DoublyLinkedList {
        Node dummyHead;
        Node dummyTail;
        int size;

        DoublyLinkedList() {
            dummyHead = new Node(-1, -1);
            dummyTail = new Node(-1, -1);
            dummyHead.next = dummyTail;
            dummyTail.prev = dummyHead;
            this.size = 0;
        }

        // 新节点插入到头部（最新访问）
        void addToHead(Node node) {
            node.prev = dummyHead;
            node.next = dummyHead.next;
            dummyHead.next.prev = node;
            dummyHead.next = node;
            size++;
        }

        // 从链表中移除指定节点
        void removeNode(Node node) {
            node.prev.next = node.next;
            node.next.prev = node.prev;
            size--;
        }

        // 淘汰尾部最久未使用的节点
        Node removeTail() {
            if (size == 0) return null;
            Node tail = dummyTail.prev;
            removeNode(tail);
            return tail;
        }
    }

    private final int capacity;
    private int minFreq;
    private final Map<Integer, Node> keyTable;
    private final Map<Integer, DoublyLinkedList> freqTable;

    public LFUCache(int capacity) {
        this.capacity = capacity;
        this.minFreq = 0;
        this.keyTable = new HashMap<>();
        this.freqTable = new HashMap<>();
    }

    public int get(int key) {
        if (capacity == 0) return -1;
        Node node = keyTable.get(key);
        if (node == null) return -1;

        // 节点被访问，频次自增 1，并在频次链表间迁移
        increaseFreq(node);
        return node.value;
    }

    public void put(int key, int value) {
        if (capacity == 0) return;

        Node node = keyTable.get(key);
        if (node != null) {
            // 已存在：更新值并增加频次
            node.value = value;
            increaseFreq(node);
        } else {
            // 不存在：检查容量
            if (keyTable.size() >= capacity) {
                // 淘汰 minFreq 链表最末尾的节点
                DoublyLinkedList minList = freqTable.get(minFreq);
                Node deadNode = minList.removeTail();
                keyTable.remove(deadNode.key);
            }

            // 插入新节点
            Node newNode = new Node(key, value);
            keyTable.put(key, newNode);

            // 新节点频次为 1，将 minFreq 强制重置为 1
            this.minFreq = 1;
            DoublyLinkedList list = freqTable.computeIfAbsent(1, k -> new DoublyLinkedList());
            list.addToHead(newNode);
        }
    }

    /**
     * 核心晋升逻辑：将 node 从旧频次链表摘除，移入 (freq + 1) 频次链表头部
     */
    private void increaseFreq(Node node) {
        int oldFreq = node.freq;
        DoublyLinkedList oldList = freqTable.get(oldFreq);
        oldList.removeNode(node);

        // 如果当前移除的正是最小频次链表，且移除后该链表为空，minFreq 自增
        if (oldFreq == minFreq && oldList.size == 0) {
            minFreq++;
        }

        // 频次增加并挂到新链表
        node.freq++;
        DoublyLinkedList newList = freqTable.computeIfAbsent(node.freq, k -> new DoublyLinkedList());
        newList.addToHead(node);
    }
}
```

## ⏱️ 复杂度分析

- **时间复杂度**：`get` 和 `put` 严格平均 **$O(1)$**。两张哈希表寻址 $O(1)$，双向链表增删 $O(1)$。
- **空间复杂度**：$O(\text{capacity})$。

## 🔁 LRU vs LFU 面试终极对比

| 对比维度 | LRU（最近最少使用 LC 146） | LFU（最不经常使用 LC 460） |
| :--- | :--- | :--- |
| **淘汰核心依据** | **最后一次访问时间**距今最远 | **累计访问次数最少**；相同频次再比时间 |
| **底层核心结构** | 1 个哈希表 + 1 条双向链表 | **2 个哈希表 + 多条频次双向链表** |
| **实现代码量** | 约 70 ~ 80 行（中等难度） | **约 140 ~ 160 行（困难难度，代码最长）** |
| **对抗偶发批量扫描**| 易受缓存污染（批量遍历一次就把热数据全洗掉） | **抗缓存污染能力极强**（高频热数据频次很高，不会轻易被淘汰） |
