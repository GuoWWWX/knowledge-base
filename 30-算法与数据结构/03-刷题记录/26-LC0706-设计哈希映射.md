# LC0706-设计哈希映射 (手撕 HashMap)

> 链接：[LeetCode 706. 设计哈希映射](https://leetcode.cn/problems/design-hashmap/)  
> **大厂考情**：美团、字节、虾皮等大厂高频面试手撕原题（“不借助任何内置库，纯手写一个 HashMap”）。

## 🧾 题目理解

不使用任何内建的哈希表库设计一个哈希映射（`HashMap`）。

实现 `MyHashMap` 类：
- `MyHashMap()` 用空映射初始化对象。
- `void put(int key, int value)` 向 HashMap 插入 `(key, value)` 键值对。如果 `key` 已经存在于映射中，则更新其对应的值 `value`。
- `int get(int key)` 返回目标 `key` 所映射的 `value`；如果映射中不包含该 `key`，则返回 `-1`。
- `void remove(int key)` 如果映射中存在 `key` 的映射，则移除该键值对。

### 输入输出示例
```text
输入：
["MyHashMap", "put", "put", "get", "get", "put", "get", "remove", "get"]
[[], [1, 1], [2, 2], [1], [3], [2, 1], [2], [2], [2]]

输出：
[null, null, null, 1, -1, null, 1, null, -1]

解释：
MyHashMap myHashMap = new MyHashMap();
myHashMap.put(1, 1); // myHashMap 现在为 [[1,1]]
myHashMap.put(2, 2); // myHashMap 现在为 [[1,1], [2,2]]
myHashMap.get(1);    // 返回 1
myHashMap.get(3);    // 返回 -1 (未找到)
myHashMap.put(2, 1); // myHashMap 现在为 [[1,1], [2,1]]（更新已有映射）
myHashMap.get(2);    // 返回 1
myHashMap.remove(2); // 删除键为 2 的映射，myHashMap 现在为 [[1,1]]
myHashMap.get(2);    // 返回 -1 (未找到)
```

## 💡 思路分析：拉链法（链地址法 Separate Chaining）

### 1. 为什么不能开一个大小为 $10^6$ 的直接寻址一维数组？
- 数据规模要求 $0 \le key, value \le 10^6$，若直接 `new int[1000001]`：
  1. 空间浪费极其巨大（稀疏存储时大量内存闲置）；
  2. 面试官考察的是**散列碰撞（Hash Collision）的处理机制**，直接按下标映射属于投机取巧，必被扣分！

### 2. 核心架构：大质数取模 + 单向链表桶
- **数组桶（Bucket Array）**：定义大小为质数 `BASE = 769` 的数组（使用质数作为模数可以最大程度减少因倍数规律引起的哈希冲突）；
- **哈希函数**：`hash(key) = key % BASE`；
- **单向链表节点**：每个桶挂载一个链表，节点保存 `key`, `value`, `next`：
  - `put(key, value)`：先计算桶下标。遍历该桶链表，若存在相同 `key` 则覆盖更新；若不存在则头插法插入新节点；
  - `get(key)`：计算桶下标并遍历链表，找到返回对应 `value`，遍历结束未找到返回 `-1`；
  - `remove(key)`：经典的链表删除节点（利用虚拟前驱节点 `dummy` 穿针引线删除）。

## 💻 Java 标准白板手撕源码

```java
class MyHashMap {

    // 1. 自定义单向链表节点
    private static class Node {
        int key;
        int value;
        Node next;

        Node(int key, int value) {
            this.key = key;
            this.value = value;
        }
    }

    // 2. 选择质数作为桶数量，减少哈希碰撞
    private static final int BASE = 769;
    private final Node[] data;

    public MyHashMap() {
        this.data = new Node[BASE];
    }

    /**
     * 插入/更新键值对
     */
    public void put(int key, int value) {
        int idx = hash(key);
        Node head = data[idx];

        // 检查是否已经存在该 key
        Node cur = head;
        while (cur != null) {
            if (cur.key == key) {
                cur.value = value; // 存在则覆盖
                return;
            }
            cur = cur.next;
        }

        // 不存在：使用头插法插入新节点
        Node newNode = new Node(key, value);
        newNode.next = data[idx];
        data[idx] = newNode;
    }

    /**
     * 获取 key 对应的值，不存在返回 -1
     */
    public int get(int key) {
        int idx = hash(key);
        Node cur = data[idx];

        while (cur != null) {
            if (cur.key == key) {
                return cur.value; // 命中
            }
            cur = cur.next;
        }
        return -1; // 未找到
    }

    /**
     * 移除 key 对应的映射
     */
    public void remove(int key) {
        int idx = hash(key);
        Node head = data[idx];
        if (head == null) return;

        // 若要删除的刚好是头节点
        if (head.key == key) {
            data[idx] = head.next;
            return;
        }

        // 遍历删除非头节点
        Node prev = head;
        while (prev.next != null) {
            if (prev.next.key == key) {
                prev.next = prev.next.next; // 跨过待删除节点
                return;
            }
            prev = prev.next;
        }
    }

    /**
     * 散列函数：质数取模
     */
    private int hash(int key) {
        return key % BASE;
    }
}
```

## ⏱️ 复杂度分析

- **时间复杂度**：平均 $O(N / \text{BASE}) \approx O(1)$。在数据均匀分布时，每个桶链表长度极短；最坏碰撞退化为 $O(N)$。
- **空间复杂度**：$O(N + \text{BASE})$。$N$ 为实际插入的键值对总数。

## ⚠️ 工业面试高频追问

1. **为什么选择质数（769/1009）做模数？**
   - 若模数有公约数（如合数 1000），当插入的 Key 呈现某种步长规律（如 10, 20, 30...）时，会全部聚集在能被公约数整除的少数桶中造成严重倾斜；而质数与绝大多数整数互质，能让离散数据散列得极度均匀。
2. **JDK 1.8 HashMap 为什么选 2 的幂而不是质数？**
   - 工业级通用实现中为了追求极速计算，利用位运算 `(n - 1) & hash` 替代 `%` 取模（速度快 10 倍以上），并通过**高位异或扰动函数**弥补非质数的碰撞问题。
3. **链表过长怎么优化？**
   - 当单桶链表长度超过阈值（如 JDK 中的 8）时，将链表树化为红黑树，使最坏查询时间从 $O(N)$ 降维至 $O(\log N)$。
