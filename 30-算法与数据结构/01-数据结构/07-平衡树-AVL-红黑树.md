# 平衡树 AVL 红黑树

> [!abstract] 一句话总结
> 平衡树通过旋转维持树高接近 O(log n)，避免普通 BST 在有序输入下退化成链表。

## AVL vs 红黑树

| 结构 | 平衡程度 | 适合 |
| ---- | -------- | ---- |
| AVL | 更严格 | 查询多、更新少 |
| 红黑树 | 相对宽松 | 插入删除频繁的通用 Map/Set |

## 红黑树性质速记

- 节点红或黑。
- 根节点黑。
- 红节点不能连续。
- 从任一节点到叶子空节点的黑节点数相同。

## Java 关联

- `TreeMap` / `TreeSet` 基于红黑树。
- `HashMap` 桶内链表过长时会树化为红黑树。

## 为什么红黑树更常用于工程

AVL 树平衡更严格，查询路径更短，但插入删除时可能需要更多旋转。红黑树允许局部不那么平衡，用更少的旋转换取稳定的增删改性能，因此更适合通用集合实现。

## TreeMap 常用能力

```java
TreeMap<Integer, String> map = new TreeMap<>();
map.put(10, "a");
map.floorKey(12);   // <= 12 的最大 key
map.ceilingKey(12); // >= 12 的最小 key
```

适合需要有序键、范围查询、最近邻查询的问题。

## 面试重点

- 能说明为什么需要平衡。
- 不要求手写完整红黑树，但要知道旋转和重新染色的目的。
- 能比较 HashMap、TreeMap、LinkedHashMap。
- 说明红黑树查询、插入、删除都是 O(log n)，但常数和使用场景与哈希表不同。
