# 递归与分治

> [!abstract] 一句话总结
> 递归把问题交给更小的同类问题，分治则把问题拆分、求解、合并。

## 三要素

- 递归定义：函数负责解决什么。
- 终止条件：什么时候不再递归。
- 递推关系：如何由子问题得到当前答案。

## 分治四步

1. 划分：把原问题拆成规模更小、结构相同的子问题。
2. 解决：递归求解子问题。
3. 合并：把子问题答案合成为当前问题答案。
4. 边界：处理规模足够小时的直接答案。

常见分治题包括归并排序、快速排序、二叉树递归、最近公共祖先、逆序对统计。判断关键是：子问题之间是否相对独立，合并阶段是否能在可接受复杂度内完成。

## 模板

```java
Result solve(Input x) {
    if (isBase(x)) return baseResult(x);
    Result left = solve(leftPart(x));
    Result right = solve(rightPart(x));
    return merge(left, right);
}
```

## 复杂度分析

- 递归树法：看每层成本和层数，例如归并排序每层 O(n)，共 O(log n) 层，总 O(n log n)。
- 主定理直觉：`T(n)=aT(n/b)+f(n)`，比较“子问题总规模”和“合并成本”谁主导。
- 空间复杂度通常包含递归栈深度，平衡二叉递归是 O(log n)，链式递归可能是 O(n)。

## 面试表达

回答递归题时不要只说“递归即可”，而要说清楚函数语义。例如：`dfs(root)` 返回以 `root` 为根的子树答案；当前节点只负责合并左右子树结果。这种表达能证明你不是靠直觉硬写。

## 易错点

- 没有终止条件导致栈溢出。
- 子问题不是同类问题，递归定义不清。
- 合并阶段漏掉跨左右区间的答案。
- 对二叉树题，先判断当前节点需要“自底向上返回值”还是“自顶向下传状态”。
