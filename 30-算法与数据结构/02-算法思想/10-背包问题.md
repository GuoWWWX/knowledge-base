# 算法思想：背包问题全家桶（0-1/完全/多重与空间压缩本质）

> **第一性原理**：背包问题是在**有限资源（背包容量）约束下，进行离散物品选择以求达到收益极值**的经典多阶段决策模型。
> 面试中所有复杂的变种题（零钱兑换、分割等和子集、目标和），本质上都是**0-1 背包**或**完全背包**在“最值、存在性、计数”上的数学马甲！

---

## 1. 背包双雄：0-1 背包 vs 完全背包本质对比

```mermaid
flowchart TD
    subgraph KnapsackFamily["背包核心分类与遍历本质"]
        ZeroOne["0-1 背包 (每个物品只能选 1 次)"] -->|"空间压缩后"| ReverseLoop["容量循环【必须倒序】: 确保 dp[c - w] 依然保存上一轮状态"]
        Complete["完全背包 (每个物品可选无限次)"] -->|"空间压缩后"| ForwardLoop["容量循环【必须正序】: 允许利用当前轮刚刚更新的状态继续累加"]
    end
```

### 1.1 为什么 0-1 背包必须“倒序”，而完全背包必须“正序”？（数学推导）
- **0-1 背包二维原始方程**：
  $$dp[i][c] = \max(dp[i - 1][c], \ dp[i - 1][c - w[i]] + v[i])$$
  注意：右侧第二项依赖的是 **$i - 1$（上一行/尚未放入当前物品时的状态）**！
- **降维成一维数组 `dp[c]`**：
  - 如果我们**从大到小倒序计算 `c`**（$C \to w[i]$）：当我们计算 `dp[c]` 时，较小下标处的 `dp[c - w[i]]` 还没有被当前物品刷新，它依然**保存着上一层 $i - 1$ 的历史纯净值**！完全符合二维方程的物理含义！
  - 如果我们**正序计算 `c`**（$w[i] \to C$）：当算到大的容量时，较小容量的 `dp[c - w[i]]` 早已经被当前物品加过一次了，此时再次叠加，**相当于同一个物品被拿了 2 次、3 次甚至无数次！直接蜕变为了完全背包！**

## 2. 0-1 背包经典实战：分割等和子集（LC 416）

题目：判断一个正整数数组是否可以分割成两个子集，使得两个子集的元素和相等。

### 2.1 破局转化
- 计算数组总和 `sum`。若 `sum` 为奇数，绝对不可能对半分，直接返回 `false`。
- 目标：从数组中挑选一些数字，能否恰好装满容量为 $\text{target} = \text{sum} / 2$ 的背包？每个数字只能选一次！**标准的 0-1 背包存在性问题**！

```java
class CanPartitionSolution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) sum += num;
        if (sum % 2 != 0) return false; // 奇数不可等分

        int target = sum / 2;
        // dp[c] 表示容量为 c 的背包能否恰好装满
        boolean[] dp = new boolean[target + 1];
        dp[0] = true; // 0 容量什么都不装即为满

        for (int num : nums) {
            // 0-1 背包铁律：容量倒序遍历，防止同一个数字被重复使用！
            for (int c = target; c >= num; c--) {
                dp[c] = dp[c] || dp[c - num];
            }
            // 剪枝提速：如果已经能凑出 target，直接提前返回
            if (dp[target]) return true;
        }

        return dp[target];
    }
}
```

## 3. 完全背包经典实战：零钱兑换（LC 322 最值模型）

题目：给定不同面额的硬币 `coins` 和一个总金额 `amount`，求凑成总金额所需的**最少硬币个数**。每种硬币数量无限。

- **模型**：完全背包求最小值。
- **状态转移**：$dp[c] = \min(dp[c], \ dp[c - \text{coin}] + 1)$
- **Base Case 初始化**：由于求最小值，除了 `dp[0] = 0` 以外，其余全部初始化为一个大于 `amount` 的极大值（如 `amount + 1`），代表初始无法凑齐。

```java
class CoinChangeSolution {
    public int coinChange(int[] coins, int amount) {
        int max = amount + 1; // 虚拟无穷大哨兵
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, max);
        dp[0] = 0; // 凑成 0 元需要 0 枚硬币

        // 外层物品，内层容量正序（完全背包）
        for (int coin : coins) {
            for (int c = coin; c <= amount; c++) {
                dp[c] = Math.min(dp[c], dp[c - coin] + 1);
            }
        }

        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```

## 4. 多重背包与二进制拆分优化（化归为 0-1 背包）

### 4.1 问题的物理场景
- **定义**：第 $i$ 种物品有确定的数量上限 $K_i$ 个，重量为 $w_i$，价值为 $v_i$。
- **暴力拆分瓶颈**：若将 $K_i$ 个物品拆为 $K_i$ 个独立的 0-1 背包物品，物品总数变为 $\sum K_i$，总时间复杂度为 $O(C \sum K_i)$，在 $K_i \le 10^5$ 时必然超时。

### 4.2 二进制拆分原理
二进制计数原理保证：**任何正整数 $K$，都可以唯一分解为若干个 2 的幂（$1, 2, 4, 8, \dots, 2^p$）与一个余数 $R$ 之和**，其中：
$$R = K - (2^0 + 2^1 + \dots + 2^p) < 2^{p+1}$$

**完备性证明**：
1. 用集合 $\{1, 2, 4, \dots, 2^p\}$ 内的数字组合，可以凑出 $[0, \ 2^{p+1}-1]$ 内的所有整数；
2. 再将该集合中的每个组合加上余数 $R$，可以覆盖 $[R, \ K]$ 内的所有整数；
3. 因为 $R < 2^{p+1}$，两段区间 $[0, \ 2^{p+1}-1]$ 与 $[R, \ K]$ 必然严密重叠并无缝拼合为连续区间 $[0, \ K]$，且任何组合的累加和均不会超过 $K$！

通过二进制拆分，仅需 $\lfloor \log_2 K_i \rfloor + 1$ 个复合新物品，即可等价表示选取 $0 \sim K_i$ 个该物品的所有可能，时间复杂度从 $O(C \sum K)$ 骤降至 $O(C \sum \log K)$！

```java
class MultiKnapsackBinarySplit {
    /**
     * 多重背包二进制拆分标准模板
     * @param capacity 背包总容量
     * @param weights  物品重量数组
     * @param values   物品价值数组
     * @param counts   物品数量上限数组
     * @return 最大价值
     */
    public int multiKnapsack(int capacity, int[] weights, int[] values, int[] counts) {
        int n = weights.length;
        List<Integer> newWeights = new ArrayList<>();
        List<Integer> newValues = new ArrayList<>();

        // 1. 二进制拆分打包
        for (int i = 0; i < n; i++) {
            int w = weights[i];
            int v = values[i];
            int k = counts[i];

            for (int base = 1; k >= base; base <<= 1) {
                newWeights.add(base * w);
                newValues.add(base * v);
                k -= base;
            }
            if (k > 0) {
                newWeights.add(k * w);
                newValues.add(k * v);
            }
        }

        // 2. 直接套用 0-1 背包倒序更新模板
        int[] dp = new int[capacity + 1];
        for (int i = 0; i < newWeights.size(); i++) {
            int w = newWeights.get(i);
            int v = newValues.get(i);
            for (int c = capacity; c >= w; c--) {
                dp[c] = Math.max(dp[c], dp[c - w] + v);
            }
        }

        return dp[capacity];
    }
}
```

## 5. 背包高阶分水岭：组合数 vs 排列数（循环顺序决定命运）

当题目要求求“有多少种装满方案”时，两层 `for` 循环的内外层顺序具有决定性生死影响！

```mermaid
flowchart TD
    subgraph OrderChoice["方案数循环顺序双峰对决"]
        Comb["求【组合数】(顺序无关, 如 LC 518 零钱兑换 II): 必须外层遍历物品，内层遍历容量"]
        Perm["求【排列数】(顺序相关, 如 LC 377 组合总和 IV): 必须外层遍历容量，内层遍历物品"]
    end
```

### 5.1 为什么“外物品内容量”是组合，“外容量内物品”是排列？
- **外层物品**：物品是依次进场的。只有先考虑完硬币 1，才开始考虑硬币 2。硬币 2 永远不可能排在硬币 1 前面被放入，天然避免了乱序重排，因此算出来的是**组合数**！
- **外层容量**：站在容量 $c$ 的视角，每次填入最后一步时，所有的物品（1 和 2）都可以作为最后放入的那一枚。因此既能生成 `1 + 2 = 3`，也能生成 `2 + 1 = 3`，算出来的是**排列数**！

## 6. 大厂面试 30 秒绝杀（背包高频深度考点）

### Q1：背包问题中，不同目标（最值、存在性、方案数）的初始化规则有什么根本区别？
> **答题标杆**：
> 1. **求最大价值（Max）**：`dp` 数组通常全部初始化为 `0`；若要求“必须恰好装满”，除了 `dp[0]=0` 外，其余初始为负无穷 `-INF`。
> 2. **求最少元素个数（Min）**：除了 `dp[0]=0` 外，其余全部初始化为正无穷 `INF`（或 `amount + 1`），防止被初始值污染。
> 3. **求方案数（Count）**：必须令 **`dp[0] = 1`**！含义是“容量为 0 时，什么都不装也是 1 种合法方案”。若初始全填 0，后续加法累加全为 0，答案必定错误。
> 4. **求能否装满（Boolean）**：`dp[0] = true`，其余全为 `false`。
