# 简历-Java后端方向

> [!abstract] 一句话总结
> Java 后端简历要把 JVM、并发、数据库、分布式、系统设计和故障处理能力落到项目证据、指标和可追问细节上，避免只堆技术名词。

## 🎯 定位

目标岗位：Java 后端工程师 / 高级后端工程师。核心卖点是：

- Java / Spring Boot 工程落地能力。
- MySQL、Redis、MQ 的性能与一致性经验。
- 高并发系统设计和压测验证能力。
- JVM、线程池、SQL、锁等待等问题排查能力。
- 分布式事务、幂等、补偿和可观测意识。

## 🧩 技能关键词

| 模块 | 关键词 | 证据写法 |
| ---- | ------ | -------- |
| Java 基础 | 集合、JVM、JUC、线程池、AQS | 写清源码理解和故障排查案例 |
| Spring | IoC、AOP、事务、MVC、MyBatis | 写清事务失效、状态机、Outbox 等落地 |
| 数据库 | MySQL 索引、执行计划、锁、事务 | 写清 SQL 优化前后指标和锁冲突排查 |
| 缓存 | Redis、Lua、缓存一致性、热点 key | 写清秒杀库存、限流、缓存保护 |
| MQ | Kafka/RocketMQ、幂等、DLQ、顺序消息 | 写清 DB+MQ 一致性和消费补偿 |
| 分布式 | 限流、熔断、分布式事务、链路追踪 | 写清故障隔离、补偿、对账和 Trace |
| 工程化 | 日志、指标、Trace、压测、灰度、降级 | 写清问题、方案、结果 |

## 📦 项目表达模板

```text
项目背景：业务为什么需要这个系统。
我的职责：负责哪些核心模块和关键决策。
技术方案：核心链路、关键组件、为什么这样选。
难点突破：遇到什么问题、如何定位、如何解决。
结果指标：性能、成本、准确率、稳定性、业务收益。
复盘改进：后续还能怎么优化。
```

## 🧱 项目一：高并发秒杀系统

关联：[[../20-Java后端/09-项目实战/01-项目-高并发秒杀系统]]

### 简历 bullet

```text
设计并实现高并发秒杀核心链路，基于 Redis Lua 完成库存原子预扣，结合 MQ 异步下单、订单唯一索引、请求幂等和 Outbox 补偿机制，保证固定库存压测场景下无超卖、无重复下单，并沉淀 QPS、P95/P99、MQ lag 和库存一致性校验指标。
```

### 可追问点

- 为什么 Redis 预扣而不是直接扣 DB？
- Lua 如何防超卖？
- Redis 扣减成功但 MQ 失败怎么办？
- 消费者重复消费怎么办？
- 支付成功和超时关单并发怎么办？
- 热点 key 如何拆分？
- 如何证明没有超卖？

### 证据准备

- Lua 脚本。
- 订单表和唯一索引。
- Outbox 表和投递日志。
- 压测报告。
- 一致性校验 SQL。
- MQ 失败补偿记录。

## 🧱 项目二：订单履约系统

关联：[[../20-Java后端/09-项目实战/03-项目-订单履约系统]]

### 简历 bullet

```text
负责订单履约系统状态机设计，围绕创建订单、支付回调、库存冻结、履约发货、超时关单和退款售后建立状态流转模型，使用本地事务 + Outbox + MQ + 消费者幂等 + 补偿任务保证跨服务最终一致，并支持支付/关单并发、重复回调、消息重放等失败场景验证。
```

### 可追问点

- 订单状态机怎么设计？
- 支付回调重复如何处理？
- 关单和支付并发怎么互斥？
- 为什么不用强分布式事务？
- Outbox 投递重复怎么办？
- 补偿任务如何避免越补越乱？

### 证据准备

- 状态机图。
- `orders`、`payment_order`、`order_state_log`、`outbox_event` 表。
- 状态条件更新 SQL。
- 支付重复回调测试。
- Outbox 重试日志。
- 补偿任务执行记录。

## 🧱 项目三：JVM 故障排查演练

关联：[[../20-Java后端/09-项目实战/05-项目-JVM故障排查演练]]

### 简历 bullet

```text
搭建 JVM 故障演练项目，模拟 CPU 飙高、Heap/Metaspace/Direct Memory OOM、死锁和频繁 Full GC 等场景，沉淀 top、jstack、jmap、jcmd、JFR、Arthas 的排查流程，形成“现象-证据-根因-修复-复验”的故障复盘模板。
```

### 可追问点

- CPU 飙高怎么定位到代码行？
- Heap OOM 和 Direct Memory OOM 怎么区分？
- Full GC 频繁一定是内存泄漏吗？
- 死锁日志怎么看？
- Arthas trace/watch 怎么用？

### 证据准备

- 故障触发接口。
- GC 日志。
- `jstack` 输出。
- heap dump 摘要。
- Arthas 命令输出。
- 修复前后指标对比。

## ✅ 简历自查

- 每个技能点都能对应一个项目或问题排查经历。
- 每个项目至少有一个量化指标或验证方案。
- Java 项目不要只写 CRUD，要写性能、并发、一致性和可用性。
- 不要写“精通”却没有项目证据。
- 写了 MQ 就要能回答幂等、重试、DLQ、顺序和堆积。
- 写了 Redis 就要能回答缓存一致性、热点 key、Lua、过期策略。
- 写了 MySQL 就要能回答索引、锁、事务、执行计划。
- 写了 JVM 就要能回答真实排查命令和证据。
