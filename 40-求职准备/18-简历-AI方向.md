# 简历-AI方向

> [!abstract] 一句话总结
> AI 方向简历不要只写“调用大模型 API”，要把 RAG、Agent、MCP、评估、权限、可观测和后端工程化能力落到项目证据、指标和可追问细节上。

## 🎯 定位

目标岗位：AI 应用开发工程师 / RAG 工程师 / AI Agent 工程师 / Java + AI 后端工程师。核心卖点是：

- Java 后端工程化能力 + 大模型应用落地能力。
- 能做 RAG、Agent、MCP、Tool Calling、Langfuse 观测和评估回归。
- 能处理权限隔离、提示注入、工具风险、成本延迟和 badcase 复盘。
- 不只会 Prompt，而是能把 AI 应用做成可运行、可评估、可治理的系统。

## 🧩 技能关键词

| 模块 | 关键词 | 证据写法 |
| ---- | ------ | -------- |
| LLM 应用 | Prompt、结构化输出、Function Calling、流式输出 | 写清输入输出约束、失败兜底、格式校验 |
| RAG | 文档解析、Chunk、Embedding、VectorStore、Hybrid Search、Rerank | 写清召回、排序、引用和评估指标 |
| Agent | ReAct、Plan-Execute、Tool Gateway、Memory、状态机 | 写清工具权限、审批、幂等、审计 |
| MCP | Tools、Resources、Prompts、Server、Client | 写清工具封装、鉴权、限流、错误处理 |
| 评估观测 | Ragas、Langfuse、评估集、badcase | 写清 Recall@K、Faithfulness、P95、Token 成本 |
| 后端基础 | Spring Boot、MySQL、Redis、MQ | 写清工程化、稳定性和性能指标 |

## 📦 项目表达模板

```text
项目背景：为什么业务需要 AI 应用。
我的职责：负责哪些核心模块和工程化能力。
技术方案：RAG/Agent/工具/评估/观测如何串起来。
难点突破：召回不准、幻觉、权限、工具风险、成本延迟如何处理。
结果指标：Recall@K、Faithfulness、任务完成率、P95、Token 成本、人工接管率。
复盘改进：badcase 怎么收敛，后续怎么优化。
```

## 🤖 项目一：企业知识库 RAG 系统

关联：[[../10-AI应用开发/08-项目实战/03-项目-企业知识库RAG系统]]

### 简历 bullet

```text
基于 Spring AI + Milvus/pgvector 构建企业知识库 RAG 系统，实现文档解析、结构化切分、Embedding 入库、Hybrid Search、Rerank、引用溯源、租户权限过滤和 Langfuse 观测；构建评估集跟踪 Recall@K、MRR、Faithfulness、拒答准确率、P95 延迟和 Token 成本，支持 badcase 回归优化。
```

### 可追问点

- 文档解析如何处理 PDF、表格、页码和标题层级？
- Chunk size 和 overlap 怎么选？
- 为什么需要 Hybrid Search？
- Rerank 加在哪一层？有什么成本？
- RAG 答错了怎么定位？
- 如何防止越权召回？
- 如何证明 RAG 效果不是“感觉更好”？

### 证据准备

- document/chunk 表结构。
- 向量库 collection 设计。
- Prompt 模板。
- 评估集样例。
- Langfuse trace 截图或字段。
- badcase 复盘记录。
- Recall@K / Faithfulness / P95 / Token 成本指标。

## 🤖 项目二：业务 Agent 系统

关联：[[../10-AI应用开发/08-项目实战/07-项目-业务Agent系统]]

### 简历 bullet

```text
设计业务 Agent 系统，将 RAG、多轮记忆、MCP 工具和 Skills 编排到统一状态机中，通过 Tool Gateway 实现工具白名单、参数校验、权限校验、风险分级、人工审批、幂等和审计，支持智能客服场景下订单查询、回复草稿、补偿审批等端到端任务。
```

### 可追问点

- Agent 和 Workflow 怎么取舍？
- 为什么不能让 Agent 直接调用所有工具？
- Tool Gateway 做了什么？
- 高风险动作如何审批？
- 工具调用失败如何重试和补偿？
- Memory 如何防污染和泄露？
- Agent 如何评估？

### 证据准备

- Agent 状态机图。
- Tool Gateway 流程图。
- tool call 审计表。
- 风险等级表。
- 人工审批样例。
- Langfuse trace。
- 任务完成率、人工接管率、工具失败率、P95、Token 成本。

## 🤖 项目三：MCP Server 工具集

关联：[[../10-AI应用开发/08-项目实战/06-项目-MCP-Server工具集]]

### 简历 bullet

```text
实现面向业务系统的 MCP Server 工具集，将订单查询、知识检索、工单创建等能力封装为标准化 Tools，并在服务端补充鉴权、参数校验、限流、审计和错误语义，支持 Claude/Cursor/自研 Agent 等多客户端复用。
```

### 可追问点

- MCP 和 Function Calling 的区别？
- Tools、Resources、Prompts 分别适合什么？
- MCP Server 如何做鉴权和限流？
- 工具 description 怎么写才不容易误调？
- 工具报错如何返回给模型？
- 本地 stdio 和远程 HTTP 怎么选？

## 🧪 AI 项目指标写法

| 指标 | 简历写法 |
| ---- | -------- |
| Recall@K | “通过 Hybrid Search + Rerank 提升检索召回稳定性，并用 Recall@K 评估” |
| Faithfulness | “使用评估集检查答案是否忠于资料，降低无依据回答” |
| P95 延迟 | “记录端到端 P95 延迟，拆分检索、Rerank、LLM 生成耗时” |
| Token 成本 | “跟踪单次问答输入/输出 token，优化 chunk 和 Prompt 长度” |
| 人工接管率 | “高风险 Agent 动作进入人工审批，统计人工接管率和审批通过率” |
| Badcase 收敛 | “按召回失败、排序失败、Prompt 失败、模型幻觉分类复盘” |

## ✅ 简历自查

- AI 项目不要只写“调用大模型”，要写评估、观测、安全和降级。
- RAG 项目必须能讲解析、切分、检索、Rerank、引用、权限和评估。
- Agent 项目必须能讲工具权限、审批、幂等、审计和失败恢复。
- MCP 项目必须能讲协议角色、Tools/Resources/Prompts、鉴权和错误处理。
- 每个项目至少有一个可量化指标或评估方案。
- 不要夸大“准确率提升”，没有评估集就写“建立评估集并跟踪指标”。
- 如果是个人项目，要明确哪些已实现、哪些是生产化设计。
