# 面试-Skills与AGENTS

> [!abstract] 一句话总结
> 本文用于把 Skills、MCP、Workflow、Agent、AGENTS.md 的边界整理成可直接复习和面试输出的话术。回答时遵循“先结论、再边界、再项目落地、最后风险与取舍”。

## 回答总框架

1. **先给结论**：一句话回答面试官。
2. **再讲边界**：说清楚谁负责什么，避免概念混淆。
3. **落到项目**：举一个企业场景或自己的项目实现。
4. **补风险与治理**：讲权限、成本、观测、失败兜底。

## 先把五个概念分开

### AGENTS.md 是“团队规则/运行约束”

AGENTS.md 更像给 Agent 的项目内操作手册，典型内容包括：

- 代码库约定。
- 可以用哪些工具。
- 提交、测试、评审要求。
- 输出风格、目录边界、禁改区域。

它回答的是：**这个 Agent 在当前代码库里应该遵守什么规则。**

### Skill 是“任务经验包”

Skill 更像某类任务的最佳实践模板，强调“怎么做更像样”。

典型内容：

- 做代码评审时看什么。
- 做部署时按什么步骤。
- 做数据分析时采用什么结构。

它回答的是：**这类任务通常怎么做。**

### MCP 是“能力连接协议”

MCP 不是任务经验，也不是决策逻辑，而是把外部工具、资源、提示模板标准化暴露出来。

它回答的是：**Agent 能通过什么统一协议连到外部系统。**

### Workflow 是“固定流程编排”

Workflow 更适合步骤稳定、风险高、可审计的场景。

它回答的是：**这件事应该按什么顺序执行。**

### Agent 是“动态决策者”

Agent 的核心价值是基于目标和上下文自己决定下一步。

它回答的是：**现在该做什么、是否要用工具、是否要拆子任务。**

## 一张表讲清边界

| 概念 | 本质 | 关注点 | 典型问题 |
| ---- | ---- | ---- | ---- |
| AGENTS.md | 项目内运行规则 | 约束与边界 | 在这个仓库里怎么做事 |
| Skill | 任务经验包 | 方法与模板 | 这类任务一般怎么做好 |
| MCP | 标准连接协议 | 工具/资源接入 | 外部能力怎么接进来 |
| Workflow | 固定流程编排 | 顺序与控制 | 任务按什么步骤执行 |
| Agent | 动态决策主体 | 目标驱动与工具选择 | 下一步该做什么 |

> [!tip] 最容易拿分的一句话
> **AGENTS.md 管规则，Skill 管经验，MCP 管连接，Workflow 管流程，Agent 管决策。**

## 高频问题

### Q1：Workflow 和 Agent 怎么选？

> 流程固定、风险高、需要稳定审计的任务优先 Workflow；目标开放、需要动态决策和工具选择时才上 Agent。真实企业里常常是 Workflow 包 Agent，而不是二选一。

#### 展开讲

- Workflow 擅长确定性、可追踪、可审批。
- Agent 擅长开放问题、动态分解、环境探索。
- 企业里常见做法是：主流程用 Workflow 控，某一步交给 Agent 自主完成。

#### 项目版答法

> 比如售后场景里，“接诉单→查订单→判断是否超权限→进入审批” 适合 Workflow；而“根据聊天记录总结问题、查知识库、生成回复草稿” 适合 Agent。这样既保留灵活性，也保证关键动作可控。

### Q2：Skill 和 Prompt 有什么区别？

> Prompt 更像一次性的指令；Skill 是可复用、可治理的任务经验包。Skill 不是简单把 Prompt 变长，而是把一类任务的最佳实践沉淀下来。

#### 可以补一句

- Prompt 偏单次交互输入。
- Skill 偏长期沉淀和标准化复用。

### Q3：Skills 和 MCP 有什么区别？

> Skill 描述“怎么做事”，MCP 提供“能用什么工具和数据”。Skill 更偏经验与方法，MCP 更偏能力接入与协议标准。

#### 项目版答法

> 比如“代码评审”这个 Skill 会告诉 Agent 先看 diff、再看风险点、最后输出 review 结构；真正去 GitHub 拉 PR diff、读 issue、发评论，靠的是 MCP 提供的工具连接能力。

### Q4：Function Calling 和 MCP 有什么关系？

> Function Calling 是应用内工具调用机制；MCP 是把工具、资源、提示模板标准化暴露给多个客户端的协议。可以理解成 MCP 是更平台化、可复用的上一层。

### Q5：AGENTS.md 和 Skill 会不会重复？

> 会有交集，但职责不同。AGENTS.md 更强调当前仓库和团队规则，Skill 更强调某类任务的方法论。前者偏“在这里别怎么做”，后者偏“做这类事应该怎么做”。

### Q6：企业为什么需要 AGENTS.md，而不是只靠 Prompt？

> 因为企业要把规则沉淀到代码库或项目边界里，保证不同 Agent、不同人、不同会话都遵守同一套约束。Prompt 太临时，AGENTS.md 更适合作为长期运行规则。

## 企业落地场景

### 场景一：研发效能平台

组合关系：

- AGENTS.md：约束只能改哪些目录、提交前必须跑哪些测试。
- Skill：代码评审、缺陷定位、变更说明生成。
- MCP：连接 GitHub、CI、制品库、告警平台。
- Workflow：提测、审批、发布、回滚流程。
- Agent：在代码分析、故障定位、Review 建议阶段动态决策。

### 场景二：客服/运营 Copilot

组合关系：

- AGENTS.md：限制不可直接退款、不可导出敏感数据。
- Skill：回复草稿生成、投诉分类、知识库引用模板。
- MCP：连 CRM、订单系统、工单系统。
- Workflow：退款审批、升级投诉、补偿发放。
- Agent：在多轮对话里判断该查什么、该引用什么知识。

### 场景三：数据分析 Agent

组合关系：

- AGENTS.md：限定数据目录、禁止跨租户查询。
- Skill：报表分析模板、异常归因模板。
- MCP：连数仓、BI、指标平台。
- Workflow：日报、周报、审批分发。
- Agent：根据问题动态选择维度、生成解释和结论。

## 项目版答法模板

### 模板一：讲边界

> 在我的理解里，这几个概念不能混着讲。AGENTS.md 负责项目内规则，Skill 负责任务经验沉淀，MCP 负责外部能力标准接入，Workflow 负责固定流程编排，Agent 负责目标驱动下的动态决策。企业落地通常不是五选一，而是几者组合。

### 模板二：讲架构

> 我更倾向于 Workflow 包 Agent。主链路保持可控，比如审批、发布、数据导出这些关键步骤走固定流程；在流程中的开放问题，比如查资料、写草稿、分析日志，让 Agent 借助 MCP 动态调用工具，而 Skill 则把这类任务的最佳实践沉淀下来。

### 模板三：讲治理

> 真正上线时，重点不是“让 Agent 更聪明”，而是把规则和能力边界收住。比如 AGENTS.md 约束代码仓库操作，MCP Server 做权限和租户隔离，Workflow 兜审批与回滚，Skill 保证输出风格和任务质量。

## 高频追问

### 追问 1：为什么不全都做成 Agent？

> 因为很多业务不是缺“智能”，而是缺“确定性和可控性”。审批、资金、权限、发布这类高风险动作，全做成 Agent 只会增加不确定性。

### 追问 2：为什么不全都做成 Workflow？

> 因为 Workflow 对开放问题处理能力弱。像代码定位、知识检索、复杂问答、根因分析这类任务，固定流程很难覆盖，需要 Agent 动态探索。

### 追问 3：Skill 和知识库是不是一回事？

> 不是。知识库提供“事实与资料”，Skill 提供“做事方法”。一个回答“知道什么”，一个回答“怎么做”。

### 追问 4：MCP 和 API Gateway 有什么关系？

> 两者不等价。API Gateway 偏通用服务治理，MCP 偏面向 LLM 的能力暴露协议。企业里常见做法是 MCP Server 部署在 API Gateway 后面，共享鉴权、限流、审计能力。

### 追问 5：如果模型乱调工具怎么办？

> 不把权限放在模型侧，而是放在服务端。模型只能提议调用，真正的授权由 Tool Gateway / MCP Server / Policy Engine 判断，必要时进入审批流。

### 追问 6：怎么证明你的方案有效？

> 我会看三类指标：任务成功率、人工接管率、工具误调用率。另外对高风险场景还要看审批命中率、拒绝原因和补偿成功率。

## 一套可直接背的 3 层回答

### 第 1 层：30 秒版

> AGENTS.md、Skill、MCP、Workflow、Agent 各自解决的问题不同。AGENTS.md 管规则，Skill 管经验，MCP 管连接，Workflow 管流程，Agent 管动态决策。企业里通常是 Workflow 包 Agent，再让 Agent 通过 MCP 调工具，同时用 Skill 保证任务质量。

### 第 2 层：3 分钟版

> 如果我来做企业级智能体平台，不会把这些概念混在一起。AGENTS.md 负责项目或代码库级约束，比如哪些目录能改、提交前必须做什么；Skill 负责沉淀任务级最佳实践，比如代码评审、故障分析、报表总结；MCP 负责把 GitHub、工单、数据库这些外部能力标准化接进来；Workflow 负责审批、发布、回滚这类固定主流程；Agent 则负责在开放任务里做动态决策。这样分层的好处是：规则稳定、能力可复用、流程可审计、决策可智能化。

### 第 3 层：项目落地版

> 比如在研发效能场景里，我会让 AGENTS.md 约束代码仓库操作，Skill 固化 code review 和 root cause analysis 的输出结构，MCP 连接 GitHub、CI 和告警系统，Workflow 管住提测、审批、发布、回滚，Agent 负责在故障分析和代码修改阶段动态选择工具。这样既能让 Agent 发挥智能，又不会破坏企业最看重的治理能力。

## 面试时的常见误区

- 把 Skill 讲成“长 Prompt”。
- 把 MCP 讲成“就是插件”。
- 把 Agent 和 Workflow 讲成非此即彼。
- 忽略 AGENTS.md 这类项目内规则文件的治理意义。
- 只谈效果，不谈权限、审计、成本、失败兜底。
