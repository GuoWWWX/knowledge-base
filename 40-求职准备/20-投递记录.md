# 投递记录

> [!abstract] 一句话总结
> 用表格记录求职动作、反馈和复盘，让投递从随机行为变成可迭代流程。

## 公司调研维度

| 维度 | 要看什么 |
| ---- | -------- |
| 业务 | 是否有真实 AI 落地场景 |
| 技术 | Java / Spring / RAG / Agent / 数据平台使用情况 |
| 岗位 | JD 是否要求工程化、RAG、Agent、模型平台 |
| 面试 | 高频问题、项目深挖方向 |

## 复盘动作

- 每 10 次投递复盘一次简历命中率。
- 每次面试后当天记录问题和回答缺口。
- 把反复被问到的问题沉淀到 [[17-面试-项目类问题]]。

## 周复盘模板

| 项目 | 记录 |
| ---- | ---- |
| 本周投递数 | 真实投递后填写 |
| 简历通过数 | 真实投递后填写 |
| 面试邀约数 | 真实投递后填写 |
| 高频 JD 关键词 | 例如 RAG、Agent、Spring、并发、MySQL |
| 下周调整 | 调整简历项目描述、补面试题、定向投递 |

## 状态口径

- `已投递`：简历已发出，等待反馈。
- `简历通过`：进入笔试或面试流程。
- `面试中`：已约面或已完成部分轮次。
- `已拒绝`：收到拒信或超过两周无反馈。
- `Offer`：已拿到正式录用意向。
