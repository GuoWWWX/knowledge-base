# 08 · 系统设计：从核心难点推导高并发高可用架构

系统设计的核心不在于堆砌中间件名词，而在于先看清具体业务场景下的物理瓶颈——比如流量突增时请求积压在哪里、并发读写时锁竞争在哪里、节点宕机时数据怎么恢复——然后再针对性地引入缓存、消息队列、分片或容灾机制。

本章从系统设计的通用思维框架与容量估算出发，逐步拆解高并发、高可用、缓存三大基础架构，并深入秒杀、短链、即时通讯（IM）、订单四个高频工程场景，带你一步步推导架构是如何演进出来的。
