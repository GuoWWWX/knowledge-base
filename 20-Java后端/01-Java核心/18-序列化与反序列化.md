# 序列化与反序列化

> [!abstract] 一句话总结
> 对象在内存里，文件和网络传递的是数据。序列化把对象的数据变成 JSON 文本或其他协议数据，反序列化按目标类型把数据还原成对象；Java 原生 Serializable 只是其中一种具体机制。

## 🎯 先回答：这个要不要学

按当前补 Java 后端基础的目标，分两层：

| 内容 | 现在学到什么程度 | 为什么 |
| --- | --- | --- |
| 对象与 JSON 的转换 | 应该会用，知道输入输出和异常 | HTTP 接口、消息、缓存和配置都可能涉及 |
| Java 原生序列化 | 先认识 Serializable、transient、UID；遇到相关系统再深入 | 它是一种特定的 Java 二进制对象协议，并非所有项目都使用 |

所以“原生对象流源码暂时不深挖”可以；“对象怎么变成可传输数据完全不学”会影响接口开发。本篇先做更直观的 JSON 实验，再把原生机制放到选读部分。

前置：[[11-IO与NIO]]。示例使用 JDK 21；JSON 实验依赖 Jackson，原生实验只需要 JDK。

## 1. 🤔 为什么需要：内存里的 User 怎么交给另一个程序

假设服务器内存里有一个 User：姓名是小明，年龄是 20。这个对象的引用只用于当前 JVM；把引用的打印结果传给前端，前端无法因此得到你的 User 对象。

可以约定传这些数据：

```json
{"name":"小明","age":20}
```

转换过程是：

```text
Java User 对象
    ↓ 序列化
JSON 字符串
    ↓ 按 UTF-8 等约定编码
文件 / HTTP 消息等场景中的字节数据
    ↓ 读取并按约定解码
JSON 字符串
    ↓ 反序列化，指定 User 作为目标类型
新的 Java User 对象
```

JSON 可以表达字段数据，不会把 User 类的方法实现一同复制过去。接收方按自己的代码和映射规则处理这些数据；不是拿到 JSON 就知道你项目里全部 Java 类型。

### 在什么地方遇到

- 前端提交 JSON 请求，后端转换成请求对象；后端返回对象，再转换成 JSON 响应。Spring MVC 配置相应消息转换器后，通常在框架层完成这一步。
- 发消息时把订单数据编码成约定消息格式，消费者再解析。
- 缓存或文件中保存对象数据，之后读回。具体格式由配置决定，不能假设 Redis / MQ 一定使用 Java 原生序列化或一定是 JSON。

ORM 把字段映射到关系数据库是另一套映射过程；不是所有“保存对象数据”都意味着调用本篇某个序列化 API。

## 2. 🧰 先认识两个实际操作：对象写 JSON、JSON 读对象

Jackson 是处理 JSON 的库，ObjectMapper 是其常用入口。下面是核心片段，假设已有 mapper、original 和 User 类，完整定义在第 3 节：

```java
String json = mapper.writeValueAsString(original); // 输入对象，输出 JSON 字符串
User restored = mapper.readValue(json, User.class); // 输入 JSON 与目标类型，输出 User
```

User.class 是“我要读成 User 类型”的说明。readValue 不是自动猜业务类，也不会替你去数据库查询或保存这个用户。

两者的名字可以直接读：writeValueAsString，把值写成字符串；readValue，从数据里读出一个指定类型的值。

## 3. 💻 完整 JSON 实验：对象写文件，再读回对象

在一个新的实验目录里放 `pom.xml` 和 `JsonDemo.java` 两个文件。只用于学习，不修改已有项目的依赖。

独立实验固定使用 Jackson **2.21.4** 的 2.x API。已有 Spring 项目应遵循项目的 BOM / 依赖管理，不要为照抄示例重复引入一套版本；Jackson 3 的包名与 API 应另按对应版本文档使用。

`pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>demo</groupId>
    <artifactId>json-demo</artifactId>
    <version>1.0</version>
    <dependencies>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>2.21.4</version>
        </dependency>
    </dependencies>
</project>
```

`JsonDemo.java`：

```java
import com.fasterxml.jackson.databind.ObjectMapper;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

public class JsonDemo {
    public static class User {
        public String name;
        public int age;
        public User() {} // 本例让 Jackson 先创建对象，再按字段写入数据
        public User(String name, int age) {
            this.name = name;
            this.age = age;
        }
    }
    public static void main(String[] args) throws Exception {
        ObjectMapper mapper = new ObjectMapper();
        User original = new User("小明", 20);
        Path file = Files.createTempFile("user-json-", ".json");
        try {
            String json = mapper.writeValueAsString(original);
            System.out.println(json); // {"name":"小明","age":20}，字段顺序不重要
            Files.writeString(file, json, StandardCharsets.UTF_8);

            String loaded = Files.readString(file, StandardCharsets.UTF_8);
            User restored = mapper.readValue(loaded, User.class);
            System.out.println(restored.name);        // 小明
            System.out.println(restored.age);         // 20
            System.out.println(original == restored); // false，恢复得到新对象
        } finally {
            Files.deleteIfExists(file); // 只清理本程序刚创建的临时文件
        }
    }
}
```

这里用 public 字段和无参构造器减少演示配置，不要求业务类都照这个风格写；Jackson 也支持访问器、注解等映射方式，取决于类定义与配置。本例的 User **没有 implements Serializable，仍然可以转换为 JSON**。

在上述实验目录运行下面的 PowerShell 命令，需要 Maven 和 JDK 21，首次解析依赖可能需要网络：

```powershell
mvn dependency:copy-dependencies -DincludeScope=runtime
javac -encoding UTF-8 -cp "target/dependency/*" JsonDemo.java
java -cp ".;target/dependency/*" JsonDemo
```

第一条将库及其依赖放进 target/dependency；第二条编译时让 Java 找到这些库；第三条带着当前目录和依赖目录运行。Windows 的 classpath 多项用分号分隔，放进引号避免 PowerShell 将它当作命令分隔符。

本实验确实写入再读回文件，结束时删除临时文件。需要跨重启保留时，可以改成你明确选择的持久化位置，并分别运行写入和读取程序；转换与文件读写是两个步骤。

最小练习：把年龄改为 21，观察 JSON 和恢复对象中的年龄一起变化；再把待解析 JSON 的 age 改为无法转换成 int 的文本，观察映射错误。

## 4. 🆚 序列化、拷贝、toString 分别干什么

| 操作 | 目标 | 不自动保证什么 |
| --- | --- | --- |
| 浅 / 深拷贝 | 在当前程序得到需要独立修改的数据 | 不代表已经转成文件或网络协议 |
| JSON 序列化 | 把数据转换成约定 JSON 表示 | 不保证所有 Java 类型、身份和引用关系原样保留 |
| Java 原生序列化 | 按 Java 对象流协议写入相应对象状态 | 不等于通用、无风险的跨系统协议 |
| toString | 生成便于人阅读或调试的文字 | 格式不一定是 JSON，也不保证可以还原 |

“先转 JSON 再读回来”在简单映射下会创建新对象，但字段过滤、类型、日期、共享引用等都可能改变。不要把它当成不用分析字段就可靠的通用深拷贝方案，见 [[17-对象语义与拷贝]]。

## 5. 📘 选读：Java 原生序列化到底是什么

它用 ObjectOutputStream / ObjectInputStream 读写 Java 对象流，普通参与类通常实现 Serializable。Serializable 是标记接口，本身没有需要实现的方法。

保存为 `NativeSerializationDemo.java`，运行 `java NativeSerializationDemo.java`。只读取本程序自己生成的内存数据，不读取外部未知文件。

```java
import java.io.*;

public class NativeSerializationDemo {
    static class User implements Serializable {
        private static final long serialVersionUID = 1L;
        String name;
        int age;
        transient String token; // 演示字段，不保存到默认对象流
        User(String name, int age) {
            this.name = name;
            this.age = age;
        }
    }
    public static void main(String[] args) throws Exception {
        User original = new User("小明", 20);
        original.token = "demo-token";
        byte[] data;
        try (var bytes = new ByteArrayOutputStream();
             var out = new ObjectOutputStream(bytes)) {
            out.writeObject(original); // 对象 → 二进制对象流
            out.flush();
            data = bytes.toByteArray();
        }
        System.out.println(data.length > 0); // true，已有协议字节，不是 JSON 文本
        try (var in = new ObjectInputStream(new ByteArrayInputStream(data))) {
            User restored = (User) in.readObject(); // 二进制对象流 → 对象
            System.out.println(restored.name);        // 小明
            System.out.println(restored.age);         // 20
            System.out.println(restored.token);       // null
            System.out.println(original == restored); // false
        }
    }
}
```

本例 token 没有被写进默认对象流，恢复时得到引用默认值 null。把 transient 去掉再运行，会恢复 demo-token；这只解释默认原生序列化，不代表给字段加 transient 就一定对任何 JSON 库配置生效。

### 先认识三个词，暂时不用背整套源码

| 名称 | 做什么 | 需要知道的边界 |
| --- | --- | --- |
| Serializable | 标记支持原生序列化 | 根类支持，不代表所有要写出的引用字段对象都支持 |
| transient | 默认对象流跳过该实例字段 | 不是加密；自定义读写方法可以改变默认行为 |
| serialVersionUID | 参与类版本兼容性检查 | 不匹配可能 InvalidClassException；相同也不保证任意字段变更兼容 |

static 字段属于类，不是默认保存的实例状态。普通 Serializable 类恢复时不执行本类的普通构造器与实例字段初始化器，而会调用第一个非 Serializable 父类可访问的无参构造器；Record 等有专门恢复规则，深入时再单独看。

如果在本例 User 加一个普通实例字段 `Object extra = new Object();`，默认写出会遇到 NotSerializableException，因为对象图中这个需要保存的对象不支持该机制。

## 6. ⚠️ 实际使用时关注什么

- JSON 字段名、类型与目标类不匹配，可能报错或按配置被忽略；不要假设 readValue 永远成功。
- JSON 集合反序列化通常还要说明元素类型，TypeReference 的原因见 [[01-泛型与类型擦除]]，基础示例先掌握单个对象。
- 写文件要约定字符集，文件 IO 与数据转换都可能失败；本篇 main 的 throws Exception 是实验简化，业务异常边界见 [[02-异常处理最佳实践]]。
- 不直接对不可信输入调用原生 readObject。确实有历史兼容需求时，再按业务配置 ObjectInputFilter 和输入限制；过滤不代替字段验证。
- 日期时间、金额、敏感字段是否输出，要由接口契约与映射配置决定；“能转成 JSON”不等于“所有字段都应该返回”。

## 🎯 自测与面试问题

> [!question]- 为什么后端返回 User 时，前端看到的通常是 JSON？
> HTTP 传输的是约定格式的数据，消息转换器按配置把 User 的相关字段转换成 JSON，并编码为字节；不是把当前 JVM 中的对象引用交给前端。

> [!question]- User 没有 implements Serializable，为什么 Jackson 示例能运行？
> Serializable 是 Java 原生对象流的机制；Jackson 使用自己的 JSON 映射规则，不要求普通 User 为此实现该接口。

> [!question]- writeValueAsString 和 readValue 的输入输出分别是什么？
> 前者输入对象、返回 JSON 字符串；后者输入数据和目标类型信息，返回该类型对象。本篇指定 User.class，恢复得到的是新 User。

> [!question]- 现在是否必须深入 ObjectInputStream 源码？
> 当前先会对象与 JSON 的转换、识别默认原生序列化规则；遇到原生对象流、兼容性或相关面试要求，再深入对象图、UID、构造过程与过滤。
