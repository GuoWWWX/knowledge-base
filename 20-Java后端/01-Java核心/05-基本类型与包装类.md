# 基本类型与包装类

> [!abstract] 一句话总结
> 基本类型保存数值等简单值，包装类让它们进入对象体系；数值提升、溢出、装箱缓存和 null 拆箱决定了很多“编译通过但结果不对”的边界。

## 🎯 本节定位

- 语言前置课。初学者先读本篇，再读 [[06-面向对象与方法调用]]，然后进入泛型与集合。
- 本篇示例使用 JDK 21；基本语义同样适用于 JDK 8/17。十进制精度深入见 [[07-BigDecimal与数值精度]]。

## 🗣️ 白话版

`int` 像一格有固定容量的数值空间，`Integer` 则是对象引用，可以为 null。把两者混用，编译器会自动转换，但不会替业务决定“缺值是不是 0”，也不会自动阻止整数溢出。

## 🧩 核心概念

| 类型 | 位数 / 范围要点 | 包装类 |
| --- | --- | --- |
| byte | 8 位，-128～127 | Byte |
| short | 16 位有符号 | Short |
| int | 32 位有符号 | Integer |
| long | 64 位有符号，字面量常用 `L` | Long |
| float | 32 位 IEEE 754 二进制浮点，字面量用 `F` | Float |
| double | 64 位 IEEE 754 二进制浮点 | Double |
| char | 16 位无符号，表示一个 UTF-16 代码单元 | Character |
| boolean | true / false，语言规范不规定独立变量占多少位 | Boolean |

`String`、数组、包装类都是引用类型。实例字段和数组元素有默认值（数值 0、boolean 为 false、引用 null）；局部变量必须先完成明确赋值才能读取。

## ⚙️ 数值转换为什么会出错

### 提升发生在运算时，不是赋值时

`byte/short/char` 参与常见整数算术时先提升为 int；混入 long、float、double 时再按数值提升规则计算。`long x = int值 * int值` 先做 int 乘法，结果溢出后再赋给 long 也救不回来，应在运算前提升一个操作数。

整数除法会向 0 截断：`5 / 2 == 2`，`-5 / 2 == -2`。想得到小数，要在除法前转换，如 `5 / 2.0`。`long → double` 虽是拓宽转换，也可能损失整数精度。

### 强转和复合赋值

`(byte) 128` 截掉高位后得到 -128，不是范围校验。`byte b = 1; b += 1;` 包含隐式窄化转换，而 `b = b + 1` 不能直接编译。需要拒绝溢出时用 `Math.addExact/multiplyExact/toIntExact`。

`&`、`|` 对 boolean 会计算两边，`&&`、`||` 短路；整数位移 `>>` 保留符号扩展，`>>>` 高位补 0。int 位移距离只取低 5 位，因此 `1 << 32` 实际是 `1 << 0`。

## 🔍 装箱、缓存与相等性

装箱通常由 `Integer.valueOf(int)` 完成，拆箱由 `intValue()` 完成。`Integer.valueOf` 保证缓存 -128～127，范围外可能缓存，也可能不缓存；业务判断不能依赖对象身份。

- 两个 Integer 用 `==` 比引用；与 int 比较时会拆箱，null 会 NPE。
- `Integer.equals` 同时看类型和值：`Integer.valueOf(1).equals(Long.valueOf(1))` 是 false。
- `Integer.parseInt("12")` 返回 int，`Integer.valueOf("12")` 返回 Integer；非法文本抛 `NumberFormatException`。
- `Objects.equals(a, b)` 可比较可空引用，但不会统一不同包装类型的数值语义。

## 💻 代码实践 / 🧪 最小验证

保存为 `PrimitiveDemo.java`，运行 `java PrimitiveDemo.java`。这是可独立运行的 JDK 21 示例。

```java
import java.util.Objects;

public class PrimitiveDemo {
    public static void main(String[] args) {
        int n = 50_000;
        System.out.println(n * n);             // -1794967296
        System.out.println(1L * n * n);        // 2500000000
        System.out.println((byte) 128);       // -128
        System.out.println(5 / 2);            // 2
        Integer a = 127, b = 127;
        System.out.println(a == b);           // true，缓存范围内
        System.out.println(Objects.equals(a, b)); // true，按值比较
        Integer missing = null;
        try {
            int value = missing;
            System.out.println(value);
        } catch (NullPointerException e) {
            System.out.println("null cannot unbox");
        }
        try {
            Math.multiplyExact(n, n);
        } catch (ArithmeticException e) {
            System.out.println("overflow detected");
        }
    }
}
```

## ⚠️ 踩坑与注意事项

- 三元表达式混合包装类与基本类型，可能触发拆箱；先判空，再参与计算。
- `float/double` 不是精确十进制；金额不要靠多转几次类型解决。
- `Integer` 不可变，`count++` 是拆箱、计算、重新装箱，不是原子操作。
- 一维数组的 `length` 是元素数；字符串的 `length()` 是 UTF-16 代码单元数，见 [[03-String与字符串常量池]]。

## 🎯 面试问题

> [!question]- 为什么 `long total = a * b` 仍可能溢出？
> **30 秒**：如果 a、b 都是 int，乘法先按 int 执行，赋给 long 太晚。写 `(long) a * b`，需要范围检查时用 Exact 系列方法。
>
> **追问**：long 自身也有上限；超出 long 的整数运算应考虑 BigInteger。

> [!question]- 为什么 Integer 有时 `==` 是 true，有时不是？
> `==` 比对象引用，缓存会使部分装箱结果复用。数值比较应明确类型后使用 equals 或拆箱比较，并先处理 null。

## 🧭 源码入口速查

- `Integer#valueOf` / `IntegerCache`：装箱缓存。
- `Integer#intValue`：拆箱对应调用。
- `Math#multiplyExact`：溢出检测。
