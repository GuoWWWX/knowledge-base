# 正则表达式

> [!abstract] 一句话总结
> 正则是一种“描述字符串长什么样”的规则。Java 按这条规则完成整串校验、从文字中提取片段、替换或切分；先确定要做哪种操作，再选择方法。

## 🎯 本节先学会这三件事

1. 判断订单编号是否符合约定格式，用 matches。
2. 从一段文字中找出订单编号，用 Pattern、Matcher、find 和 group。
3. 把文字中的数字替换掉，用 replaceAll；顺便理解 split。

所有完整示例使用 JDK 21，不需要安装第三方库。先读第 1～6 节并运行程序，再看转义和其他注意事项；前置是 [[03-String与字符串常量池]]。

## 1. 🤔 从一个实际要求开始：编号必须是 ORD- 加四位数字

假设项目规定编号形如 ORD-2026，这只是本篇的格式约定，不表示真实订单系统一定这样设计。希望得到：

| 输入 | 是否符合格式 |
| --- | --- |
| ORD-2026 | 是 |
| ORD-0001 | 是 |
| ORD-26 | 否，数字只有两位 |
| ORD-ABCD | 否，后面不是数字 |
| xORD-2026 | 否，多了前缀 |

可以手写长度判断、startsWith，再逐个检查字符。正则把这套字符排列规则写成一个字符串：

```java
String rule = "ORD-[0-9]{4}";
```

逐段读：

| 规则部分 | 含义 |
| --- | --- |
| ORD- | 必须出现这四个普通字符 |
| [0-9] | 当前位置是 0 到 9 中的任意一个数字 |
| {4} | 前面那个数字规则恰好重复 4 次 |

所以 [0-9]{4} 不是数字值等于 4，而是“四个位置，每个位置都是数字”。

## 2. ✅ 整个字符串合不合格：matches

下面是可放进 main 的代码，不需要额外 imports：

```java
String rule = "ORD-[0-9]{4}";
System.out.println("ORD-2026".matches(rule));  // true
System.out.println("ORD-26".matches(rule));    // false
System.out.println("ORD-ABCD".matches(rule));  // false
System.out.println("xORD-2026".matches(rule)); // false
```

这里 matches 返回 boolean，检查整个字符串是否符合规则；它不会返回提取出来的编号。因为是整串匹配，本例不必再加 ^ 和 $。

规则也可以更简单：

```java
System.out.println("123".matches("[0-9]+"));  // true，至少一个数字
System.out.println("a123".matches("[0-9]+")); // false，整个字符串还含字母
```

`+` 表示前面的规则出现一次或多次。如果只是判断一个字符串是否等于固定文本，用 equals 即可；判断是否包含固定文本，用 contains 即可。

## 3. 🔎 从一段文字里找编号：find

现在输入变成“处理 ORD-2026 和 ORD-1001”。整段话显然不符合单个编号格式，我们要做的是从里面找到两段符合规则的文字。

下面片段可放进 main，需要导入 `java.util.regex.Pattern` 和 `java.util.regex.Matcher`：

```java
String text = "处理 ORD-2026 和 ORD-1001";
Pattern pattern = Pattern.compile("ORD-[0-9]{4}");
Matcher matcher = pattern.matcher(text);

while (matcher.find()) {
    System.out.println(matcher.group());
}
// 依次打印 ORD-2026、ORD-1001
```

每一行都对应明确动作：

| 代码 | 在做什么 |
| --- | --- |
| Pattern.compile(rule) | 把规则编译成 Pattern 对象，供后面匹配使用 |
| pattern.matcher(text) | 针对这段文字建立一个 Matcher，记录查找位置和结果 |
| matcher.find() | 从当前位置继续找下一段，找到返回 true，没找到返回 false |
| matcher.group() | 取出刚刚找到的整段文字，等价于 group(0) |

第一次 find 找到 ORD-2026，第二次找到 ORD-1001，第三次没有结果，循环结束。**find 决定能否进入循环，group 才取出本次找到的内容。**

只想取第一个时用 if (matcher.find())；想取所有时用 while。必须先成功匹配，再调用 group，不能一创建 Matcher 就直接 group。

本节输入约定编号以空格或标点分隔。如果真实规则要防止从 ORD-202600 中截取出 ORD-2026，还需要加边界约束；find 找局部片段，不会自动判断完整业务编号。

## 4. ✂️ 只想取编号后面的数字：加括号并用 group(1)

把规则改成 `ORD-([0-9]{4})`。小括号表示“把这一部分另外记下来”，这样就能取到 2026，而不带 ORD- 前缀。

```java
// 需要前一节的 Pattern、Matcher imports，可放进 main。
Matcher matcher = Pattern.compile("ORD-([0-9]{4})")
        .matcher("处理 ORD-2026 和 ORD-1001");
while (matcher.find()) {
    System.out.println(matcher.group(0) + " -> " + matcher.group(1));
}
// ORD-2026 -> 2026
// ORD-1001 -> 1001
```

- group(0)：本次完整匹配，如 ORD-2026。
- group(1)：第一个捕获括号里的内容，如 2026。
- 多个捕获组按左括号出现的顺序编号；没有相应组时不能凭空 group(2)。

括号本身不出现在提取结果里，它是规则的一部分。

## 5. 🔄 替换与切分

### replaceAll：把所有匹配片段换成指定文字

下面片段可放进 main：

```java
String text = "订单2026金额99";
String result = text.replaceAll("[0-9]+", "#");
System.out.println(result); // 订单#金额#
System.out.println(text);   // 订单2026金额99，原 String 没有变
```

第一个参数是“要找到什么”，第二个参数是“找到后换成什么”。[0-9]+ 把连续数字当成一段，因此 2026 换成一个 #，不是四个 #。

固定文本替换可直接用 `text.replace("旧文本", "新文本")`，不需要正则；replaceAll 的第一个参数才按正则解释。

### split：按分隔规则拆成数组

```java
// 可放进 main；这里用完整类名，不需要另写 import。
String[] parts = "a,b,c".split(",");
System.out.println(java.util.Arrays.toString(parts)); // [a, b, c]
String[] dotted = "a.b.c".split("\\.");
System.out.println(java.util.Arrays.toString(dotted)); // [a, b, c]
```

为什么点号前要有两个反斜杠？下一节解释。逗号在这里是普通字符；点号在正则中是特殊字符，不能当普通点直接使用。

## 6. 💻 完整实验：校验、提取、替换、切分

保存为 `RegexDemo.java`，运行 `java RegexDemo.java`。

```java
import java.util.Arrays;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class RegexDemo {
    public static void main(String[] args) {
        String rule = "ORD-[0-9]{4}";
        System.out.println("ORD-2026".matches(rule));  // true
        System.out.println("ORD-26".matches(rule));    // false
        System.out.println("xORD-2026".matches(rule)); // false

        Matcher matcher = Pattern.compile("ORD-([0-9]{4})")
                .matcher("处理 ORD-2026 和 ORD-1001");
        while (matcher.find()) {
            System.out.println(matcher.group(0) + " -> " + matcher.group(1));
        }
        System.out.println("订单2026金额99".replaceAll("[0-9]+", "#"));
        System.out.println(Arrays.toString("a.b.c".split("\\.")));
    }
}
```

依次输出：

```text
true
false
false
ORD-2026 -> 2026
ORD-1001 -> 1001
订单#金额#
[a, b, c]
```

最小练习：把编号规则的 {4} 改成 {2,4}，分别验证 ORD-26、ORD-2026 和 ORD-20260，整串校验结果应为 true、true、false。再把替换规则改成 [0-9]，观察每位数字被单独替换后的结果。

## 7. 🧩 先够用的语法与两层转义

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| [0-9] | 一位 ASCII 数字 | 7 |
| [a-zA-Z] | 一位英文字母 | a 或 Z |
| + | 前一规则至少一次 | [0-9]+ 匹配 12 |
| * | 前一规则零次或多次 | a* 也能匹配空串 |
| ? | 前一规则零次或一次 | colou?r 匹配 color、colour |
| {m,n} | 前一规则重复 m 到 n 次 | [0-9]{2,4} |
| (...) | 捕获这一部分 | 用 group(1) 读取 |
| . | 默认匹配一个非行终止符字符 | 它不是普通点号 |

正则引擎希望收到 `\.`，意思是匹配普通点。但 Java 字符串本身也使用反斜杠转义，因此源码要写 `"\\."`：

```text
Java 源码字符串 "\\." → 运行时字符串 \. → 正则含义：普通点号
```

同理，正则 `\d+` 在 Java 源码写成 `"\\d+"`；本篇优先写 [0-9]+，减少入门时同时理解两层转义的负担。默认 \d 对应 ASCII 数字，Unicode 字符类模式会改变这类预定义规则的范围。

## 8. ⚠️ 进阶选读与常见错误

- 看目标选方法：matches 校验整串，find 找局部，lookingAt 检查开头；不要把“包含数字”当成“全部是数字”。
- split 默认丢弃末尾空项；`"a,b,".split(",", -1)` 会保留末尾空字符串。
- 同一规则反复使用时复用 Pattern；每个请求独立创建 Matcher，Matcher 有可变状态，不能无保护共享给多个线程。
- 动态文本按字面量匹配时用 Pattern.quote(text)；动态替换文本含 $、反斜杠时，用 Matcher.quoteReplacement(text)，两者处理不同语法层。
- 替换里的 $1 可以引用第一个捕获组，这是另一项功能，不要把外部字符串未经处理地当作替换表达式。
- ^/$ 受行模式等影响；需要绝对输入边界可了解 \A/\z。点号是否跨行由 DOTALL 等标志控制，和 MULTILINE 不是同一个开关。
- .* 默认贪婪，.*? 尽量少取，但非贪婪不保证高效；避免 (a+)+ 这类歧义嵌套重复，在外部输入上限制长度。Java Matcher 没有每次匹配的内建超时参数。
- 正则检查日期“长得像日期”，不证明 2 月 30 日存在；日期交给 [[08-日期时间API]] 严格解析。JSON 等结构化文本交给对应解析器。

## 🎯 自测与面试问题

> [!question]- [0-9]{4} 到底匹配数字 4，还是四位数字？
> 是四个数字位置，{4} 约束前一个规则的重复次数。匹配具体数字 4 直接写普通字符 4。

> [!question]- 从“处理 ORD-2026”中取编号，为什么不能只用 matches？
> 整段文字不符合单个编号格式。用 find 找出局部片段，再用 group 读取；matches 返回的是整串校验结果 boolean。

> [!question]- group(0) 与 group(1) 分别是什么？
> group(0) 是本次完整匹配，group(1) 是第一个捕获组。必须先匹配成功，再读取结果。

> [!question]- 把连续数字换成一个 #，为什么用 [0-9]+？
> + 把一段连续数字作为一次匹配；只写 [0-9] 会让每个数字分别匹配并分别替换。
