## 📌 JDK 排序 API 全景

| API                      | 适用        | 底层算法              | 稳定?     | 说明             |
| ------------------------ | --------- | ----------------- | ------- | -------------- |
| `Arrays.sort(int[])`     | 基本类型数组    | **双轴快排**          | ❌       | 最快，常数小         |
| `Arrays.sort(Object[])`  | 对象数组      | **TimSort**（改良归并） | ✅       | 对象要稳定          |
| `Arrays.parallelSort()`  | 大数据数组     | 并行归并/快排           | ❌/✅     | >8192 才划算      |
| `Collections.sort(List)` | 老 API     | **TimSort**       | ✅       | 委托 `List.sort` |
| `list.sort(Comparator)`  | JDK 8+ 推荐 | **TimSort**       | ✅       | 推荐             |
| `Stream.sorted()`        | 流处理       | 流内部排序             | ✅       | 并行时归并          |
| `PriorityQueue`          | TopK/优先队列 | **堆**             | ❌（无序迭代） | 见 Queue 篇      |

> [!important] 一句话记底层
> **基本类型 → 双轴快排（不稳定）；对象/集合 → TimSort（稳定）。** 这是 Java 排序 API 最核心的差异，面试必问。

## 🧩 核心概念

### 稳定性：为什么 Java 的对象排序必须稳定

> [!note] 什么是稳定性
> **相等元素排序前后的相对顺序不变**。多字段排序时，第二次排序必须稳定，否则第一次的顺序会被打乱——"先排次要键，再排主要键"依赖稳定性。

- `List.sort`（TimSort）**稳定** → 多字段排序结果正确。
- `Arrays.sort(int[])`（双轴快排）**不稳定** → 但 `int` 相等元素没有"身份"，不需要稳定，所以用更快的快排。

```java
// 例：按分数排 [{name:"张三",score:90},{name:"李四",score:90}]
// 稳定排序：张三在前（保持原始顺序）；不稳定排序：顺序可能变
```

### Comparable vs Comparator

| | Comparable | Comparator |
| ---- | ---- | ---- |
| 位置 | 类自身实现（`compareTo`） | 外部定义（`compare`） |
| 一个类只能 | 一种自然排序 | 多种排序方式 |
| 典型 | `Integer`、`String`、自定义业务对象 | 排序时临时指定 |
| 坑 | 改类内实现影响全局 | 写错合同抛异常 |

```java
// Comparable：类内自然序
record Student(String name, int score, int age) implements Comparable<Student> {
    @Override public int compareTo(Student o) {
        return Integer.compare(this.score, o.score);   // 按分数升序
    }
}

// Comparator：外部临时指定（推荐，灵活）
List<Student> students = ...;
students.sort(Comparator.comparing(Student::age));                // 按年龄
students.sort(Comparator.comparing(Student::score, Comparator.reverseOrder()));  // 分数降序
```

## 💻 常用 API 与代码

### 1. 数组排序

```java
int[] arr = {5, 3, 8, 1, 9, 2};
Arrays.sort(arr);                        // 双轴快排，原地升序 → [1,2,3,5,8,9]

// 降序：基本类型没有 Comparator，要转成对象或自己实现
Integer[] boxed = {5, 3, 8, 1, 9, 2};
Arrays.sort(boxed, Comparator.reverseOrder());          // 对象数组可传 Comparator

// 范围排序
Arrays.sort(arr, 1, 4);                  // 只排 [1,4)，其余不动

// 并行排序（大数据）
Arrays.parallelSort(arr);                // 内部 ForkJoin，>8192 元素才划算
```

### 2. 集合排序

```java
List<Integer> list = new ArrayList<>(List.of(5, 3, 8, 1, 9, 2));
list.sort(Comparator.naturalOrder());    // ✅ JDK 8+ 推荐（TimSort）
Collections.sort(list);                  // 老 API（内部也是 TimSort）

// 降序
list.sort(Comparator.reverseOrder());

// 自定义对象
students.sort(Comparator.comparing(Student::score));   // 按分数升序
```

### 3. Stream 排序

```java
List<String> names = students.stream()
        .sorted(Comparator.comparing(Student::score).reversed())   // 分数降序
        .map(Student::name)
        .toList();
```

## 💻 复杂排序

### 1. 多字段排序（Comparator 链）

```java
// 需求：先按分数降序，同分按年龄升序
students.sort(Comparator.comparing(Student::score, Comparator.reverseOrder())
        .thenComparing(Student::age));
// 结果：李四(90,18) → 张三(90,20) → 王五(85,22)

// 等价写法（多条件 lambda）
students.sort((a, b) -> {
    int c = Integer.compare(b.score(), a.score());   // score 降序
    if (c != 0) return c;
    return Integer.compare(a.age(), b.age());        // age 升序
});
```

> [!note] 为什么 Comparator 链稳定
> `thenComparing` 依赖底层 TimSort 的稳定：第一键相等时，第二键比较不打乱第一键相同元素的顺序。**若底层是不稳定的快排，`thenComparing` 也不能保证。**

### 2. null 处理

```java
list.sort(Comparator.nullsLast(Comparator.naturalOrder()));    // null 排最后
list.sort(Comparator.nullsFirst(Comparator.reverseOrder()));   // null 排最前
// 不处理 null → Comparator.naturalOrder() 对 null 抛 NPE
```

### 3. 排序 + 分页/去重的组合

```java
// 排序后取前 N（小数据）：sorted + limit
List<Student> top3 = students.stream()
        .sorted(Comparator.comparing(Student::score).reversed())
        .limit(3)
        .toList();

// 排序后去重（稳定 → 保留第一次出现的）
list.stream().distinct().sorted().toList();

// 排序后二分查找（Arrays.binarySearch 要求有序）
Arrays.sort(arr);
int idx = Arrays.binarySearch(arr, 5);   // 返回下标或 -(插入点+1)
```

## 🔍 JDK 内置排序底层（必须说清）

### 为什么 `Arrays.sort(int[])` 用双轴快排

```java
// DualPivotQuickSort：两个 pivot 把数组分成三段，常数比普通快排更小
// 小数组（≤47）改用插入排序；中等（≤286）用单轴快排；大数组且近乎有序用归并
int[] arr = ...;
Arrays.sort(arr);   // 基本类型：双轴快排（不稳定、快）
```

### TimSort 是什么（对象排序的灵魂）

```java
// TimSort = 插入排序 + 归并排序 的混合
// 1. 把数组切成"自然有序段"（run）：升序段直接用，降序段反转
// 2. 短 run（<32）用插入排序补齐
// 3. 用归并合并所有 run
// 优点：近乎有序的数据接近 O(n)；稳定；工程上最实用
List<Integer> list = ...;
list.sort(Comparator.naturalOrder());   // 对象/集合：TimSort（稳定）
```

**为什么对象排序用 TimSort 而基本类型用双轴快排**：
1. **稳定性**：对象排序常依赖多字段排序，需要稳定；
2. **有序数据快**：真实数据常部分有序（数据库取出、时间序列），TimSort 的 run 检测让这种情况接近 O(n)；
3. **基本类型不需要稳定**：`int` 相等元素无"身份"，用更快的快排。

> [!note] 面试一句话
> `Arrays.sort(int[])` 用双轴快排（不稳定、最快）；`Arrays.sort(Object[])` / `Collections.sort` / `list.sort` 用 TimSort（稳定、对有序数据友好）。

## ⚠️ 踩坑与注意事项

- [ ] **稳定性用错**：需要稳定时用了 `Arrays.sort(int[])`（但那本来就是基本类型，无所谓）；对象排序想要稳定就用 `List.sort`/`Arrays.sort(Object[])`，别手写快排。
- [ ] **`a - b` 溢出**：`return a.score - b.score` 在极值会溢出（MAX - MIN），**必须用 `Integer.compare`**。
- [ ] **Comparator 违反合同**：不满足自反/反对称/传递 → TimSort 抛 `IllegalArgumentException: Comparison method violates its general contract!`。
- [ ] **null 排序 NPE**：用 `Comparator.nullsFirst/nullsLast` 处理。
- [ ] **基本类型不能传 Comparator**：`Arrays.sort(int[], Comparator)` 不存在，要先装箱或自己实现。
- [ ] **`parallelSort` 小数组更慢**：ForkJoin 拆分开销大，>8192 元素才划算。
- [ ] **`Stream.sorted()` 是全量有状态操作**：大流会占内存，别对无限流排序。
- [ ] **稳定性影响分页**：SQL `ORDER BY` 不保证相等行稳定，分页要加唯一键兜底。

## 🧭 排查路径

- 排序抛 `IllegalArgumentException: violates contract` → Comparator 不满足传递性/对称性，用 `Integer.compare` 重写。
- 排序结果不对但"看起来有序" → 检查多字段排序是否依赖了不稳定的底层（对象排序应走 TimSort）。
- null 排序 NPE → 加 `nullsFirst/nullsLast`。
- 大数组排序慢 → 换 `parallelSort` 或考虑是否真的需要全排序（TopK 用堆）。

## 🎯 面试问题

> [!question]- Java 有哪些排序 API？底层分别是什么？
> `Arrays.sort(int[])` 双轴快排（不稳定）；`Arrays.sort(Object[])`/`Collections.sort`/`list.sort` TimSort（稳定）；`Stream.sorted` 稳定；`parallelSort` 并行归并。

> [!question]- 为什么基本类型用快排、对象用 TimSort？
> 对象需要稳定（多字段排序）+ TimSort 对有序数据友好；基本类型相等元素无身份、不需要稳定，用更快的双轴快排。

> [!question]- TimSort 是什么？
> 插入 + 归并的混合：切自然有序段（run）、短段插入排序、归并所有段。稳定，近乎有序数据接近 O(n)。

> [!question]- 多字段排序怎么做？
> `Comparator.comparing(...).thenComparing(...)` 链式，依赖底层稳定排序。

> [!question]- 手写 Comparator 的坑？
> `a-b` 溢出、违反合同抛异常、null 要 `nullsFirst/Last`。

> [!question]- TopK 用 Java 怎么写？
> `PriorityQueue` 维护大小为 K 的堆（求最大 K 用小顶堆，比堆顶大就替换），O(n log K)。见 [[06-Queue实现-ArrayDeque与PriorityQueue]]。

> [!question]- `Arrays.sort` 和 `Collections.sort` 区别？
> 一个排数组（`Arrays.sort(int[])` 双轴快排、`Arrays.sort(Object[])` TimSort），一个排集合（TimSort）。都是原地排序，集合版委托 `List.sort`。
