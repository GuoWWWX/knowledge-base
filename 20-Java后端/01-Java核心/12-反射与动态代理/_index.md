## 🧭 学习路线

1. **先读原理篇**，重点是"最小验证"那节导出 `$Proxy0` 字节码：**先看见生成的替身类，再谈原理**。看到 `extends Proxy` 那一行，"为什么只能代理接口"就不用背了。
2. **再做实战篇**，必须自己敲，不要复制。核心必做：案例 1（感受静态代理的痛，动机全在这）、2-3（核心能力 + 工厂形态）、9（无 target 的代理 = MyBatis/Feign/AiServices 真身）、11（自调用失效现场复现）。约 1.5 小时。
3. **坑位验证（案例 4-8）**每个十几分钟，目的是把原理篇"看过"的结论变成"亲眼见过"。
4. **排查篇的工具 1/2/3 在做案例时顺手用上**，不要单独学。工具 1（打印 `bean.getClass()`）是所有 AOP 问题的第一步。

## 🎯 学到什么程度

两者目标深度不同，别平均用力：

- **反射：能读、能排查，不必能写。** 业务里手写反射多半是坏味道（有 MapStruct/Jackson/BeanUtils）。需要它的场景是读框架源码、写通用工具、排查"字段为什么没注入"。API 认识即可，用时查文档。
- **动态代理：必须手写，而且不止一遍。** Spring AOP、`@Transactional`、MyBatis Mapper、Feign、LangChain4j 的 `AiServices` 是同一个套路。不手写过，这些永远是五个互不相干的黑盒；写过之后会塌缩成同一件事。

## 🧪 验证目标

- 不看资料写出 `Proxy.newProxyInstance` 三个参数，并说出每个参数错了会怎样。
- 能从 `$Proxy0` 的反编译结构推出"只能代理接口""类是 final""每次调用都装箱"，而不是背结论。
- 手写案例 9 的迷你 AiServices 并跑通，能指出它和 MyBatis Mapper 机制相同。
- 能复现案例 11 的自调用失效，并说明这与 `@Transactional` 失效是同一回事。
- 拿到"AOP 不生效"，能背出排查决策树前两步（打印真实类名 → handler 第一行埋点）。
