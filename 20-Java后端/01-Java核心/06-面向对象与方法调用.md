# 面向对象与方法调用

> [!abstract] 一句话总结
> 类把状态和行为组织在一起；重载在编译期选签名，重写让实例方法在运行期分派，参数永远按值传递，引用的副本仍能指向同一个对象。

## 🎯 本节定位

- 前置：[[05-基本类型与包装类]]。本篇补齐泛型、代理和 Record 之前的语言语义。
- 使用 JDK 21，不启用预览特性；对象布局见 JVM 章，设计取舍见 [[../11-设计模式与设计原则/_index|设计模式与设计原则]]。

## 🧩 核心概念

| 概念 | 解决的问题 | 边界 |
| --- | --- | --- |
| 封装 | 让对象自己维护不变量，如余额不能为负 | private 字段加任意 setter 不自动等于良好封装 |
| 继承 | 表达“是一种”，复用并扩展契约 | 单类继承，可实现多个接口；能组合就不必强行继承 |
| 多态 | 调用接口契约，让实现决定行为 | 实例方法重写支持动态分派；字段和 static 方法不支持同样的分派 |
| 接口 | 表达行为契约，可有 default/static/private 方法 | 接口字段隐式为 public static final，不保存每个对象的实例状态 |
| 抽象类 | 共享实例状态、构造过程和部分实现 | 不能直接实例化，继承额度只有一个 |

### 访问控制、static 与 final

- `public` 对可访问的类型公开；`private` 限制在所在顶层类的嵌套声明范围内。
- 不写访问修饰符是包可见；`protected` 允许同包访问，并允许异包子类按受保护访问规则访问，不能通过任意父类实例访问。
- `static` 成员属于类；静态方法没有 `this`，调用它不需要实例。
- `final` 类不能被继承、方法不能被重写、变量不能再次赋值；`final List` 的内容仍可能变化，见 [[17-对象语义与拷贝]]。

## ⚙️ 重载、重写与初始化

### 编译期先选重载，运行期再找重写实现

`print(Object)` 与 `print(String)` 是重载，编译器按实参的静态类型和适用性选签名，不能只凭返回类型重载。确定签名后，可重写实例方法按接收者的实际类型分派。

重写要求方法签名匹配，可返回协变的引用类型，不能缩小访问权限，不能扩大受检异常范围。`private` 方法不被继承，`static` 同名方法发生隐藏，`final` 方法禁止重写。

### 对象初始化顺序（JDK 21 普通构造器）

类首次初始化时先初始化父类，再执行本类静态字段初始化器和静态块（源码顺序）。创建对象时字段先获得默认值，再沿构造链执行父类构造过程、本类实例字段初始化器和实例块、本类构造器剩余代码。

`this(...)` 委托本类另一构造器，`super(...)` 委托父类构造器；JDK 21 中显式构造器调用须在构造器第一条语句。父类构造器中调用可重写方法，可能进入子类方法，而子类字段尚未完成显式初始化，因此应避免。

## 🔍 Java 为什么只有值传递

基本类型传的是值的副本，引用类型传的是引用值的副本。两份引用指向同一对象，所以修改对象字段对调用方可见；给形参重新赋新引用，只改了方法内的副本。

“能改对象”不能证明引用传递。真正区分点是：方法能否通过给形参重新赋值，直接替换调用方变量里的引用；Java 做不到。

## 💻 代码实践 / 🧪 最小验证

保存为 `ObjectDemo.java`，运行 `java ObjectDemo.java`。

```java
public class ObjectDemo {
    static class Parent {
        String field = "parent";
        String name() { return "parent"; }
        static String kind() { return "parent-static"; }
    }
    static class Child extends Parent {
        String field = "child";
        @Override String name() { return "child"; }
        static String kind() { return "child-static"; }
    }
    static class Box { int value; }
    static String pick(Object x) { return "Object"; }
    static String pick(String x) { return "String"; }
    static void change(Box box) {
        box.value = 7;
        box = new Box();
        box.value = 99;
    }
    public static void main(String[] args) {
        Parent p = new Child();
        System.out.println(p.name());          // child，重写
        System.out.println(p.field);           // parent，字段不动态分派
        System.out.println(Parent.kind());     // parent-static
        Object text = "hello";
        System.out.println(pick(text));        // Object，按静态类型选重载
        Box box = new Box();
        change(box);
        System.out.println(box.value);         // 7，形参重绑定不影响调用方
    }
}
```

## 🧩 枚举与内部类

### 枚举：固定实例，可带字段与行为

下面是声明片段，可放进普通类体中。每个枚举常量是单例实例，构造器不能公开；可以有字段、实现接口和覆盖方法。

```java
enum Status {
    NEW("N"), PAID("P");
    private final String code;
    Status(String code) { this.code = code; }
    String code() { return code; }
}
// Status.values() 遍历；Status.valueOf("PAID") 按名字查，未知名字抛异常。
```

比较同一枚举类型可用 `==`，它也能安全处理 null。一律不要用 `ordinal()` 作为数据库稳定编码，插入常量会改变序号；使用显式 code 并定义映射。`EnumSet`、`EnumMap` 适用于固定枚举域。

枚举常量可以带专属类体；这时枚举隐式为 sealed，否则隐式为 final，完整验证见 [[14-Java新特性-Record与密封类]]。常量上的可变字段是共享状态，不能拿来存每笔订单的失败原因。

### 嵌套类：是否依赖外部实例

| 形式 | 是否有外部实例上下文 | 常见用途 |
| --- | --- | --- |
| static 嵌套类 | 不需要外部实例 | Builder、辅助类型 |
| 非 static 成员内部类 | 与外部实例关联，通常用 `outer.new Inner()` 创建 | 依赖外部对象状态的协作对象 |
| 局部类 | 定义在方法等代码块内 | 局部命名实现 |
| 匿名类 | 创建表达式中声明无名子类 / 接口实现 | 一次性实现、泛型 TypeReference |

局部类、匿名类捕获的局部变量必须 final 或 effectively final；匿名类有自己的 `this`，Lambda 的 `this` 沿用外层上下文。需要实例化长期存活的辅助对象时，先确认是否真的需要依赖外部实例，避免意外延长其生命周期。

## ⚠️ 踩坑与注意事项

- 对父类引用做强转不会改变对象；实际类型不匹配会抛 `ClassCastException`。
- 多接口继承不意味着可以无条件继承冲突的 default 实现；无更具体实现时要显式覆盖。
- 构造器不被继承，也不是可被重写的普通方法。

## 🎯 面试问题

> [!question]- 重载和重写分别发生在什么时候？
> 重载在编译期按静态类型等规则选签名；可重写实例方法在运行期按接收者实际类型找实现。先选中哪个签名，再决定这个签名由谁实现。

> [!question]- 给方法传 List 后能 add，为什么仍叫值传递？
> 方法拿到引用值的副本，双方指向同一 List，所以 add 可见。把形参赋成另一个 List 不会替换调用方变量。

> [!question]- 接口和抽象类怎么选？枚举能不能存业务数据？
> 跨类型共享行为契约用接口；确实需要共享实例状态与构造过程时考虑抽象类。枚举可存常量对应的元数据，但每次请求的动态数据应放进独立对象。
