# 对象语义与拷贝

> [!abstract] 一句话总结
> 想复制一个对象，先决定哪些数据要独立：赋值只增加一个引用；浅拷贝创建新对象，但仍共享内部引用对象；本例的深拷贝会另外创建地址和标签列表，让这些可变数据也独立。

## 🎯 本节要学会什么

- 能自己写出普通 Java 对象的浅拷贝、深拷贝方法，而不只会背定义。
- 能复制 List、数组、Map，并判断里面的对象是否还共享。
- 前置：[[06-面向对象与方法调用]]、集合基本操作。完整实验使用 JDK 21，不依赖第三方库。
- 先做第 1～5 节；不可变对象、clone 和复杂对象图放在后面理解。

## 1. 🤔 为什么要拷贝：修改草稿时保留原资料

假设用户资料包含姓名、年龄、地址和标签。你想做一份草稿，修改草稿地址，不影响原资料。下面的字段声明是示意，完整类和构造器在第 5 节：

```java
class User {
    String name;
    int age;
    Address address;   // Address 自己也有可修改的 city 字段
    List<String> tags;
}
```

这里至少有三份需要考虑的可变数据：User 对象、Address 对象、标签 List。**创建了一个新 User，不等于它里面的 Address 和 List 也自动创建了新的。**

以下片段都复用第 5 节的 User、Address 和 original，实际对象是“小明、20 岁、杭州、[java]”。

## 2. 直接赋值：没有复制对象

```java
User alias = original;
alias.name = "小红";
System.out.println(original.name); // 小红，改的是同一个 User
System.out.println(alias == original); // true
```

original 和 alias 是两个变量，保存的引用值指向同一个对象。这一步没有调用构造器，也没有创建新 User。

## 3. 浅拷贝怎么写：new 外层对象，逐字段赋值

本例采用普通构造器，不需要 implements Cloneable，也不需要特殊注解：

```java
User shallow = new User(
        original.name,
        original.age,
        original.address,
        original.tags);
```

这段代码已经完成了本例的浅拷贝：

| 字段 | 复制后发生什么 |
| --- | --- |
| age（int） | 复制数值，两份 age 独立 |
| name（String） | 复制引用；String 不可变，给 shallow.name 重新赋值不影响 original.name |
| address（Address） | 复制引用，双方仍指向同一个可变地址对象 |
| tags（List） | 复制引用，双方仍指向同一个可变列表 |

所以这两种修改产生不同结果，分别从新建的原资料开始观察：

```java
shallow.name = "小红";          // 改新 User 的 name 字段，原资料姓名仍是小明
shallow.address.city = "上海"; // 改共享 Address 的字段，原资料地址也变成上海
shallow.tags.add("vip");      // 改共享列表，原资料标签也增加 vip
```

“浅”指没有继续复制引用字段所指向的对象。它不是“只能复制一部分字段”，而是字段值复制完后，对内部对象仍共享。

## 4. 深拷贝怎么写：把本例内部可变数据也 new 出来

目标是让草稿的地址、标签都能独立修改。对应写法是：

```java
User deep = new User(
        original.name,
        original.age,
        new Address(original.address.city),
        new ArrayList<>(original.tags));
```

逐项看：

- new User：新的用户外层对象。
- new Address：新的地址对象；city 是不可变 String，可以安全共享其值的引用。
- new ArrayList：新的标签列表；元素是不可变 String，因此这个例子不需要再复制标签元素。
- name 是不可变 String，不需要写 new String 来制造一个相同内容的字符串。

这已经复制了本例所有需要独立修改的可变数据。于是：

```java
deep.address.city = "北京";
deep.tags.add("copy-only");
// 原资料的地址和标签不跟着变化。
```

这两个方法名是我们自己取的，不是 JDK 自带的 API。可以把上面的构造过程封装成 shallowCopy(original) 和 deepCopy(original)，具体实现如下。

## 5. 💻 完整实验：真正实现并验证两种拷贝

保存为 `CopyDemo.java`，运行 `java CopyDemo.java`。为突出复制过程，演示类直接访问字段；约定 address、tags 非 null，标签元素都是 String，无循环引用。真实业务允许缺字段时，在相应复制位置明确处理 null。

```java
import java.util.ArrayList;
import java.util.List;

public class CopyDemo {
    static class Address {
        String city;
        Address(String city) { this.city = city; }
    }
    static class User {
        String name;
        int age;
        Address address;
        List<String> tags;
        User(String name, int age, Address address, List<String> tags) {
            this.name = name;
            this.age = age;
            this.address = address;
            this.tags = tags;
        }
    }
    static User sample() {
        return new User("小明", 20, new Address("杭州"),
                new ArrayList<>(List.of("java")));
    }
    static User shallowCopy(User source) {
        return new User(source.name, source.age, source.address, source.tags);
    }
    static User deepCopy(User source) {
        return new User(source.name, source.age,
                new Address(source.address.city), new ArrayList<>(source.tags));
    }
    public static void main(String[] args) {
        User original = sample();
        User alias = original;
        User shallow = shallowCopy(original);
        System.out.println(alias == original);                 // true
        System.out.println(shallow == original);               // false
        System.out.println(shallow.address == original.address); // true
        System.out.println(shallow.tags == original.tags);     // true

        shallow.name = "小红";
        shallow.age = 21;
        System.out.println(original.name + " " + original.age); // 小明 20
        shallow.address.city = "上海";
        shallow.tags.add("vip");
        System.out.println(original.address.city);             // 上海
        System.out.println(original.tags);                     // [java, vip]

        // 此时原资料已是上海、[java, vip]，以它为基础做深拷贝。
        User deep = deepCopy(original);
        System.out.println(deep.address == original.address);  // false
        System.out.println(deep.tags == original.tags);         // false
        deep.address.city = "北京";
        deep.tags.add("copy-only");
        System.out.println(original.address.city);             // 仍是 上海
        System.out.println(original.tags);                     // 仍是 [java, vip]
    }
}
```

这次验证同时检查了“是不是同一个对象”和“修改后原数据变不变”。只打印 toString 或只比较外层 User 是否相同，无法证明内部数据已经独立。

最小练习：把 deepCopy 中的 new Address(...) 改成 source.address，运行后原资料会变成北京；再改回去，观察恢复独立。这比只背“深拷贝会递归复制”更容易理解。

## 6. 🧰 集合、数组、Map 怎么复制

以下片段复用第 5 节的 User、sample、deepCopy，需要 `java.util.*`。片段分开运行，避免前一个实验的修改干扰后一个。

### List：复制容器，还是连每个 User 一起复制

```java
List<User> users = new ArrayList<>(List.of(sample()));
List<User> shallowList = new ArrayList<>(users); // 新列表，但里面的 User 仍共享

List<User> deepList = new ArrayList<>();
for (User user : users) {
    deepList.add(deepCopy(user)); // 每个 User 及其内部可变字段也复制
}
```

对 shallowList add/remove 不改变 users 的结构；但 `shallowList.get(0).address.city = "北京"` 会改到原用户。deepList 的对应修改不会影响 users。

### 数组：基本类型元素与对象元素不同

```java
int[] numbers = {1, 2};
int[] copiedNumbers = numbers.clone();
copiedNumbers[0] = 99; // numbers[0] 仍是 1

User[] users = {sample()};
User[] shallowArray = users.clone(); // 新数组，User 仍共享
User[] deepArray = new User[users.length];
for (int i = 0; i < users.length; i++) {
    deepArray[i] = deepCopy(users[i]);
}
```

int 的元素值复制后已经独立；User[] 复制的是引用，需要继续复制 User。`Arrays.copyOf` 也不自动深拷贝引用元素。

### Map：先复制容器，再按需要复制 value

```java
Map<String, User> source = new HashMap<>();
source.put("u1", sample());
Map<String, User> shallowMap = new HashMap<>(source); // value 仍共享
Map<String, User> deepMap = new HashMap<>();
for (Map.Entry<String, User> entry : source.entrySet()) {
    deepMap.put(entry.getKey(), deepCopy(entry.getValue()));
}
```

本例 key 是不可变 String，可以共享；如果 key 本身是可变对象，还要单独决定 key 的复制与相等性规则。

## 7. 📝 如果只是复制部分对象数据

不一定要复制完整 User。例如接口只返回姓名与城市，可以明确选字段建立一个新的结果，而不复制年龄和所有标签：

```java
// 复用第 5 节的 original，需要导入 java.util.Map。
Map<String, String> view = Map.of(
        "name", original.name,
        "city", original.address.city);
```

这叫按需要做数据映射。本例结果只包含不可变字符串值，之后修改 original.address.city 是给原地址字段重新赋值，不会把 view 中保存的旧城市字符串一起改掉。正式接口也可以定义自己的 DTO 类，按构造器或 setter 逐字段赋值。

## 8. 🔍 后续再理解的边界

### clone 并不自动完成深拷贝

Object.clone 的默认行为是字段级浅拷贝。自定义类通常需要实现 Cloneable，并公开合适的 clone 方法；还要自己继续复制内部可变对象，才能满足深拷贝要求。Cloneable 只是标记接口，不会自动给你的类生成可调用的公开 clone 方法。初学时先掌握本篇的显式构造器复制，过程最直观。

复制构造器 `new User(oldUser)` 也一样：究竟浅还是深，取决于构造器内部如何赋值，不能仅凭方法名判断。

### List.copyOf 与不可修改视图

- `Collections.unmodifiableList(source)` 是不可修改视图，source 之后的结构修改仍可见。
- `List.copyOf(source)` 的结果不跟随源列表后续结构变化，不允许 null，但仍可能共享可变元素。
- final List 和 Record 的 final 组件字段限制引用重新赋值，不自动限制元素变化。

### 不是所有业务对象都能照着同一个方法复制

本例是简单对象树。循环引用、多个字段共享同一地址身份、数据库连接、线程等情况需要明确策略，不能机械地不停 new。若需要保留对象图的共享关系，通常还需要已复制对象的映射；本篇不实现通用对象图复制器。

JSON 转换也不能当作无条件可靠的通用深拷贝：字段可见性、类型、日期、共享引用和库配置会影响结果，见 [[18-序列化与反序列化]]。

Object 默认 equals 比对象身份；数组内容比较用 Arrays.equals/deepEquals，相等性契约详见 [[04-集合框架/01-核心机制与选型]]。判断引用是否共享时，本篇直接使用 ==，不拿 hashCode 当内存地址。

## 🎯 自测与面试问题

> [!question]- b = a、new User(...)、new ArrayList<>(users) 分别创建了什么？
> b = a 不创建对象；new User 创建新的外层 User，内部引用是否复制取决于实参；new ArrayList 创建列表容器，元素引用仍可能共享。

> [!question]- 如何用代码让 User 的地址和标签能独立修改？
> 创建新的 User，给 address 传 new Address(old.address.city)，给 tags 传 new ArrayList<>(old.tags)。本例 String 标签不可变；换成可变标签对象时，还需要逐个复制标签。

> [!question]- 验证深拷贝，只看 copy != original 够吗？
> 不够。还要检查内部可变对象是否独立，实际修改副本的地址和集合，确认原数据不跟着变化。

> [!question]- String 字段也必须 new String 才算深拷贝吗？
> 不需要。不可变值可以共享，目标是让业务需要独立修改的可变数据不再互相影响，而不是制造所有对象的新实例。

- 不看示例，能写出本例 shallowCopy 和 deepCopy。
- 能分别验证姓名重新赋值、地址字段修改、标签增删对原对象的影响。
- 能复制 List<User>、User[]、Map<String, User>，并说明只复制容器和逐个复制元素的区别。
- 能按需要选择复制完整对象，或只取字段建立 DTO / 结果 Map。
