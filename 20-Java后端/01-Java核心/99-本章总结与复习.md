> [!abstract] 一句话总结
> 先理解值、对象和调用，再用泛型与集合组织数据，用数值、时间和空值契约定义业务语义，通过 Stream 和 IO 处理数据，最后理解反射、注解、模块封装与现代建模；每一步都要能说明失败边界并写出验证。

## 全章主线与学习因果链

1. **语言语义 → 对象契约与泛型**：先区分值、引用、重载重写，再讨论类型参数和值相等。
2. **集合 → 拷贝 → 业务值**：容器依赖元素契约，复制容器不自动复制元素；金额精度和时间含义在存储与传输前明确。
3. **异常与空值 → 数据处理**：无结果和操作失败分开；用 Optional 和 Stream 组合转换，明确合并与并行边界。
4. **IO → 序列化与文本**：先确认字节、字符集与资源，再讨论对象协议和正则；格式正确不代表业务有效。
5. **反射与注解 → 模块 → 现代建模**：理解框架如何调用，再看封装如何限制访问；Record、sealed 建立在对象语义之上。
6. **线程使用 → JVM 与并发深入**：本章掌握创建、等待与下游限流，后续深入调度、JMM、锁与压测。

完整路线与学习进度见 [[_index]]，保留文件编号用于定位。当前优先动手做对象拷贝、正则和 JSON 转换；Java 原生序列化与 JPMS 模块机制作为后续按需深入内容。

## 快速复习：先记边界，再记源码

- **算术与对象**：运算前提升类型；final 限制赋值，不限制引用对象内部变化；参数永远按值传递。
- **字符串**：`"😀".length()` 为 2、码点数为 1、UTF-8 字节数为 4；不要统称字符数。
- **泛型与资源**：PECS 限定安全读写类型；异常保留 cause，关闭异常与主异常分开。
- **集合**：fail-fast 不是并发安全；哈希相等不推出对象相等；比较器返回 0 会影响 TreeSet 去重。
- **数值与时间**：BigDecimal.equals 和 compareTo 不等价；逐行舍入和汇总舍入可能不同；本地时间没有时区，日历一天未必是 24 小时。
- **Stream 与复制**：toList 不可修改，Collectors.toList 不承诺可修改；copyOf 不跟随源容器结构变化，但不深拷贝元素。
- **运行期边界**：setAccessible 不是无条件放行；代理自调用会绕过代理；enum 是否 sealed 取决于常量专属类体。

## 🧠 自测与面试问题（先答再展开）

> [!question]- int 乘法为何赋给 long 仍可能错误？null Integer 与 int 比较会怎样？
> 乘法先按表达式类型执行，溢出后再扩宽无效；比较时拆箱 null 会 NPE。分别在运算前提升、拆箱前明确缺值策略。

> [!question]- 重载、重写与值传递分别解释什么？
> 重载解释编译期选签名，重写解释实例方法的运行期分派，值传递解释形参得到值或引用值的副本。修改同一对象可见，形参重绑定不会替换调用者变量。

> [!question]- PECS 的读写边界是什么？TypeReference 为什么能读取泛型？
> extends 可按上界读，不能安全添加任意非 null 的上界值；super 可写指定类型，读取只保证 Object。TypeReference 利用匿名子类父类签名的元数据，不是恢复任意对象被擦除的信息。

> [!question]- 主流程和 close 都失败时应该保留谁？
> try-with-resources 保留主流程异常，关闭异常进入 suppressed；资源按声明逆序关闭。异常转换还要保留 cause。

> [!question]- 为什么一个 emoji 的 length 可以是 2？
> length 数 UTF-16 代码单元，补充字符使用代理项对；码点和编码字节数分别计算，组合字形还可能有多个码点。

> [!question]- HashSet 去重、HashMap 扩容和 TreeSet 排序分别依赖什么？
> HashSet 借助 Map 使用哈希与 equals；JDK 8 HashMap 扩容用 oldCap 对应的 hash 位拆分；TreeSet 的比较结果同时决定顺序与去重。

> [!question]- List、Map、Queue 如何选型？源码至少要解释什么？
> 常见默认是 ArrayList、HashMap、ArrayDeque；有序键用 TreeMap，访问序用 LinkedHashMap，优先级用 PriorityQueue。能解释数组扩容、哈希拆链、双向链表与堆上浮下沉。

> [!question]- 1.0 与 1.00 为什么在两种 Set 中数量可能不同？
> BigDecimal.equals 区分 scale，compareTo 不区分；HashSet 和自然顺序 TreeSet 的等价规则不同。金额 key 必须先定义规范化规则。

> [!question]- 如何测试今天到期，又如何排查时间差 8 小时？
> 注入固定 Clock 与业务时区；排查输入偏移、解析时区、数据库映射和展示时区。日历一天不一定是 24 小时，时间戳还须区分秒和毫秒。

> [!question]- orElse 为什么可能多查询一次？map 和 flatMap 怎么选？
> 方法调用前先求实参，orElse 的备用查询已经执行；orElseGet 才延迟。普通转换用 map，返回 Optional 的转换用 flatMap。

> [!question]- Stream 重复键与可变列表如何明确表达？
> toMap 提供合并函数，若需要顺序再提供 Map 工厂；可变列表用 toCollection(ArrayList::new)，不依赖 Collectors.toList 的当前实现。

> [!question]- 复制列表后为什么修改元素仍影响原列表？
> 只复制容器槽位，仍共享元素引用。手写 List<User> 深拷贝时创建新列表，遍历每个 User，再创建新 User、内部地址与需要独立的列表；不可变 String 可以共享。具体边界由业务字段决定。

> [!question]- Files.list 为什么需要关闭？flip 和 compact 有何区别？
> Files.list 的 Stream 持有目录资源；flip 将写入区域转成可读区间，compact 保留未读数据并准备继续写。

> [!question]- 对象与 JSON 互转怎么写？为什么不要求 implements Serializable？
> Jackson 的 writeValueAsString 输入对象、返回 JSON 字符串；readValue 输入数据和 User.class 等目标类型、返回对象。Serializable 是原生对象流的标记，JSON 使用映射库自己的规则。

> [!question]- 选读：transient、UID 和 JSON 分别属于什么规则？
> 前两者属于 Java 原生序列化相关机制；JSON 字段排除由映射库决定。普通 Serializable 类不执行自己的常规构造器，Record 有专门恢复规则；UID 相同不保证任意变更兼容。

> [!question]- find 与 matches 有何区别？动态替换文本如何转义？
> matches 返回整串格式是否合格；find 找下一段局部匹配，成功后 group 取完整内容、group(1) 取第一个捕获组。动态模式字面量用 Pattern.quote，动态替换字面量用 Matcher.quoteReplacement。

> [!question]- 注解、反射与代理各负责什么？为什么自调用可能使增强失效？
> 注解保存元数据，反射可在运行期读取，代理在调用路径加入增强；this 调用不经过代理，因而绕开拦截器。编译期注解处理无需依赖运行期反射。

> [!question]- exports 与 opens 有何区别？setAccessible 可以越过一切封装吗？
> exports 控制普通包访问，opens 控制深反射；跨模块仍需开放关系，setAccessible 可能抛 InaccessibleObjectException。

> [!question]- Record 是深不可变吗？enum 的 isSealed 一定是 false 吗？
> Record 不自动深拷贝可变组件；enum 有常量专属类体时隐式 sealed，没有时隐式 final。必须看实际声明。

> [!question]- 为什么虚拟线程仍要限制下游并发？pinning 为什么要标版本？
> 线程便宜不代表连接和下游无限；可用信号量等限制并发。JDK 21 synchronized 阻塞可能 pin carrier，JDK 24 的 JEP 491 改变了该行为，其他 native 场景需另论。
