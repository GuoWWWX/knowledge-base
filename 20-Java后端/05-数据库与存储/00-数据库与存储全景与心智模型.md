# 🗄️ 00 · 数据库与存储全景与心智模型（国家档案馆与闪存便签纸）

> **一句话导读**：业务代码写得再天花乱坠，只要数据库扛不住，整个系统瞬间归零。掌握关系型数据库（MySQL）与分布式内存缓存（Redis）的“动静结合之道”，你就守住了整个系统性能与数据安全的命脉。

---

## 🏛️ 核心心智模型：国家档案馆与桌面便签纸

任何互联网系统的本质，剥离到最底层其实就两个动作：**算力（CPU）与记忆（存储）**。

在海量请求的洪峰面前，计算机硬件的物理规律决定了没有任何一种单一存储介质能同时满足“无限容量、绝对安全落盘、纳秒级读取”：

```mermaid
flowchart TD
    subgraph Pyramid["计算机存储金字塔（速度越快越贵，越慢容量越大）"]
        L1["1. CPU 寄存器与 L1/L2/L3 缓存 (纳秒级，极小)"]
        L2["2. 内存 RAM (如 Redis，纳秒到微秒级，断电丢失需特殊持久化)"]
        L3["3. 固态/机械硬盘 SSD/HDD (如 MySQL，毫秒级，安全落盘容纳海量)"]
    end
```

为了兼顾**性能**与**安全**，现代系统演化出了经典的**“冷热分离、双剑合璧”**架构：

```mermaid
flowchart LR
    Client["📱 用户请求"] --> Redis["⚡ 桌面即贴便签：Redis 内存缓存<br/>- 极速响应 (微秒级)<br/>- 扛住 90% 的高频热点读取<br/>- 支撑高并发计数与分布式锁"]
    
    Redis -.->|"缓存未命中 / 真正写落盘"| MySQL["🏛️ 国家地下档案库：MySQL 关系数据库<br/>- 绝对安全 (ACID 事务，落盘不丢)<br/>- 复杂关系查询 (JOIN, 聚合)<br/>- 最终唯一真理源 (Single Source of Truth)"]
```

| 角色 | 现实生活比喻 | 核心使命 | 牺牲了什么？ |
| :--- | :--- | :--- | :--- |
| **MySQL** | **国家防空洞绝密档案馆** | **保底与求真**。以 ACID 强事务为后盾，确保每一笔转账、每一个订单绝对安全、永不丢失、关系严谨。 | 牺牲了单机极限吞吐量（单机写通常在几千 TPS）。 |
| **Redis** | **手边桌面的彩色即贴便签** | **极速与冲锋**。纯内存操作，单机可轻松扛住 10 万+ QPS，专为应对瞬时流量洪峰。 | 牺牲了部分复杂关系查询能力与内存成本。 |
