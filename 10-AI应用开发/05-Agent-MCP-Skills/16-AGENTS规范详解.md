# 📄 AGENTS.md 规范详解

> [!abstract] 一句话总结
> `AGENTS.md` 是给支持它的编程 Agent 阅读的项目指引，可记录项目结构、构建测试命令、代码约定和修改边界。

## 📌 为什么需要 AGENTS.md

假设周报助手是一个 Java 项目，团队约定 Controller 只处理请求，业务逻辑放在 Service，提交前运行 `mvn test`。如果每次让编程 Agent 改代码都要重复这些要求，既费事，也容易遗漏。把约定写进项目的 `AGENTS.md` 后，支持该文件的 Agent 就可以在处理项目任务时读取。
`AGENTS.md` 是普通 Markdown，不需要固定字段；写入的命令应符合项目实际环境。如果项目改用 Gradle，或测试命令发生变化，指引也应同步更新。

## 🧩 一份项目指引长什么样

下面假设项目使用 Maven，且已有 `controller`、`service` 分层：

```markdown
# 项目约定

## 结构与编码

- controller 只处理请求和参数校验。
- 业务逻辑放在 service，不在 controller 直接写 SQL。
- 使用 SLF4J 记录日志，不要输出密钥。

## 验证

- 在项目根目录执行 mvn test。

## 修改边界

- 不修改 src/main/resources/legacy/ 下的历史文件。
- 涉及数据库 schema 调整时先按团队流程评审。
```

这份文件告诉 Agent “在这个项目工作要遵守什么”，不是程序配置，也不是自动执行的测试脚本。示例只展示写法；实际项目需要根据构建工具、模块和团队规则调整。

## 📂 放在哪里，谁会读取

通常可以在仓库根目录放一份通用约定；多模块项目也可以在子目录增加局部约定，例如：

```text
weekly-report-service/
├── AGENTS.md              # 项目通用约定
├── pom.xml
└── report/
    ├── AGENTS.md          # 报表模块的补充约定
    └── src/
```

一些支持嵌套指引的宿主会同时考虑根目录和子目录文件，遇到冲突时参考更靠近目标文件的约定。但**查找路径、加载时机和冲突处理由具体宿主决定**，不能假定所有编程工具都自动读取 `AGENTS.md`，也不能假定所有工具只读取离文件最近的一份。
把文件提交到项目版本库，团队成员才能共享；修改项目结构或命令后也要同步维护。文件中的指引不会扩大宿主沙箱和用户已经授予的权限，更不能覆盖更高优先级的系统规则。

## 🆚 和 README、SKILL.md 有什么区别

| 文件 | 主要回答的问题 | 周报项目中的例子 |
| ---- | -------------- | ---------------- |
| `README.md` | 这个项目是什么，怎样安装和使用？ | 介绍周报服务、依赖和启动方法 |
| `AGENTS.md` | 在这个项目修改代码要遵循什么约定？ | 说明分层、测试命令和修改边界 |
| `SKILL.md` | 遇到某类任务时按什么步骤做？ | 指导如何根据记录生成周报草稿 |

`README.md` 主要面向开发者，但 Agent 也可以读；`AGENTS.md` 也可以由人维护。Skill 是否可用取决于当前宿主是否支持以及放置位置，`AGENTS.md` 不会因为引用了一个 Skill 就自动安装它。Skill 的目录结构和加载过程见 [[13-Skills详解]]。

## 🧪 怎么验证指引是否生效

1. 查看所用编程工具的文档，确认它支持 `AGENTS.md`，以及当前项目使用的发现路径。
2. 在根目录写入符合项目实际情况的指引，给 Agent 一个小范围修改任务，例如调整周报 Service 的字段校验。
3. 检查它是否遵循目录与编码约定、是否运行相关验证；如宿主提供读取记录或日志，也检查是否发现了该文件。
4. 用一个明确的项目约定做正反检查，发现未生效时先排查路径和宿主配置，再检查指令是否具体、是否存在冲突。

例如 Agent 把业务规则加在 Service，并运行了 `mvn test`，只能说明本次行为符合约定；若没有读取记录，不能据此断定它一定读过该文件。上面的 Maven 项目和检查步骤是示例，本文未在实际项目中执行。

## ⚠️ 编写时注意

- 优先写当前项目真正需要的命令、目录边界和代码约定，避免照搬其他项目。
- 命令应说明执行位置和前提；不要在文件中放密钥或生产环境凭据。
- 子目录规则保持明确，定期检查与根目录规则是否冲突。
- 对外部项目中的指引保持审查，尤其注意其中要求执行的命令。

## 🎯 自测

> [!question]- `AGENTS.md` 和 `SKILL.md` 的区别是什么？
> 前者提供项目工作的约定，后者封装某类任务的流程和资源。二者的发现、作用范围和优先级都由宿主决定。

> [!question]- 仓库放了 `AGENTS.md`，所有 AI 编程工具都会自动读取吗？
> 不一定。要确认当前工具是否支持、查找哪些目录以及是否启用相关配置。

> [!question]- 里面写了允许访问数据库，就一定能访问吗？
> 不能。文档只是指引，实际访问仍受宿主、运行环境、业务系统和用户授权约束。
