# LLM 与 Prompt 工程全景与心智模型

> [!abstract] 一句话心智模型
> 如果把大语言模型（LLM）比作一位**博览群书但没有长期实体记忆的“超级速记秘书”**：
> - **底层本质（Next Token Predictor）**：他本质上在玩一场极度高超的**“文字接龙游戏”**。他没有真正的主观意识，而是根据你给的上下文线索，在几万个词表里计算“下一个最合理的字词概率”；
> - **三阶段人生履历**：
>   1. **海量通读（预训练 Pre-training）**：读遍全网数万亿文本，学会了语言语法和人类世界常识（拥有了深厚知识底模）；
>   2. **职场集训（指令微调 SFT）**：经过数十万道标准“Q&A 问答题”训练，学会了听懂人类指令，不再随意胡乱发散；
>   3. **价值观对齐（人类反馈强化学习 RLHF / DPO）**：树立安全与道德底线，学会友善、严谨、拒绝输出有害违规内容；
> - **Prompt 工程（指挥官的精准简报）**：给秘书下达任务时，不要指望他能读心。你的指令（System Prompt）、提供的范例（Few-shot）、推理引导（CoT 一步步思考）以及输出约束（JSON 结构化），就是他在有限工作台（上下文窗口）上交付完美答卷的唯一依据！

## 🎯 一、LLM 运行的第一性原理流转链

在工程师眼中，一次大模型 API 调用绝不是神奇的魔法，而是一条精密无比的数学流水线：

```mermaid
flowchart LR
    TextIn["用户 Prompt 文本\n'天空是蓝色的，因为'"] --> Tok["1. Tokenizer 编码\n切分为 Token ID 数组: [1203, 334, 581]"]
    Tok --> Emb["2. 词嵌入 (Embedding)\n查表映射为高维稠密向量 (如 4096 维)"]
    Emb --> TF["3. Transformer 堆叠层\n自注意力机制 (Self-Attention) 捕捉词间依赖关系"]
    TF --> Logits["4. 概率计算 (Logits & Softmax)\n在 100,000 个词表上计算下一个 Token 的概率分布"]
    Logits --> Sample["5. 采样器 (Temperature / Top-P)\n根据随机度参数挑选出中奖 Token: '光'"]
    Sample --> Check{"6. 遇到停止符 <EOS> 或达最大长度?"}
    Check -- "否" --> Loop["将新词拼入上下文，继续循环生成!"] --> TF
    Check -- "是" --> TextOut["7. Detokenizer 解码还原为自然文本输出"]
```

### 必须牢记的工程师铁律：
1. **模型看不懂汉字或英文字母**：它只认数字 ID（Token ID）；
2. **生成是自回归单向流动的（Auto-regressive）**：模型每输出一个 Token，就要把这个新 Token 塞进上下文末尾，重新经历一次 Transformer 计算来预测下一个，直到撞上停止符。这就是为什么大模型 API 是**流式打字机（Streaming SSE）**输出的根本原因！

## 🗺️ LLM 核心概念全景对照表

| 核心术语 | 形象化比喻 | 工程师需要关心的物理本质 | 核心控制参数 / 影响 |
| :--- | :--- | :--- | :--- |
| **Token** | 模型的“汉字部首 / 英文词根” | 模型处理语言的最小信息单元。100 个汉字约等于 120~160 个 Token；100 个英文单词约等于 130 个 Token。 | 计费计量单位；上下文窗口占用的基础单位。 |
| **Embedding** | 语义多维空间坐标 | 把离散的文字转换为 1536/4096 维的数学向量。语义相似的词在多维空间中距离越近（余弦相似度高）。 | RAG 知识库检索、向量数据库的检索基石。 |
| **Attention** | 人眼聚光灯与人脉关系网 | 计算输入句子中每一个词与周围所有其他词之间的关联权重（$Q, K, V$ 矩阵点积计算）。 | 解决代词指代（“它”是谁）、长距离语义依赖。 |
| **Temperature** | 想象力开关 / 酒精浓度 | 控制 Softmax 概率分布的平滑度。设为 0 时永远挑概率第一的词（最严谨）；调大时给低概率词上场机会（更有创意）。 | 代码/结构化输出设 `0.0~0.2`；文案写作设 `0.7~0.9`。 |
| **Top-P (核采样)** | 候选词及格线圈定 | 只在累积概率达到 $P$（如 0.9）的前几个最靠谱候选词中抽签，直接剔除掉尾部胡说八道的离谱词。 | 通常与 Temperature 二选一调整，生产推荐 `0.9`。 |
| **Context Window** | 秘书桌面的大小（工作台） | 模型单次交互能容纳的“历史输入 + 输出”的最大 Token 上限（如 128K、1M）。 | 超过窗口会发生遗忘或报错；窗口过大存在“大海捞针”迷失问题。 |
| **Prompt Caching** | 秘书桌上的常备备忘录 | 对前面重复度高的静态前缀（如系统提示词、长知识库背景）进行 KV Cache 缓存复用。 | 延迟下降 80%，成本立省 50%~90% 的企业降本神技！ |
