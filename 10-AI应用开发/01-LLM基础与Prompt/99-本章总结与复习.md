## ⚡ 大厂面试 30 秒绝杀 10 连问

> [!important] 高频核心问题直击要害
>
> 1. **为什么中文有时比英文消耗更多的 Token？**
>    - 答：早期的 BPE 词表以英文语料为主，中文单字可能被拆为 2~3 个字节 Token；现代主流多语言大模型（如 Qwen、DeepSeek）扩充了中文词表，中文压缩比已大幅优化至 0.6~0.8 字符/Token。
>
> 2. **为什么大模型数不清 "strawberry" 里的 'r'？**
>    - 答：Tokenizer 将 "strawberry" 作为一个整体或两个子词切分，大模型在注意力层看到的是抽象的数字 ID，看不见底层的拼写字母；只有通过强制逐字母切分或开启 CoT 逐步拼读才能答对。
>
> 3. **Temperature 为 0 和 Top-P 为 0 有什么区别？**
>    - 答：`temperature=0` 会使 Softmax 极端陡峭，退化为确定性的贪心采样（Greedy Search，每次只挑概率绝对第一的 Token）；Top-P 是累积概率核采样，通常先固定一个再调另一个。
>
> 4. **什么是 Lost in the Middle（迷失在中间）？如何工程应对？**
>    - 答：Transformer 的长上下文注意力往往对最前端（System）和最末端（用户最新输入）最敏感，处于正中间的信息注意力权重会显著衰减。工程上需将核心规则与关键证据放置在首尾两端。
>
> 5. **CoT（思维链）为什么能提升复杂推理能力？**
>    - 答：Transformer 每一层的计算是固定深度的 $O(1)$ 运算，无法在单步前向中容纳深层逻辑；CoT 将中间推导作为显式 Token 吐入上下文（KV Cache），相当于把思考过程变成了可反复注意力的显式工作内存。
>
> 6. **JSON Mode 和 Structured Outputs 有何本质不同？**
>    - 答：JSON Mode 仅保证输出外层语法是合法 JSON，但不保证字段名和类型匹配；Structured Outputs 基于语法引导生成（Constrained Decoding），在生成每一步用 DFA 状态机进行 Logit Masking，100% 符合 JSON Schema 契约。
>
> 7. **什么是间接提示注入（Indirect Prompt Injection）？**
>    - 答：攻击者将恶意控制指令隐匿在外部网页、文档、邮件或简历中，当大模型为正常用户检索并处理该内容时被恶意指令“夺舍”，操纵 Agent 越权调用高危工具。
>
> 8. **为什么说 System Prompt 不能作为系统最终安全边界？**
>    - 答：因为自然语言没有传统操作系统的内存隔离和机器代码边界，指令与数据在同一个上下文矩阵中混淆；安全边界必须建立在确定性的代码沙箱、RBAC 鉴权与人机协同门禁之上。
>
> 9. **Prompt Caching 的核心触发条件是什么？**
>    - 答：严格的**前缀字节完全匹配**。请求中从位置 0 开始的 Tools、System Prompt 必须一字不差（连空格和换行都不能变），任何动态时间戳或 UUID 必须移至消息末尾。
>
> 10. **推理模型（如 DeepSeek-R1、o1）的思考 Token 是如何计费的？**
>     - 答：思考 Token 全额按照模型输出（Output）费率计费，且与用户可见的最终回答共享 `max_tokens` 总额度，在工程调用时必须留足输出预算，避免思考阶段用尽额度导致答案被截断。

## 🚨 生产落地十诫（Architectural Commandments）

1. **一戒混淆字符与 Token**：估算成本、限流排队与截断长度必须使用对应模型的专用 Tokenizer（如 `jtokkit`），严禁使用 `String.length()` 粗暴计算。
2. **二戒无预留 max_tokens**：调用接口必须显式指定 `max_tokens`，且留出至少 1K~4K 的回答余量，防思考或推理爆仓。
3. **三戒在 System Prompt 插动态时间**：动态时间戳会彻底毁掉 Prompt Caching，导致每次请求全额冷启动计费；易变信息必须放在 user 消息末尾。
4. **四戒让模型自由发挥吐 JSON**：严禁仅用提示词祈祷“请输出 JSON”，必须开启强契约 Structured Outputs，并配套后端 Jackson 反序列化容错。
5. **五戒简单分类盲目上 CoT**：意图识别、简单抽取等知觉任务加 CoT 只会白白增加几百毫秒延迟和数倍 API 账单。
6. **六戒自然语言防注入**：不要幻想通过写狠话恐吓模型来防止越狱，代码鉴权和参数白名单才是唯一真理。
7. **七戒高危工具全自动执行**：删库、转账、外发邮件等不可逆破坏性工具，必须引入 Human-in-the-Loop 真人二次点击确认。
8. **八戒全量历史无脑堆叠**：会话长轮次必须实施滑动窗口（Sliding Window）或基于 Token 预算的语义摘要压缩。
9. **九戒忽略 Lost in the Middle**：多文档 RAG 场景中，最相关的核心证据必须排序置于 Prompt 的最前或最后。
10. **十戒单模型打天下**：建立分层路由架构，日常查询与意图分发使用轻量小模型（Flash），复杂多步推理与代码生成路由至大模型（Pro/Reasoning）。
