## 📝 快速复习

- `uv` 管 Python 环境、依赖和运行命令；`pnpm` 管 Node 项目的依赖与脚本。
- `asyncio` 适合并发等待模型、检索和工具等 I/O，不适合直接承担重 CPU 计算。
- FastAPI 用路由和 Pydantic 快速暴露 AI 服务；Next.js App Router 可同时承载页面与 Route Handler。
- Vercel AI SDK 中，`generateText` 处理一次性生成，`streamText` 处理流式生成，`useChat` 管理前端聊天交互。
- LangChain Python / JS 偏通用 LLM 编排；Mastra 偏 TypeScript Agent 与 Workflow 工程化。
- Java 适合稳定企业后端，TypeScript 适合 AI 全栈与流式 UI，Python 适合快速接入 AI 生态；选型应服从项目目标。

## ❓ 自测问题

> [!question]- 如何分别用 `uv` 和 `pnpm` 跑起已有项目？
> 先看 README 和锁文件。Python 项目按要求使用 `uv sync --locked`；Node 项目依据 `package.json` 安装依赖并运行已有脚本。

> [!question]- `async / await` 为什么适合并发等待 I/O？
> 等待未完成的 I/O 时，事件循环可以调度其他协程；CPU 密集计算或同步阻塞调用不会因此自动变快。

> [!question]- Pydantic 模型与 Java DTO、Validation 有什么对应关系？
> Pydantic 声明数据字段并进行运行时解析与校验，功能上类似 DTO 加参数校验；Python 类型注解本身不会自动验证。

> [!question]- Route Handler、`streamText` 和 `useChat` 怎样配合？
> 服务端 Route Handler 调用 `streamText` 并返回兼容的流，前端 `useChat` 发送消息和维护流式状态；具体 API 取决于 SDK 版本。

> [!question]- 怎么选择 LangChain.js、Mastra 和 Java 后端？
> 先看团队技术栈和任务复杂度：LangChain.js 提供模型与检索编排，Mastra 偏 Agent 和 Workflow，Java 后端适合与已有业务、权限和审计体系整合。

> [!question]- 怎样检查 AI 编程助手的修改是否完成？
> 查看变更与需求是否一致，运行适当的测试或验证命令，检查失败和未验证的边界，再汇报结果。
