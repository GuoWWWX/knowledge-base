# 火山方舟

> [!abstract] 一句话总结
> 火山方舟是火山引擎的大模型服务平台，常用于接入豆包等模型、模型推理、知识库/应用构建和企业级 API 调用；工程上重点掌握 endpoint、OpenAI 兼容接口、鉴权、限流和成本监控。

## 📌 定位

火山方舟适合已经使用火山引擎、需要豆包模型、国内云服务、内容安全和企业部署管理的团队。它既能作为模型 API 供应商接入业务，也能作为上层平台做模型体验、应用构建和知识库能力。
和阿里百炼的差异主要体现在云生态、模型族、价格、区域、内容安全策略和企业已有基础设施，而不是“谁完全替代谁”。

## 🤔 解决什么问题 / 为什么需要

火山方舟提供豆包等模型能力，可与火山引擎的账号、权限、网络和计费体系配合。部分接口支持 OpenAI 兼容调用，也可以通过 LiteLLM 等网关与其他供应商组成主备路由；切换前需验证模型参数、响应及业务效果。

## 🧩 核心组件

| 组件 | 作用 | 学习重点 |
| ---- | ---- | -------- |
| Endpoint/模型服务 | 具体可调用模型入口。 | endpoint ID、模型版本、区域和限流。 |
| Ark API | 方舟推理 API。 | 鉴权、base_url、错误码和流式输出。 |
| OpenAI Compatible API | 兼容 OpenAI 客户端。 | 模型名映射、messages 格式、工具调用差异。 |
| Knowledge/Application | 平台应用与知识能力。 | 是否满足业务知识库、发布和权限要求。 |
| 监控计费 | 调用量、token、错误和账单。 | 按租户和应用拆分成本。 |

## ⚙️ 接入流程

```mermaid
flowchart LR
    A[开通火山方舟] --> B[创建 API Key]
    B --> C[选择模型/Endpoint]
    C --> D[OpenAI 兼容调用]
    D --> E[接入网关或后端]
    E --> F[监控限流与成本]
```

1. 开通火山方舟，确认账号权限、地域、计费和可用模型。
2. 创建 API Key 或服务凭证，生产环境通过密钥管理系统注入。
3. 选择模型或 endpoint，记录上下文窗口、价格、限流和支持能力。
4. 使用 OpenAI 兼容接口接入后端，或配置到 LiteLLM、Dify、LangChain/Spring AI。
5. 建立日志字段：endpoint、模型名、用户、租户、token、耗时、错误码。
6. 配置配额告警、限流策略和备用模型。

## 💻 Spring AI 接入片段

假设已引入 Spring AI 2.x 的 OpenAI 兼容 Starter。以下属性是配置示意，需要按方舟控制台的区域、模型和接口文档填写；先检查该版本客户端与供应商地址的拼接方式，避免重复 `/v1`；其他 Spring AI 版本的属性可能不同。

```properties
spring.ai.openai.base-url=${PROVIDER_BASE_URL}
spring.ai.openai.api-key=${ARK_API_KEY}
spring.ai.openai.chat.model=${PROVIDER_MODEL}
```

假设 `chatClient` 已由应用配置并注入，`text` 为待处理文本，下面只展示调用关系；片段未连接外部模型运行。

```java
String answer = chatClient.prompt()
        .user("请概括：" + text)
        .call().content();
```

实际模型名和 endpoint 以控制台配置为准，生产代码不要把测试 endpoint 写死。例如北京区域的 OpenAI 兼容 base URL 为 `https://ark.cn-beijing.volces.com/api/v3`；最终请求路径需按所用客户端版本联调验证。
方舟的聊天兼容接口与向量化接口不能一概而论：当前官方兼容说明指出向量化需按方舟支持的接口接入，具体以当前文档为准。

## ⚠️ 生产坑

- endpoint、模型名和区域混用，测试环境能调通，生产环境因权限或区域不一致失败。
- 接入兼容接口时，检查目标模型的工具调用、结构化输出和多模态能力。
- 检查流式 `usage` 等响应字段，以及上游返回的错误类型。
- 不要对参数错误等不可恢复的 4xx 响应盲目重试；计费规则需以供应商为准。
- 方舟作为备用模型时，输出风格和安全策略与主模型不同，需要业务回归。
- 账单只按总 Key 看，无法按应用/租户拆分成本，后续很难治理。

## 🎯 面试 / 选型

> [!question]- 火山方舟适合什么场景？
> 已在火山引擎生态、需要豆包模型、国内云合规、企业级权限和模型服务管理的场景。

> [!question]- 方舟和百炼怎么选？
> 看企业云生态、模型能力、价格、区域、内容安全和团队运维习惯；工程上最好通过网关保留多供应商切换能力。

> [!question]- 接入方舟上线前测什么？
> endpoint 权限、模型能力、流式响应、工具调用、内容安全、限流、成本和备用模型一致性。

## ✅ 精通检查清单

- 能按官方接口配置 Spring AI 并验证方舟模型调用。
- 能把方舟配置进 LiteLLM 或 Dify。
- 能解释 endpoint、模型名、区域和 Key 的关系。
- 能制定限流、重试、成本和降级策略。
