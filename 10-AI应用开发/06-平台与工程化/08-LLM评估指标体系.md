# LLM评估指标体系

> [!abstract] 一句话总结
> LLM 评估指标体系是上线前后的质量仪表盘，要同时看任务正确性、安全性、稳定性、成本、延迟和可观测数据，而不是只看单次回答是否顺眼。

## 📌 定位

评估指标是 AI 应用工程化的发布门禁。它连接 Ragas 的离线评估、Langfuse 的线上 trace、LiteLLM 的成本统计，以及业务侧的人工验收。

指标应该按应用类型拆：

- 通用问答：相关性、事实性、拒答、语气和安全。
- RAG：召回、引用、忠实度、答案正确性。
- Agent：工具选择、参数正确性、任务完成率、回滚能力。
- 结构化抽取：字段准确率、JSON 合法率、漏抽/错抽。

## 🤔 解决什么问题 / 为什么需要

- **发布决策**：模型、Prompt、知识库或工具变更前后有可比较数据。
- **线上告警**：延迟、失败率、token 成本、拒答率、负反馈率异常时能发现。
- **问题归因**：把“模型不行”拆成召回、生成、工具、权限、数据质量等具体原因。
- **面试表达**：能从业务目标讲到指标、样例集、阈值和持续改进。

## 🧩 指标分层

| 层级 | 指标 | 说明 |
| ---- | ---- | ---- |
| 业务效果 | 任务完成率、人工通过率、用户负反馈率 | 最终是否解决用户问题。 |
| 生成质量 | 正确性、相关性、忠实度、拒答准确率 | 回答是否对、是否基于证据。 |
| RAG 检索 | Recall@K、Precision@K、MRR、引用命中率 | 检索片段是否覆盖答案依据。 |
| Agent 工具 | 工具选择准确率、参数准确率、成功执行率 | 是否会用工具并传对参数。 |
| 工程稳定 | P95/P99 延迟、错误率、超时率、重试率 | 服务是否稳定。 |
| 成本安全 | token/次、成本/租户、敏感信息泄露、越权率 | 是否可控、合规。 |

## ⚙️ 落地流程

```mermaid
flowchart LR
    A[定义任务类型] --> B[建立样例集]
    B --> C[选择指标和阈值]
    C --> D[离线评估]
    D --> E[灰度上线]
    E --> F[线上监控]
    F --> G[坏例回流]
```

1. 按任务类型定义成功标准，例如“合同问答必须引用原文条款”。
2. 建样例集：正常题、边界题、越权题、无答案题、长文档题都要覆盖。
3. 给每类指标设阈值，例如 JSON 合法率 99%、关键字段准确率 95%、P95 延迟 5 秒内。
4. 用 Ragas/自定义脚本跑离线评估，用 Langfuse 记录样例和 score。
5. 灰度上线后看线上负反馈、成本、错误率和 trace 抽样。
6. 把线上坏例回流到评估集，形成回归测试。

## 💻 指标记录示例

```json
{
  "app": "contract-qa",
  "version": "2026-07-04",
  "model": "qwen-plus",
  "metrics": {
    "faithfulness": 0.91,
    "answer_relevancy": 0.88,
    "citation_hit_rate": 0.94,
    "p95_latency_ms": 4200,
    "avg_cost_cny": 0.018
  }
}
```

## ⚠️ 生产坑

- 只看自动评分，不抽样人工复核，容易被评估模型偏差带偏。
- 样例集长期不更新，模型对老题表现稳定，但真实业务已经变化。
- 只看均值，不看低分样例、P95/P99 和高风险用户群。
- 成本指标没有按租户、功能、模型拆分，费用异常时找不到来源。
- 安全指标没有纳入发布门禁，越权问答和敏感信息泄露只能事后补救。

## 🎯 面试 / 选型

> [!question] 高频问题
> - Q: LLM 应用怎么做质量评估？
>   - A: 先按任务类型定义成功标准，再建样例集，离线跑自动指标，人工复核关键样例，上线后用 trace、负反馈和成本指标持续监控。
> - Q: RAG 评估和普通问答评估有什么不同？
>   - A: RAG 要额外看检索片段是否召回答案依据、回答是否忠实于 context、引用是否正确。
> - Q: 模型升级如何判断能否上线？
>   - A: 用同一批样例比较正确性、安全、延迟和成本；关键指标不退化，高风险坏例通过人工复核后再灰度。

## ✅ 精通检查清单

- 能为一个 RAG 应用设计指标和阈值。
- 能解释业务指标、模型质量指标、工程指标之间的关系。
- 能把 Langfuse、Ragas、业务日志组合成评估闭环。
- 能说出模型/Prompt/知识库变更的发布门禁。
