# Coze扣子

> [!abstract] 一句话总结
> Coze/扣子是面向 Bot 和 Agent 发布的低代码平台，优势在插件、工作流、知识库和多渠道发布；学习重点是能把一个 Bot 从配置、调试、发布到 API/渠道集成跑通。

## 📌 定位

Coze 更偏“智能体产品化平台”，适合快速做客服、运营助手、内部问答、任务执行 Bot。和 Dify 相比，Coze 更强调 Bot、插件生态、工作流和渠道分发；和纯代码框架相比，可控性较弱，但交付速度更快。

典型边界：

- 适合：标准问答、工具调用、轻量流程、知识库问答、多渠道 Bot。
- 谨慎：强私有化、复杂事务、深度定制模型路由、严格审计和内网系统打通。

## 🤔 解决什么问题 / 为什么需要

- **Bot 快速上线**：Prompt、技能、知识库、插件和发布渠道在一个平台里完成。
- **工具生态复用**：常见搜索、数据库、HTTP、办公协作能力可以通过插件或工作流接入。
- **多人协作调试**：产品可以改人设和流程，研发负责 API、插件和权限边界。
- **渠道分发**：同一个 Bot 可以面向网页、飞书/企微等渠道或通过 API 暴露。

## 🧩 核心组件

| 组件 | 作用 | 学习重点 |
| ---- | ---- | -------- |
| Bot/Agent | 面向用户的智能体入口。 | 人设、指令、开场白、上下文和发布渠道。 |
| Workflow | 多步骤任务编排。 | 条件、变量、HTTP、LLM、插件节点的输入输出。 |
| Plugin | 外部能力封装。 | API schema、鉴权、参数校验和错误提示。 |
| Knowledge | 文档知识库。 | 文档解析、切片、召回测试和答案引用。 |
| Conversation API | 业务系统接入 Bot。 | 会话 ID、用户 ID、流式响应和权限隔离。 |

## ⚙️ 接入流程

```mermaid
flowchart LR
    A[创建 Bot] --> B[配置模型与指令]
    B --> C[绑定知识库]
    C --> D[创建插件/工作流]
    D --> E[调试多轮对话]
    E --> F[发布渠道或 API]
    F --> G[监控会话与成本]
```

1. 明确 Bot 的用户、输入范围、拒答边界和成功标准。
2. 配置模型、人设、系统指令、变量和上下文保留策略。
3. 上传知识库，用 20 到 50 个业务问题检查召回片段和答案来源。
4. 对外部系统优先做插件或 HTTP 节点，参数字段写清含义、类型和必填项。
5. 在调试台覆盖正常问题、越权问题、工具失败和无答案问题。
6. 发布到渠道或 API，后端保存 Bot ID、Token、conversation_id 和用户映射。

## 💻 接入示例

```text
业务后端 -> Coze Conversation API -> Bot
                         |
                         +-> Workflow / Plugin / Knowledge
                         |
                         +-> 流式文本、工具结果、错误码
```

工程上建议由后端代理 Coze API：前端只拿业务会话，不直接持有平台 Token；后端负责用户鉴权、敏感参数补全、失败重试和日志脱敏。

## ⚠️ 生产坑

- Bot 指令写成“万能助手”，会导致插件调用边界不清，用户稍微换说法就偏离任务。
- 插件 schema 描述太口语化，模型容易漏填必填参数或把单位、时间范围传错。
- 渠道发布后上下文长度、消息格式、文件能力可能和调试台不同，需要逐渠道验收。
- 知识库文档没有版本号，业务制度更新后无法判断答案引用的是新规还是旧规。
- 平台能力强依赖云服务，企业内网系统接入要提前评估网络、鉴权和数据出境要求。

## 🎯 面试 / 选型

> [!question] 高频问题
> - Q: Coze 和 Dify 怎么选？
>   - A: 要快速做 Bot、插件生态和渠道分发，优先 Coze；要自托管、RAG 与 Workflow 工程化控制，优先 Dify。
> - Q: Coze 插件为什么要重视 schema？
>   - A: 模型按 schema 选择工具和填参数，字段含义不清会直接造成工具误调、漏调或越权调用。
> - Q: Bot 上线前测什么？
>   - A: 正常任务、无答案拒答、敏感信息、插件失败、知识库更新、渠道差异和成本上限。

## ✅ 精通检查清单

- 能创建 Bot、绑定知识库、配置 Workflow/Plugin 并发布。
- 能说明 Coze 在插件生态和渠道分发上的优势。
- 能写出插件 schema 的关键字段和常见错误。
- 能把 Coze、Dify、RAGFlow 的适用场景讲清楚。
