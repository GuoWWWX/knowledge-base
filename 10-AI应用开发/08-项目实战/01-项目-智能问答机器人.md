# 智能问答机器人

> [!info] 项目简介
> 用 Spring Boot 3 + Spring AI 实现基础聊天机器人，掌握 ChatClient、Prompt 参数、流式输出和简单会话记录。

## 🎯 本节定位

本项目是后续项目的应用基础，建议先了解 [[../01-LLM基础与Prompt/07-Prompt工程基础|Prompt 基础]] 和 [[../02-框架-SpringAI与LangChain4j/SpringAI/02-ChatClient与ChatModel|Spring AI 模型调用]]。接口与工程骨架可在 RAG、客服和业务 Agent 项目中复用，下一项目会加入工具调用。

## 📌 项目背景

这是 AI 应用开发的最小闭环项目，用来打通模型配置、接口封装、流式输出、会话记录和基础日志。后续的 RAG、Agent 和客服项目都可以复用这个项目的接口和工程骨架。

## 🎯 项目目标

- [ ] 提供普通问答接口和流式问答接口
- [ ] 支持系统提示词、温度、模型等参数配置
- [ ] 保存最近多轮会话，按用户隔离上下文
- [ ] 输出一组可演示的接口调用样例

## 🛠️ 技术栈

| 类别 | 选型 |

| 语言/框架 | Spring Boot 3 + Spring AI |

## 🗣️ 一次多轮对话如何走？

用户 A 在会话 1 先说“我做 Java 开发”，再问“给我推荐一条 AI 学习路线”。服务端先根据登录身份确认该用户对会话 1 的访问权，再读取这段会话的历史，与本轮问题一起传给模型；回答后保存本轮消息。用户 A 的另一个会话、用户 B 的会话都不应自动共用这段历史。
先完成普通问答，再增加 SSE：客户端收到文本片段后逐步显示；中途断开、模型报错和正常结束要分别记录。模型输出不是固定值，验收重点是会话隔离和流式状态，而不是要求每次推荐完全相同。

## 💻 Spring AI 最小调用片段

假设 `chatClient` 已配置模型，`message` 来自已校验的请求；下例只演示同步调用，不包含会话存储和接口代码，未连接模型运行。

```java
String answer = chatClient.prompt()
        .user(message)
        .call().content();
```

## 🧠 难点与关键技术点

- 流式输出要处理断连、异常和结束状态。
- 会话记录要按用户隔离，避免为了演示简单而忽略串话风险。
- 参数配置需要可复现，演示时能说明模型、温度和系统提示词。

## ✅ 验收标准

- `/chat` 和 `/chat/stream` 都能用 curl 或 HTTP Client 跑通。
- 同一用户连续 3 轮追问能复用上下文，不同用户之间不会串话。
- README 写清模型配置、环境变量、启动命令和 5 条演示问题。
- 日志能看到请求 ID、用户 ID、模型名、耗时和流式结束状态。
