# 行业场景：AI 客服 / AI 搜索 / 办公助手 / 数据分析 Agent

> [!abstract] 一句话总结
> 企业级 AI 应用开发注重将 RAG 与 Agent 技术映射到具体业务场景，通过问题解决率、知识命中率、响应耗时与运营成本等可量化指标体现工程价值。

- **求职期场景映射**。前置：03 RAG 与 07 业务 Agent 两个核心项目；本文把项目能力翻译成 AI 客服、AI 搜索、办公助手、数据分析四个场景的简历表达。
- **延伸**：结合 [[99-本章总结与复习]] 完成整体复盘，再进入 [[../09-标杆产品拆解/_index]] 学习标杆产品拆解。

## 场景一：AI 客服

| 模块 | 技术点 |
| ---- | ------ |
| 意图识别 | 分类、路由、置信度 |
| 知识问答 | RAG、引用溯源、无答案拒答 |
| 工单动作 | Tool Calling、权限、审批 |
| 多轮上下文 | 会话状态、摘要记忆 |
| 质量评估 | 解决率、转人工率、幻觉率 |

简历表达：

> 设计 AI 客服多轮对话系统，支持意图识别、RAG 知识问答、工单工具调用和人工转接，通过 trace 和 badcase 数据集持续优化回答质量。

## 场景二：AI 搜索

| 模块 | 技术点 |
| ---- | ------ |
| Query Rewrite | Multi-Query、HyDE |
| 召回 | BM25 + Vector Hybrid |
| 排序 | Rerank、业务权重 |
| 答案生成 | 引用溯源、证据约束 |
| 权限 | metadata filter、租户隔离 |

简历表达：

> 构建企业 AI 搜索，融合关键词检索、向量检索和 Rerank，支持权限过滤和引用溯源，降低内部知识查找成本。

## 场景三：办公助手

| 模块 | 技术点 |
| ---- | ------ |
| 文档总结 | 长上下文、分层摘要 |
| 邮件/周报 | 模板化生成、风格控制 |
| 日程/待办 | Tool Calling、MCP |
| 审批辅助 | 信息抽取、风险提示 |
| 企业集成 | 权限、审计、SSO |

注意：办公助手经常涉及隐私和内部数据，必须把 [[../05-Agent-MCP-Skills/21-Agent权限治理与分级自治]] 放进设计里。

## 场景四：数据分析 Agent

| 模块 | 技术点 |
| ---- | ------ |
| 指标解释 | 业务术语库、RAG |
| SQL 生成 | schema linking、只读权限 |
| 图表生成 | 工具调用、代码执行沙箱 |
| 结果校验 | SQL explain、数值核对 |
| 交互追问 | 多轮状态和上下文压缩 |

关键安全与质量控制点：

- 数据库连接使用只读账号并配置可查询视图/表白名单；执行前通过 SQL AST 解析校验语法结构、表列级权限并强制注入租户过滤条件。
- 对大查询设置扫描行数上限、返回结果集大小限制（`LIMIT`）与执行超时时间，防止慢查询耗尽数据库资源或导致批量数据导出。
- 生成图表前校验聚合维度与指标字段含义。
- 输出分析结论时附带数据来源、时间范围与查询口径说明。

撰写项目经历时，应结合实际实现的模块与离线评估数据，客观呈现召回率、准确率、响应延迟及成本优化指标。

## 项目组合建议

面试前至少准备两个项目：

1. **企业知识库 RAG 系统**：证明你会检索、Rerank、引用、权限和评估。
2. **业务 Agent 系统**：证明你会工具调用、流程编排、审批、安全和可观测。

如果时间够，再补一个 **数据分析 Agent**，它能体现 Java 后端 + SQL + Agent 的复合能力。

## 面试讲法

> 我会先从业务闭环选场景，而不是先选框架。AI 客服关注解决率和转人工率，AI 搜索关注召回和引用可信度，办公助手关注权限和审计，数据分析 Agent 关注 SQL 安全和结果校验。不同场景对应不同的 RAG、Agent、工具和评估方案。
