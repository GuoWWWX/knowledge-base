# 项目实战：本章总结与复习

> [!abstract] 一句话总结
> 本章用聊天、RAG、工具调用和业务 Agent 项目训练完整交付能力：从场景与验收标准出发，经上下文和工具完成任务，再用权限、评估、可观测与审计证明系统可靠。

## 🧩 知识 / 能力概览

| 项目层次 | 代表内容 | 核心能力 |
| -------- | -------- | -------- |
| LLM 应用底座 | 智能问答、多轮客服 | 普通与流式接口、Prompt、会话隔离、Token 预算与记忆 |

## 📌 快速复习

- 先写业务目标、用户角色、输入输出和验收标准，再选模型与框架。
- RAG 的质量链路是解析、切分、召回、融合、重排、生成和引用；权限过滤必须在无权内容进入 Prompt 前完成。
- 多轮记忆要按用户与会话隔离，并受 Token 预算、摘要策略和敏感信息生命周期约束。
- 模型只提出工具名和参数；服务端负责鉴权、白名单、Schema 校验、风险分级、幂等和审计。
- ReAct 解决“思考、行动、观察”的执行循环，业务 Agent 还必须有状态机、超时重试、审批和失败补偿。
- 没有评估集、Trace、成本与延迟指标，就无法稳定定位 RAG 或 Agent 的 badcase。

## ❓ 自测问题

> [!question]- 基础问答项目怎样验证流式接口和会话隔离？
> 测试普通和流式请求的结束与异常，使用多个用户及多个会话检查上下文不串用，并核对请求 ID、耗时和错误记录。

> [!question]- RAG 答错时，如何区分检索问题和生成问题？
> 先对照原文检查解析与切分，再看正确片段是否召回、排序和拼入上下文，最后检查回答及引用是否受证据支持。

> [!question]- 为什么权限过滤不能只写在提示词里？
> 模型不负责业务授权，未授权资料一旦进入上下文就可能泄露；应由服务端确定用户权限并在检索时过滤。

> [!question]- Function Calling、MCP 与 ReAct 分别解决什么问题？
> Function Calling 让模型提出工具和参数；MCP 定义应用与能力服务之间的协议；ReAct 利用行动后的观察调整下一步。

> [!question]- L0 到 L4 的动作如何处理？
> 依业务策略区分只读、草稿、低风险自动执行、需审批和禁止；风险由服务端判断，审批后仍需复核权限和参数。

> [!question]- 怎样公平比较 CAG 与 RAG？
> 固定知识、问题集、模型和评分口径；分别记录长上下文、RAG 和实际缓存命中的延迟、成本与失败案例。

> [!question]- 如何说明项目的业务价值和验证结果？
> 先说明场景、用户及目标，再介绍已实现的核心流程，用实际评估样本、延迟或成本数据支持结论，并说明尚未完成的部分。
