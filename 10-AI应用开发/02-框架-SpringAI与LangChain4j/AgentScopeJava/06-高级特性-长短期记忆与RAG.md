# 🧠 长短期记忆与 RAG

> [!abstract] 一句话总结
> 会话记忆保留近期交互，长期记忆保存跨会话可能有用的信息，RAG 则根据问题检索外部资料；三者可以组合，但都需要权限与质量控制。

## 🧩 三种信息有什么区别？

| 信息 | 例子 | 关键问题 |
| :--- | :--- | :--- |
| 会话上下文 | 当前对话中用户刚提供的订单号 | 会话隔离、窗口大小和过期 |
| 长期记忆 | 用户允许保存的长期偏好 | 哪些信息值得保存、如何更新和删除 |
| 知识库 / RAG | 退货制度、商品手册 | 能否找到正确版本、是否有权限引用 |

## ⚙️ 压缩与检索如何配合？

对话越来越长时，可以保留近期消息，并将较早内容压缩为摘要；摘要可能遗漏否定条件和重要数字，不能当作完整原文。AgentScope Harness 提供记忆和压缩能力，触发条件、存储和加载方式要以具体版本配置为准。
外部知识需要时再查询，例如先检索退货规则，再检查它是否适用于当前订单。RAG 的入库、检索和评估过程见 [[../../03-知识库技术-RAG/01-RAG核心原理与全链路实战|RAG 基础]]。

## 🗣️ 用退货问题看三者的分工

用户说“订单 A123 昨天收到，能退吗？”当前会话提供订单号和收货时间；系统再从退货制度中查适用条款。如果用户此前明确允许保存“优先文字通知”的偏好，可从长期记忆取出作为回答方式的参考，但偏好不是退货规则的证据。
下次用户说收货日期有误时，应核对新信息并更新相应记录；不能因为旧记忆相似就把旧日期当作事实。制度回答也应附实际检索到的来源与版本。

## 📂 Harness 如何整理记忆？

AgentScope Java 的 Harness 提供可配置的记忆流程：从对话中提取可保留的事实并写入按日期组织的记录，再按配置整理为长期记忆；上下文太长时另有对话压缩，保留近期消息并将较早内容摘要化。
这几步解决的问题不同：长期记忆用于跨会话复用，压缩用于控制当前上下文，RAG 按问题检索外部资料。提取、合并和摘要可能产生错误，也可能产生额外模型调用和费用；启用前需检查数据保留和用户授权。

### 如何配置与验证？

下面的片段使用 `HarnessAgent`：假设已引入 `agentscope-harness`、配置好模型及对应扩展，`model` 是可用的模型实例；省略 imports，尚未连接模型运行。示例使用默认记忆流程，通过 `memory(...)` 调整提取频率。

```java
HarnessAgent agent = HarnessAgent.builder().name("order-assistant")
        .model(model).workspace(Path.of("./agent-workspace"))
        .memory(MemoryConfig.builder()
                .flushTrigger(MemoryConfig.FlushTrigger.throttled(Duration.ofMinutes(10)))
                .build())
        .build();
```

这里将每次调用结束后的记忆提取设置为最多每 10 分钟一次；首次符合条件时可以立即触发，压缩前的提取和后台整理不受这项节流限制。提取和整理可能调用模型并产生费用，应根据实际需要调整。
验证时，可以先让用户在一个会话中明确同意保存“优先文字通知”，再等待后台提取并检查工作区的 `memory/` 日记录。整理按策略在调用后触发，必要时等待整理间隔后再次调用，检查 `MEMORY.md`；实际存储位置取决于文件系统及用户隔离配置。随后使用同一用户的新会话询问通知偏好，并用另一用户检查隔离。提取和整理可能异步执行，也可能因模型判断或错误没有写入预期内容，不能只凭一次回答就断定记忆已生效。

## 🔐 工作区与访问边界

工作区有助于组织 Agent 可读写的文件，但目录约束和沙箱隔离并非同义词。限制文件访问时，除了规范化 `..` 路径，还需处理符号链接、绝对路径和并发修改等问题；应使用经过验证的隔离机制并进行实际测试，不要把一个 `normalize()` 判断当成完整沙箱。
长期记忆可能包含个人信息或错误事实，应支持查看、修正和删除，并按用户、租户隔离。

> [!question]- 对话已经压缩成摘要，原文就可以随便删除吗？
> 取决于业务、用户隐私和保留要求。摘要可能遗漏细节，也未必满足审计需求，应先设计保存和删除策略。
