# 多模型接入与配置

> [!abstract] 一句话总结
> LangChain4j 通过"一模型一模块 + builder 统一风格"支持 OpenAI、Ollama、Azure OpenAI、Google Gemini 等多家 Provider；多模型切换没有框架级路由，用"多 Builder + 按场景选 Bean/实例"的手动方式，思路与 Spring AI 一致。

## 📌 这是什么

### 模型模块与 builder（统一风格）

```xml
<!-- 每个 Provider 一个模块，按需引入 -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-open-ai</artifactId>
</dependency>
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-ollama</artifactId>
</dependency>
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-azure-open-ai</artifactId>
</dependency>
<!-- 更多：google-genai / anthropic / bedrock / dashscope(社区) 等 -->
```

```java
// 全部是 builder 风格，API 几乎对称：
ChatModel openai = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .temperature(0.7)
        .timeout(Duration.ofSeconds(60))        // 超时
        .logRequests(true)                       // 调试：打印请求
        .logResponses(true)                      // 调试：打印响应
        .build();

ChatModel ollama = OllamaChatModel.builder()
        .baseUrl("http://localhost:11434")       // 本地模型
        .modelName("qwen2.5:7b")
        .build();

ChatModel azure = AzureOpenAiChatModel.builder()
        .apiKey(System.getenv("AZURE_OPENAI_KEY"))
        .endpoint(System.getenv("AZURE_OPENAI_ENDPOINT"))
        .deploymentName("gpt-4o")
        .build();
```

### Embedding 模型（RAG 用，配置同理）

```java
EmbeddingModel embeddingModel = OpenAiEmbeddingModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("text-embedding-3-small")
        .build();
// 本地：OllamaEmbeddingModel.builder().baseUrl(...).modelName("nomic-embed-text").build()
```

## 🤔 解决什么问题 / 为什么需要

- **不同任务用不同模型**：复杂推理用强模型、简单问答用便宜模型（成本/延迟权衡）。
- **降级与容灾**：主模型挂了切备模型（手动 switch）。
- **本地与云端混用**：开发用 Ollama 本地模型，生产切云端——模型实现可替换，业务代码只依赖 `ChatModel` 接口。

## 🧩 多模型切换的三种姿势

```java
// 姿势一：按场景选实例（最简单）
ChatModel fastModel = OpenAiChatModel.builder()...modelName("gpt-4o-mini").build();
ChatModel strongModel = OpenAiChatModel.builder()...modelName("o4-mini").build();

// 姿势二：AiServices 多实例，各自绑定模型
Assistant cheapAssistant = AiServices.builder(Assistant.class).chatModel(fastModel).build();
Assistant proAssistant = AiServices.builder(Assistant.class).chatModel(strongModel).build();

// 姿势三：手动路由（降级/按配置切换）
ChatModel pick(String task) {
    return "complex".equals(task) ? strongModel : fastModel;
}
// 降级：try 主模型，抛错切备模型（配指数退避+熔断，见 07-分布式 章）
```

**与 Spring AI 的差异**：Spring AI 有"多 `ChatClient.Builder` Bean + `@Qualifier`"的框架级组织方式（05 篇）；LangChain4j 没有等价的自动路由，多模型管理靠**你自己组织实例/Bean**——简单场景反而更直接。

## 💻 代码实践 / 排查要点

```java
// Spring Boot 里组织多模型（配合 04 课 Starter 集成）
@Configuration
class ModelConfig {
    @Bean("fastModel")
    ChatModel fastModel() { return OpenAiChatModel.builder()...build(); }

    @Bean("strongModel")
    ChatModel strongModel() { return OpenAiChatModel.builder()...build(); }
}
// 使用时 @Qualifier("fastModel") 注入，或包一层 RouterService 做业务路由
```

- 请求超时/限流：builder 的 `timeout()`；重试自己写或依赖 Spring `@Retryable`。
- 调试模型输出：`logRequests(true)`/`logResponses(true)` 打开后看控制台（生产记得关）。
- 模型名/Key 别硬编码：走环境变量或配置中心（`System.getenv` / `@Value`）。

## ⚠️ 踩坑与注意事项

- **复用模型客户端实例**：`ChatModel` 实例内部维护了 HTTP 连接池与客户端配置，属于重量级对象，应在应用启动时构建并作为单例复用，避免在每次请求中重复创建。对于挂载了会话记忆的 `AiServices`，需配合 `@MemoryId` 隔离不同会话，并控制同一会话的并发调用。
- **统一模块版本**：引入多个 Provider 模块时，使用 `langchain4j-bom` 统一管理版本号，防止子模块版本不一致。
- 本地 Ollama 需要先拉模型（`ollama pull qwen2.5:7b`），`baseUrl` 写错会连不上——先 curl 验证。
- Azure OpenAI 的配置是 `deploymentName` 不是 `modelName`，别照抄 OpenAI 的配置。
- 降级路由要小心"雪崩"：主模型超时 → 全部切备模型 → 备模型也超时；必须配超时+熔断（见系统设计章）。
