# 多模型接入与配置

> [!abstract] 一句话总结
> LangChain4j 通过不同模型模块接入 OpenAI、Ollama、Azure OpenAI 等供应商。应用可以配置多个模型实例自行选择，也可以根据所用版本评估框架提供的路由能力。

## 🎯 本节定位

本篇在 [[01-LangChain4j核心概念]] 的基础上讲多模型实例的接入与选择，可对照 Spring AI 的 [[../SpringAI/05-多模型接入与切换|多模型接入与切换]]。模型选择和本地部署分别见 [[../../01-LLM基础与Prompt/05-主流模型选型对比|模型选型]]、[[../../06-平台与工程化/12-私有化部署-Ollama-vLLM-SGLang|私有化部署]]。

## 📌 这是什么

### 模型模块与 builder（统一风格）

```xml
<!-- 每个 Provider 一个模块，按需引入 -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-open-ai</artifactId>
</dependency>
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-ollama</artifactId>
</dependency>
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-azure-open-ai</artifactId>
</dependency>
<!-- 更多：google-genai / anthropic / bedrock / dashscope(社区) 等 -->
```

```java
// 全部是 builder 风格，API 几乎对称：
ChatModel openai = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .temperature(0.7)
        .timeout(Duration.ofSeconds(60))        // 超时
        .logRequests(true)                       // 调试：打印请求
        .logResponses(true)                      // 调试：打印响应
        .build();

ChatModel ollama = OllamaChatModel.builder()
        .baseUrl("http://localhost:11434")       // 本地模型
        .modelName("qwen2.5:7b")
        .build();

ChatModel azure = AzureOpenAiChatModel.builder()
        .apiKey(System.getenv("AZURE_OPENAI_KEY"))
        .endpoint(System.getenv("AZURE_OPENAI_ENDPOINT"))
        .deploymentName("gpt-4o")
        .build();
```

### Embedding 模型（RAG 用，配置同理）

```java
EmbeddingModel embeddingModel = OpenAiEmbeddingModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("text-embedding-3-small")
        .build();
// 本地：OllamaEmbeddingModel.builder().baseUrl(...).modelName("nomic-embed-text").build()
```

## 🤔 解决什么问题 / 为什么需要

- **不同任务用不同模型**：复杂推理用强模型、简单问答用便宜模型（成本/延迟权衡）。
- **降级与容灾**：主模型挂了切备模型（手动 switch）。
- **本地与云端混用**：开发用 Ollama 本地模型，生产切云端——模型实现可替换，业务代码只依赖 `ChatModel` 接口。

## 🧩 多模型如何选择

假设 `fastModel` 和 `strongModel` 已按前面的方式配置，选择逻辑可以由应用控制：

```java
ChatModel selected = complexTask ? strongModel : fastModel;
Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(selected).build();
```

Spring 项目可以把不同模型注册为 Bean，再通过 `@Qualifier` 注入。是否切换、何时降级以及备用模型的权限与成本由应用决定；不要把任何错误都当作可以重试的错误。
当前官方文档还介绍了实验性的 `RoutingChatModel` 和 `ChatModelRouter`，可以按请求选择模型。项目使用的版本是否提供该能力以及具体 API，需查看对应版本文档。

## 💻 配置和排查要点

- 比较不同模型的输出质量、耗时和成本，确认所用模型支持需要的结构化输出和工具调用。
- 配置超时与重试时同时考虑限流；写操作必须先处理幂等，避免重试导致重复执行。
- 请求与响应日志可能含敏感数据，调试时也应控制访问范围。
- 密钥放在环境变量或密钥管理系统中，不写入仓库。

## ⚠️ 踩坑与注意事项

- 优先复用配置好的 `ChatModel`，避免每次请求重复构建客户端。
- 使用会话记忆时，通过 `@MemoryId` 隔离会话，并控制同一会话的并发调用。
- 多个 Provider 模块使用 `langchain4j-bom` 统一管理版本。
- 本地 Ollama 需要先拉模型（`ollama pull qwen2.5:7b`），`baseUrl` 写错会连不上——先 curl 验证。
- Azure OpenAI 的配置是 `deploymentName` 不是 `modelName`，别照抄 OpenAI 的配置。
- 降级路由要小心"雪崩"：主模型超时 → 全部切备模型 → 备模型也超时；必须配超时+熔断（见系统设计章）。

## 🧪 最小验证

同一组问题分别调用两个已配置的模型，记录输出和耗时；再模拟主模型连接失败，检查路由是否按预设规则选择备用模型。这里的片段未连接模型运行。
