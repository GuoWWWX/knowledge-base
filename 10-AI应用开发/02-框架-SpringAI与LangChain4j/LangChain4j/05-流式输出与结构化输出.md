# 流式输出与结构化输出

> [!abstract] 一句话总结
> LangChain4j 的流式靠 `StreamingChatModel` + `TokenStream`（逐字回调），结构化输出可通过 AI Service 返回类型声明——而且 `AiServices` 方法返回类型直接写成业务对象，框架自动完成"模型 JSON → Java 对象"。

## 🎯 本节定位

- **LangChain4j 子区第 5 课**。前置：[[01-LangChain4j核心概念]]、[[02-AiServices声明式AI服务]]。
- 对照：Spring AI 的 [[../SpringAI/04-流式输出-SSE|流式输出-SSE]] 与结构化输出（`StructuredOutputConverter`）——本课讲 LangChain4j 侧的对应能力。
- 延伸：流式输出在前端 SSE 的接入方式见 08-项目实战。

## 📌 这是什么

### 流式：StreamingChatModel + TokenStream

```java
// ① 构建流式模型实例
StreamingChatModel streamingModel = OpenAiStreamingChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .build();

// ② StreamingChatModel 底层基于 StreamingChatResponseHandler 回调处理流式分块；
// ③ 在 AiServices 中可将接口方法返回类型声明为 TokenStream，简化流式回调编排
interface StreamingAssistant {
    TokenStream chat(@UserMessage String message);
}
StreamingAssistant assistant = AiServices.builder(StreamingAssistant.class)
        .streamingChatModel(streamingModel)   // 绑定流式模型
        .build();
assistant.chat("你好")
        .onPartialResponse(System.out::print)
        .onCompleteResponse(r -> System.out.println("\n[完成]"))
        .onError(Throwable::printStackTrace)
        .start();
```

**要点**：`TokenStream` 采用惰性启动机制——注册完回调后需调用 `start()` 才会发起请求；在 Web 场景中可在 `onPartialResponse` 回调内通过 `SseEmitter` 或响应式流将增量片段推送给前端。

### 结构化输出：方法返回类型映射

```java
// 定义目标业务数据结构（Record 或 POJO）
record User(String name, int age, String city) {}

// AiServices 方法返回类型直接声明为业务对象
interface UserExtractor {
    User extract(@UserMessage String text);   // 框架自动引导模型输出 JSON 并反序列化为 User
}
UserExtractor extractor = AiServices.builder(UserExtractor.class)
        .chatModel(model)
        .build();
User user = extractor.extract("张三，28 岁，上海");
```

**要点**：`AiServices` 的方法返回类型支持自定义 POJO、`Record` 或 `List<T>`，框架会自动生成格式约束指令（或在配置启用时使用底层模型的原生 JSON Schema 功能）并完成 JSON 反序列化。在生产环境中，建议结合支持原生 Structured Outputs 的模型配置，并在业务层对反序列化后的关键字段做合法性校验与解析异常兜底。

## 🤔 解决什么问题 / 为什么需要

- **流式**：大模型生成慢，用户等不了整段——逐字返回让体验"边说边出"；长文档、Agent 思考过程也靠它。
- **结构化**：业务系统要的是 `User`/`Order` 对象，不是自然语言——不结构化就得自己解析 JSON，还容易失败。

## 🧩 核心概念

| 概念 | 作用 | Spring AI 对照 |
| ---- | ---- | ---- |
| `StreamingChatModel` | 流式模型接口 | `ChatModel.stream()` |
| `TokenStream` | 流式回调编排接口 | `Flux<String>` / `Flux<ChatResponse>` |
| `.onPartialResponse/.onError/.start()` | 增量片段、异常与启动控制 | `Flux` 的 `doOnNext` / `onErrorResume` / `subscribe` |
| 结构化输出约束 | 提示词格式指令或模型原生 JSON Schema | `StructuredOutputConverter` / 原生格式选项 |
| AiServices 返回 POJO | 声明式结构化输出与反序列化 | `ChatClient.CallResponseSpec.entity(...)` |

## 💻 代码实践 / 排查要点

```java
// 流式 + SSE 伪代码（Web 层）
@GetMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter stream(String msg) {
    SseEmitter emitter = new SseEmitter();
    assistant.chat(msg)
            .onPartialResponse(chunk -> {
                try { emitter.send(chunk); } catch (IOException e) { emitter.completeWithError(e); }
            })
            .onCompleteResponse(r -> emitter.complete())
            .onError(emitter::completeWithError)
            .start();
    return emitter;
}
```

- 流式没反应 → 检查是否调了 `start()`（最常见坑）。
- 结构化输出失败 → 模型返回的不是合法 JSON：换更强模型、在 `@SystemMessage` 里明确"只输出 JSON 不要解释"、解析失败重试一次。
- 流式接口与同步接口不要混：`AiServices` 装配 `chatModel` 走同步、装配 `streamingChatModel` 走流式，方法返回类型要匹配。

## ⚠️ 踩坑与注意事项

- `TokenStream` 只能 `start()` 一次，不能复用。
- `onPartialResponse` 回调里别做重活（高频调用，注意线程安全）。
- 结构化输出对复杂嵌套对象/泛型支持有限，超复杂结构考虑先输出 JSON 再自己解析。
- 流式 + 工具调用（`@Tool`）时，工具结果可能在流中间返回——回调里要处理"工具片段"与"正文片段"的区分。
