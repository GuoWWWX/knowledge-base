# 流式输出与结构化输出

> [!abstract] 一句话总结
> LangChain4j 的流式靠 `StreamingChatLanguageModel` + `TokenStream`（逐字回调），结构化输出靠 `OutputParser`——而且 `AiServices` 方法返回类型直接写成业务对象，框架自动完成"模型 JSON → Java 对象"。

- **LangChain4j 子区第 5 课**。前置：[[01-LangChain4j核心概念]]、[[02-AiServices声明式AI服务]]。
- 对照：Spring AI 的 [[10-AI应用开发/02-框架-SpringAI与LangChain4j/SpringAI/04-流式输出-SSE|流式输出-SSE]] 与结构化输出（`StructuredOutputConverter`）——本课讲 LangChain4j 侧的对应能力。
- 延伸：流式输出在前端 SSE 的接入方式见 08-项目实战。

## 📌 这是什么

### 流式：StreamingChatLanguageModel + TokenStream

```java
// ① 模型换成流式接口
StreamingChatLanguageModel streamingModel = OpenAiStreamingChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .build();

// ② stream() 返回 TokenStream，注册回调后 start()
streamingModel.chat("讲个笑话")
        .onPartialResponse(partial -> System.out.print(partial))   // 每来一段就回调
        .onCompleteResponse(response -> System.out.println("\n[完成]"))
        .onError(error -> System.err.println("出错了: " + error))
        .start();   // 注意：必须调用 start() 才开始

// ③ 在 AiServices 里：接口方法返回 TokenStream，自动走流式
interface StreamingAssistant {
    TokenStream chat(@UserMessage String message);
}
StreamingAssistant assistant = AiServices.builder(StreamingAssistant.class)
        .streamingChatLanguageModel(streamingModel)   // 注意是 streaming 模型
        .build();
assistant.chat("你好").onPartialResponse(...).start();
```

**要点**：`TokenStream` 是"懒执行"的——注册完回调必须 `start()` 才真正发起请求；Web 场景把 `onPartialResponse` 的内容通过 SSE 推给前端（与 Spring AI 的 `Flux<String>` 思路一致）。

### 结构化输出：OutputParser / 方法返回类型

```java
// 方式一：OutputParser（显式）
String json = model.chat("返回一个用户 JSON：张三，28 岁");
User user = new JsonOutputParser<User>().parse(json);
// JsonOutputParser 泛型类型从 parse 调用处推断

// 方式二（推荐）：AiServices 方法返回类型直接写业务对象
interface UserExtractor {
    User extract(@UserMessage String text);   // 返回 User，框架自动解析 JSON
}
UserExtractor extractor = AiServices.builder(UserExtractor.class)
        .chatLanguageModel(model)
        .build();
User user = extractor.extract("张三，28 岁，上海");
// 框架内部：生成"只输出 JSON"的指令 → 模型返回 JSON → 反序列化成 User
```

**要点**：`AiServices` 的方法返回类型可以是任意 POJO（或 `List<T>`），框架自动做"结构化输出 + 反序列化"——这是比 Spring AI 的 `StructuredOutputConverter` 更"声明式"的写法；解析失败会抛异常，生产要兜底。

## 🤔 解决什么问题 / 为什么需要

- **流式**：大模型生成慢，用户等不了整段——逐字返回让体验"边说边出"；长文档、Agent 思考过程也靠它。
- **结构化**：业务系统要的是 `User`/`Order` 对象，不是自然语言——不结构化就得自己解析 JSON，还容易失败。

## 🧩 核心概念

| 概念 | 作用 | Spring AI 对照 |
| ---- | ---- | ---- |
| `StreamingChatLanguageModel` | 流式模型接口 | `ChatModel` + 流式调用 |
| `TokenStream` | 流式回调链 | `Flux<String>` |
| `.onPartialResponse/.onError/.start()` | 分段/错误/启动回调 | `Flux` 的 `map/onErrorResume/subscribe` |
| `OutputParser<T>` | 把文本解析成对象 | `StructuredOutputConverter` |
| AiServices 返回 POJO | 声明式结构化输出 | `StructuredOutput` API |

## 💻 代码实践 / 排查要点

```java
// 流式 + SSE 伪代码（Web 层）
@GetMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter stream(String msg) {
    SseEmitter emitter = new SseEmitter();
    assistant.chat(msg)
            .onPartialResponse(chunk -> {
                try { emitter.send(chunk); } catch (IOException e) { emitter.completeWithError(e); }
            })
            .onCompleteResponse(r -> emitter.complete())
            .onError(emitter::completeWithError)
            .start();
    return emitter;
}
```

- 流式没反应 → 检查是否调了 `start()`（最常见坑）。
- 结构化输出失败 → 模型返回的不是合法 JSON：换更强模型、在 `@SystemMessage` 里明确"只输出 JSON 不要解释"、解析失败重试一次。
- 流式接口与同步接口不要混：`AiServices` 装配 `chatLanguageModel` 走同步、装配 `streamingChatLanguageModel` 走流式，方法返回类型要匹配。

## ⚠️ 踩坑与注意事项

- `TokenStream` 只能 `start()` 一次，不能复用。
- `onPartialResponse` 回调里别做重活（高频调用，注意线程安全）。
- 结构化输出对复杂嵌套对象/泛型支持有限，超复杂结构考虑先输出 JSON 再自己解析。
- 流式 + 工具调用（`@Tool`）时，工具结果可能在流中间返回——回调里要处理"工具片段"与"正文片段"的区分。
