# 从 Codex 和 Claude Code 反推企业 Agent 设计

> [!abstract] 一句话总结
> Codex 和 Claude Code 的产品设计可以迁移到企业 Agent：先嵌入真实工作流，再设计上下文、工具、权限、验证和复用机制。

## 从真实业务工作流切入

构建企业级 AI 应用时，比起单纯提供一个通用对话窗口，更有效的方式是直接切入高频业务工作流：

- 先梳理高频业务流程。
- 将 Agent 嵌入关键作业节点。
- 装配业务上下文与受控工具。
- 通过权限分级与结果验证管控风险。

## 映射到企业场景

| 编程 Agent 设计 | 企业 Agent 对应设计 |
| --------------- | ------------------- |
| 代码库 | 企业业务系统 / 知识库 / 数据库 |
| AGENTS.md / CLAUDE.md | 业务规则、岗位 SOP、权限说明 |
| 文件编辑 | 创建工单、修改草稿、生成报表 |
| shell / test | 业务校验、规则引擎、审批流 |
| Git diff | 变更预览、操作审计、回滚记录 |
| sandbox / permissions | 数据权限、工具白名单、风险等级 |
| worktree | 草稿环境、沙盒环境、灰度租户 |
| subagents | 财务、法务、客服、数据分析专家 Agent |
| skills | 可复用业务流程包 |
| MCP | 企业系统标准接入层 |

## 企业 Agent 通用架构

```mermaid
flowchart TD
    A["业务入口 (客服 / 办公 / 数据 / 研发)"] --> B["任务线程"]
    B --> C["业务上下文装配"]
    C --> D["规则 / SOP / 权限 / 历史记录"]
    D --> E["Agent 决策"]
    E --> F["工具网关"]
    F --> G{"风险等级"}
    G -->|只读| H["直接查询"]
    G -->|低风险| I["自动执行"]
    G -->|高风险| J["人工审批"]
    G -->|禁止| K["拒绝或转工单"]
    H --> L["结果验证"]
    I --> L
    J -->|批准并重新校验| I
    J -->|拒绝| K
    K --> L
    L --> M["审计 / Trace / 反馈"]
```

## 设计步骤

### 1. 定义工作流

先问：

- 用户每天重复做什么？
- 哪些步骤最耗时？
- 哪些步骤需要查资料？
- 哪些步骤可以自动化？
- 哪些步骤必须人工审批？

### 2. 定义上下文

把上下文分成四类：

| 类型 | 例子 |
| ---- | ---- |
| 稳定规则 | SOP、政策、风控规则 |
| 实时数据 | 订单、库存、客户信息 |
| 历史记录 | 会话、工单、操作日志 |
| 任务输入 | 用户本次问题、附件、目标 |

### 3. 定义工具

工具不要一次性全部暴露给模型。要按场景、用户、风险过滤。

示例：

- 客服 Agent：查订单、查物流、创建工单、申请退款。
- 数据 Agent：查指标、生成 SQL、画图、解释波动。
- 办公 Agent：查制度、写邮件草稿、生成周报、创建待办。

### 4. 定义权限和风险等级

借鉴 [[../05-Agent-MCP-Skills/21-Agent权限治理与分级自治]]：

- L0：只读。
- L1：生成草稿。
- L2：低风险自动执行。
- L3：高风险需审批。
- L4：禁止自治。

### 5. 定义验证方式

不同任务要有不同验证：

| 任务 | 验证 |
| ---- | ---- |
| RAG 问答 | 引用证据、无答案拒答 |
| SQL 分析 | 只读、limit、结果核验 |
| 工单操作 | 参数校验、幂等、审批 |
| 文档生成 | 格式校验、敏感信息扫描 |
| 代码修改 | 测试、lint、diff |

## 最小可行企业 Agent

如果要做一个可面试的项目，可以按这个最小闭环：

1. 一个 Web Chat 入口。
2. 一个任务线程表。
3. 一个业务规则文档，相当于企业版 `AGENTS.md`。
4. 两个只读工具：查知识库、查业务数据。
5. 一个低风险写工具：创建工单或生成草稿。
6. 一个高风险操作：必须人工审批。
7. 一套 trace 和 eval badcase。

## 讲给面试官的版本

> 设计企业 Agent 时可借鉴 Codex 和 Claude Code 的工程架构：将 Agent 嵌入核心业务流程，自动加载组织级规则，按需检索业务上下文，通过受控工具网关执行操作，配合权限分级与人工审批管控风险，最后通过业务校验、变更预览与审计轨迹保障交付质量。在企业场景中，代码库对应业务系统与知识库，AGENTS.md/CLAUDE.md 对应岗位 SOP，shell/test 对应业务规则校验与审批流。
