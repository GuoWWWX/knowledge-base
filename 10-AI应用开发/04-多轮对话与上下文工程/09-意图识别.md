# 意图识别

> [!abstract] 一句话总结
> 意图识别把用户当前输入分类成问答、继续上文、修改约束、执行工具、闲聊、结束会话等动作，用来决定读取哪些记忆、走哪个状态和调用哪些服务。

## 🎯 本节定位

本篇介绍如何判断用户当前想做什么，并结合 [[05-结构化记忆]] 中的槽位与 [[06-分层记忆]] 选择所需上下文。是否切换任务见 [[10-话题切换检测]]，路由后的流程控制见 [[11-会话状态机]]。

## 📌 这是什么

多轮对话里的意图识别不是单句分类这么简单，它要结合最近窗口和会话状态判断“用户现在想让系统做什么”。例如“换成 Redis 方案”只有结合上文才知道是在修改存储选型。
- 输入：当前用户消息、最近窗口、会话状态、已填槽位。
- 输出：`intent`、`confidence`、`slots`、`requiresTool`、`memoryPolicy`。
- 用途：路由 Prompt、选择工具、更新状态机、决定是否检索长期记忆。

## 🤔 解决什么问题 / 为什么需要

- 区分查订单、改配置和继续解释，再决定是否调用工具。
- 结合上文理解“继续”“换一个”“按刚才的来”等指令。
- 缺少必要字段时先追问，避免直接猜测。
- 按意图决定读取哪些记忆，例如闲聊不一定需要向量检索。

## 🧩 核心数据结构

```json
{
  "intent": "modify_constraint",
  "confidence": 0.86,
  "slots": {
    "storage": "Redis",
    "scope": "short_term_memory"
  },
  "needsClarification": false,
  "requiresTool": false,
  "memoryPolicy": {
    "readWindow": true,
    "readProfile": true,
    "searchVectorStore": false,
    "updateStructuredMemory": false
  }
}
```

上例中的 Redis 是当前任务的选型，不代表用户已经更新长期偏好。其他常见 intent 包括 `new_task`、`continue_task`、`ask_explanation`、`tool_action`、`smalltalk`、`end_conversation` 和 `forget_memory`。

## ⚙️ 工作原理 / 流程

```mermaid
flowchart LR
    A[用户输入] --> B[加载最近窗口和状态]
    B --> C[意图分类]
    C --> D[置信度判断]
    D --> E{需要澄清?}
    E -->|是| F[追问缺失信息]
    E -->|否| G[路由到回答/工具/状态机]
```

1. 先用规则捕捉强信号，例如“忘掉”“重新开始”“取消”。
2. 再用模型做结构化分类，输出固定 JSON。
3. 槽位缺失或互相冲突时追问用户；模型给出的置信度未必经过校准，阈值要用标注数据验证，不能只凭数字作高风险决策。
4. 将识别结果写入 trace，后续状态机和记忆层都引用它。
5. 对高风险工具调用做二次确认。

## 💻 Spring AI / Redis 落地点

下面是流程示意片段；相关类型和方法由应用自行实现，省略配置与错误处理。

```java
IntentResult result = classify(userText, recentHistory);
if (result.needsClarification()) {
    return askUserForClarification();
}
```

识别结果可作为 `ChatClient` 前置路由：`tool_action` 进入工具编排，`forget_memory` 进入删除流程，`continue_task` 加载摘要和窗口。

## 🔍 VectorStore 关系

不是每个问题都要检索向量记忆：
- `continue_task`：优先滑动窗口和摘要。
- `ask_explanation`：可检索知识库，不一定检索用户长期记忆。
- `modify_constraint`：读取结构化记忆并准备覆盖字段。
- `forget_memory`：查找相关 memory ids，执行删除或失效。
- `new_task`：根据问题决定是否检索长期偏好。

## ⚠️ 踩坑与注意事项

- 只看当前句会误判短指令，例如“换成第二个”必须结合窗口。
- 模型分类可能不稳定，关键意图要有规则兜底。
- 置信度不是事实，低置信度要追问，不要强行路由。
- 意图识别 Prompt 里不要暴露可被用户操控的内部工具权限。
- 分类结果必须写 trace，否则无法解释为什么调用了某个工具。

## 🎯 面试问题

> [!question]- 意图识别在多轮对话里起什么作用？
> 它把用户输入路由到回答、追问、工具调用、记忆更新或状态流转，避免所有请求都走同一个 Prompt。

> [!question]- 如何处理“继续”“换一个”这类省略表达？
> 加载最近窗口和会话状态，让分类器结合上文判断；必要时追问用户确认。

> [!question]- 规则和模型分类怎么配合？
> 强规则处理取消、删除记忆等高确定意图，模型处理语义复杂意图，低置信度进入澄清。

## ✅ 精通检查清单

- 能定义业务意图枚举和输出 JSON。
- 能说明意图识别如何影响记忆读取和工具调用。
- 能处理低置信度和槽位缺失。
- 能把识别结果写入 Redis 和 trace。
- 能为关键意图设计规则兜底。
