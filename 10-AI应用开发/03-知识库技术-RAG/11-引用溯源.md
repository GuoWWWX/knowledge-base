# 引用溯源

> [!abstract] 一句话总结
> 引用溯源让 RAG 的答案能指出“依据来自哪里”，是企业知识库可信度的核心。

## 🎯 本节定位

- **本章第 11 课，可信度闭环**。前置 [[02-文档解析]]（解析期必须保存来源 metadata）、[[10-父子块策略]]（命中后回表取父块再引用）；本篇讲引用编号与溯源设计。
- **延伸阅读（本课不展开）**：引用正确性如何量化评估见 [[12-RAG评估-Ragas]]。

## 📌 这是什么

溯源不是在答案末尾随便贴链接，而是从解析阶段开始保留 source、page、section、chunk_id，并在生成时要求模型只引用实际进入上下文的资料。

## 🧩 必备元数据

| 字段 | 作用 |
| ---- | ---- |
| source | 原始文件路径或 URL |
| document_id | 文档唯一标识 |
| chunk_id | chunk 唯一标识 |
| page | 页码 |
| section | 标题路径 |
| offset | 原文位置，可选 |

## ⚙️ 生成格式

```text
答案正文……[1]

引用：
[1] 员工差旅制度.pdf，第 3 页，2.1 住宿标准
```

## 🎯 工程要点

- 上下文中给每个 chunk 加引用编号。
- Prompt 中要求“没有引用依据不要回答事实断言”。
- UI 上支持点击引用跳到原文页码或片段。
- 对同一来源多个 chunk 做合并展示，避免引用列表过长。

## ⚠️ 踩坑与注意事项

- [ ] 不要让模型自由编造引用编号。
- [ ] 不要把未进入上下文的文档列为来源。
- [ ] 文档更新后 chunk_id 和页码可能变化，要有版本号。
- [ ] 引用只能证明“依据来源”，不能自动证明答案正确。

## 🎯 面试问题

> [!question] 高频问题
> - **Q: RAG 如何降低幻觉？**
>   - A: 通过检索提供事实上下文、Prompt 约束只基于上下文回答、答案附引用，并对无依据问题拒答。
> - **Q: 溯源需要从哪个阶段开始设计？**
>   - A: 从文档解析和入库阶段开始，必须保留稳定 metadata。
