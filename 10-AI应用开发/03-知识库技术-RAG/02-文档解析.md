# 文档解析

> [!abstract] 一句话总结
> 文档解析是把 PDF、Word、网页、图片、表格等原始资料转成可切分、可检索、可溯源的结构化文本。

## 📌 这是什么

RAG 的上限经常不是模型，而是文档解析。解析阶段要尽量保留标题层级、页码、段落、表格、图片说明和来源路径。

如果解析结果错序、丢表格、丢页码，后面的切分、Embedding、召回和引用都会被污染。

## 🧩 常见文档类型

| 类型 | 解析重点 | 风险 |
| ---- | ---- | ---- |
| PDF | 页码、段落顺序、表格、页眉页脚 | 双栏错序、扫描件无文本 |
| Word | 标题层级、列表、表格 | 样式不规范 |
| HTML | 正文抽取、链接、代码块 | 导航和广告污染 |
| Excel | sheet、表头、单元格关系 | 行列语义丢失 |
| 图片/扫描件 | OCR、版面识别 | 错字、漏字 |

## ⚙️ 解析产物

```yaml
content: 正文文本
metadata:
  source: 原始文件路径或 URL
  title: 文档标题
  page: 页码
  section: 标题路径
  element_type: paragraph / table / image
```

## 💡 工程建议

- 普通文本优先保留 Markdown，因为标题、列表、代码块天然适合后续切分。
- 表格不要粗暴转成一长串文本，优先转 Markdown 表格或“表头 + 行内容”的描述。
- 页眉页脚、目录、版权声明要做去噪，否则会被反复召回。
- 扫描件先 OCR，再抽样人工检查识别质量。

## ⚠️ 踩坑与注意事项

- [ ] 解析错序会让 Embedding 学到错误上下文。
- [ ] 丢页码会导致后续无法引用溯源。
- [ ] 表格跨页时要合并表头。
- [ ] 文件名、章节标题也是强信号，不要丢。

## 🎯 面试问题

> [!question] 高频问题
> - **Q: 为什么 RAG 要关注文档解析？**
>   - A: 检索只能在解析后的文本上工作，解析丢失结构或顺序，后面切分、Embedding、召回都会受影响。
> - **Q: PDF 解析最常见问题是什么？**
>   - A: 双栏错序、表格乱序、扫描件 OCR 错误、页眉页脚污染。
