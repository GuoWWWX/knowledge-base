# Git 撤销与误操作恢复

## 1. 先定位改动所在位置

| 现状 | 命令 |
| --- | --- |
| 文件修改还没暂存 | `git restore <file>` |
| 文件已暂存，想取消暂存 | `git restore --staged <file>` |
| 提交还没推送 | `git reset` 或 `git commit --amend` |
| 提交已经共享 | `git revert` |
| 分支或提交被误删 | `git reflog` |

第一步永远是：

```bash
git status
git diff
git diff --cached
```

## 2. Restore：撤销工作区或暂存区

```bash
# 丢弃工作区修改，保留暂存区
git restore src/app.ts

# 取消暂存，保留文件修改
git restore --staged src/app.ts
```

没有确认文件内容时不要使用 `git restore`，它会丢弃对应层面的修改。

## 3. Reset：只用于未共享历史

```bash
git reset --soft HEAD~1
git reset --mixed HEAD~1
git reset --hard HEAD~1
```

| 模式 | commit 指针 | 暂存区 | 工作区 |
| --- | --- | --- | --- |
| `--soft` | 回退 | 保留 | 保留 |
| `--mixed` | 回退 | 清空 | 保留 |
| `--hard` | 回退 | 清空 | 丢弃 |

`--hard` 只适用于明确不需要相关本地修改的场景。公共分支即使只差一个提交，也不要 reset 后强推。

## 4. Amend：修正最后一个本地提交

```bash
git add <missing-file>
git commit --amend --no-edit
```

适合漏提交文件或修改最后一次提交说明。已经被别人拉取的提交不要 amend 后强推。

## 5. Revert：公共历史的撤销方式

```bash
git revert <commit>
```

它不会删除旧提交，而是新增一个反向提交，因此可以正常推送到公共分支。多个提交、merge commit 和已经部分被后续代码覆盖的场景，都要先检查 diff 再执行。

冲突处理：

```bash
git status
# 解决冲突
git add <resolved-files>
git revert --continue

# 放弃本次 revert
git revert --abort
```

## 6. Reflog：找回误删引用

```bash
git reflog --date=local
```

找到误 reset 或误删分支前的 commit 后，先建立恢复分支：

```bash
git switch -c recovery/after-reset <commit-id>
git log --oneline --decorate -10
```

确认无误后，再选择 merge、cherry-pick 或恢复原分支。reflog 主要是本地记录，不能代替远程备份。

## 7. 常见误操作处理

| 问题 | 处理思路 |
| --- | --- |
| 误删未提交代码 | 编辑器历史、IDE Local History、文件系统备份；Git 通常无法恢复未提交内容 |
| 误删本地分支 | `git reflog` 找到分支末端，再 `git switch -c` |
| reset 后找不到提交 | `git reflog` 找到旧 HEAD |
| rebase 后想回去 | reflog 找到 rebase 前的 HEAD，先建恢复分支 |
| 错误强推远程 | 立即停止继续推送，确认正确历史后从恢复分支修复 |
